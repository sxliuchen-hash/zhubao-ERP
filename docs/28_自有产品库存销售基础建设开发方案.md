# 自有产品库存销售基础建设开发方案（远期规划）

**文档版本**：V1.1

**更新日期**：2026-10-11

**状态**：远期功能规划储备，暂无实施排期，暂不启动开发

**适用范围**：在现有客户来料加工系统中扩展公司自有产品库存与销售，支持自产和采购两种来源。

## 1. 建设结论与范围

**业务方已明确：自有产品库存与销售属于远期规划功能，暂时不着急实现。本文只保留调研结论和未来设计参考，不纳入当前迭代、近期开发任务或现阶段交付承诺。** 后续由业务方明确安排启动时，再结合实际需求和届时的代码状态重新评审范围、优先级与排期。

未来启动该功能后，建议优先建设 **统一商品主数据、货权清晰的库存底座、可靠的业务过账**，并从首批自有产品业务数据开始保留来源和成本记录。采购、自产与销售通过各自业务单据接入公共库存能力。现有系统可靠性问题按当前维护范围独立评估和安排。

已由业务方确认：**自产和采购都需要，比例暂未确定。** 同一 SKU 应允许两种来源，不能以采购或自产划分两套商品编码与库存系统。

本文中的对象名、字段和接口职责均为建议方案，不代表已经建表、开放接口或确认计价规则。当前实现以 [14 开发进度](./14_开发进度跟踪.md)、[16 API 契约](./16_字段字典与API契约.md) 和实际代码为准。

| 未来拟建设范围 | 未来首轮暂不展开 |
|---|---|
| 商品、单位、仓库、客户和供应商的最小档案 | 完整 CRM、促销、会员、门店 POS、电商渠道 |
| 双货权库存、批次来源、可选单件追踪、成本记录 | 复杂 MRP、自动补货、完整成本会计与总账 |
| 统一过账、幂等、预留、释放、冲正和最小盘点 | 通用工作流引擎、微服务拆分、分布式消息平台 |
| 采购验收入库、自产完工入库和最小销售闭环 | 多公司、多租户及复杂跨组织交易 |

## 2. 当前基础与必须解决的缺口

本节依据 2026-10-11 工作区源码和现行文档调研。已存在测试代码不代表本次已执行相应测试。

| 领域 | 已有基础 | 扩展前必须处理 |
|---|---|---|
| 库存内核 | `OwnerType` 已有 `CUSTOMER / COMPANY`；数量、重量、台账、余额及单笔原子扣减 | `StockDimension` 强制母单；余额维度含客户、母单和工单，自有备货不能直接独立建账 |
| 业务流转 | 收货、报工、质检、发货、退货已有命令 | `BusinessOperationService` 当前流转固定客户货权；不能只给页面增加“自有”选项 |
| 事务与重试 | 库存仓储内事务、收付款局部幂等已有实现 | 库存和业务单据分别提交；库存重试生成新台账号，尚缺业务动作级幂等 |

## 3. 核心设计约束

### 3.1 商品身份、货权、来源和销售分配分别管理

- **商品身份**回答“是什么”：款式、SKU、规格与单位。
- **货权**回答“属于谁”：公司自有或具体客户所有，与放在哪个仓库无关。
- **库存位置与质量状态**回答“在哪里、是否可用”：仓库、可选库位、待检、合格、冻结、返工或报废。
- **来源**回答“从哪里来”：采购验收、自产完工、客户来料或经审批的期初入账，并关联来源单据行。
- **销售分配**回答“为谁留了多少”：销售订单行及其预留记录，不改变商品或批次的来源。

公司自有库存允许没有销售客户、来料母单和加工工单。客户来料继续保留客户、母单和工单隔离，不能因自有库存扩展而合并历史客户货。

不得用虚拟客户、虚拟母单绕过现有必填规则；不得依靠分仓名称实现货权隔离；不得通过给普通仓管授予 `ALL` 范围解决自有库存读取。

### 3.2 保留公共库存，新增业务边界

继续采用模块化单体和 `domain / app / infra / web` 分层。建议职责如下，具体包名在对应增量设计时确定：

| 领域 | 职责 | 与现有模块的关系 |
|---|---|---|
| 商品与基础档案 | 商品、规格、单位、仓库、往来单位 | 新建正式档案，保留旧物料编码映射 |
| 库存 | 余额、台账、预留、过账、冲正、盘点调整 | 扩展现有 `inventory`，保持唯一库存账 |
| 采购 | 采购订单、验收、退货及应付来源 | 不直接写余额，不复用耗材表充当商品采购单 |
| 自有生产 | 原料领用、退料、工序、完工及成本归集 | 复用适用的报工、质检、证据能力，隔离客户加工规则 |
| 销售 | 订单、价格快照、履约、退货及应收来源 | 新建销售聚合，复用物流、标签、附件与收付款能力 |
| 财务 | 应收应付、核销、成本与经营查询 | 区分加工和商品销售来源，避免重复确认成本 |

不把采购、自主生产和销售全部塞入现有业务服务的条件分支。原有客户来料入口和接口保持兼容，通过适配层调用公共库存能力。

## 4. 重点数据模型

以下为最小对象及约束，具体 SQL、索引、接口路径和错误码须在实施前补充到对应领域设计及 [16 API 契约](./16_字段字典与API契约.md)。

| 对象 | 最少信息 | 关键约束 |
|---|---|---|
| 商品与 SKU | 稳定 ID、编码、名称、分类、规格属性、数量单位、重量单位、追踪方式、启停状态 | 原料、半成品、成品明确用途；采购和自产能力可以同时开启；不能以名称作为唯一身份 |
| 仓库与库位 | 编码、名称、启停状态、适用货权、可选库位 | 仓库表示位置，质量与业务状态独立；停用后禁止新业务，保留历史查询 |
| 客户与供应商 | 稳定 ID、编码、名称、角色、联系方式、启停状态 | 同一往来单位可有多种角色；供应商不再仅用自由文本关联 |
| 库存批次 | SKU、批次号、货权、来源类型、来源单据行、入库日期、追踪关系 | 同款采购与自产批次可汇总查询，但来源和成本分别保留 |
| 可选单件 | 唯一标识、所属 SKU/批次、实测重量、证书号、照片或附件 | 支持按需启用；同一单件不能重复入库或重复出库；单件数与批次数量不重复累计 |
| 库存余额 | 货权主体、SKU、仓库/库位、质量状态、批次/单件、数量和重量 | 公司库存不以销售客户分桶；客户加工保留必要的母单/工单隔离上下文 |
| 库存预留 | 销售单行、库存维度、数量/重量、状态、释放与消耗记录 | 预留不等于质量冻结；取消释放、部分发货部分消耗；禁止超额预留 |
| 库存过账 | 过账号、业务唯一键、来源单据行、动作、明细、操作人、业务及记录时间、冲正关联 | 同一动作只生效一次；一张业务单可以包含多条入出库存明细 |
| 成本记录 | 成本对象、来源流水、成本类别、金额、币种、计价单位、暂估/确认状态、调整关联 | 成本价与售价分开；计价规则和分摊规则保留版本或快照 |
| 销售订单及明细 | 客户、SKU、数量/重量、计价方式、单价、优惠、适用税额口径、交期和状态 | 商品售价独立于加工费协议；一单多行、分批履约；金额和单位保留快照 |

库存数量与重量沿用当前最多三位小数的精度约束。数量单位、重量单位和计价单位必须明确；转换比例不能由页面猜测。按件销售时不能用标准单重代替实际称重扣减，单件实测重量不能作为 SKU 规格随意拆码。

### 4.1 余额与可售量

合格在库、待检、质量冻结、返工、报废分别查询。预留只占用允许销售的合格在库库存。

`可售量 = 合格在库量 - 有效销售预留量 - 其他明确占用量`

质量冻结库存若已排除在合格在库量之外，不得再次扣减。数量和重量按实际启用的管理口径分别校验；双口径商品必须同时足额。已发货事实保留在台账和履约记录中，不计入当前可售库存。

## 5. 可靠过账与兼容要求

### 5.1 事务与幂等

1. 一次业务动作中的单据状态、全部库存明细、余额及相关成本记录应在明确的事务边界中提交；任一步失败不得留下半笔结果。
2. JDBC 仓储必须参与同一事务连接或事务管理机制，不能只在外层添加 `@Transactional` 而继续各自创建连接并提交。内存仓储提供等价的成功、回滚和重试行为。
3. 同时支持请求幂等键与业务过账唯一键。业务键至少区分来源类型、单据、单据行、动作和必要的操作版本；分批入库、分批发货用独立履约记录区分，不能被误判为重复。
4. 相同键、相同内容返回原结果；相同键、不同内容拒绝。唯一性与并发控制由数据库约束及条件更新保证，不只依赖单进程锁。
5. 取消预留、冲正和退货也须幂等。已过账单据通过冲正或更正单处理，记录原单关联及原因，禁止直接改余额或删除原台账。
6. 文件上传等外部副作用不假装与数据库同事务：附件先暂存或在提交后关联，失败显示可重试状态。首轮无需引入消息中间件。

### 5.2 历史数据与部署

- 先建立旧 `materialCode` 与新商品身份的映射，再迁移库存维度；保留原客户、母单、工单及来源台账，不凭空补造采购价或成本。
- 历史客户库存迁移前后按原隔离维度核对数量、重量和台账；自有库存采用新规则，不能简单全局取消母单校验。
- 对无法确认的历史来源或成本标记“待确认”，期初自有库存通过审批和期初单入账。
- 迁移保持 append-only，按实施时最新版本递增 `V{n}__m3_xxx.sql`，不在本文预占版本号，不修改已发布脚本。
- V36 是前置升级阻断，需要单独确定兼容执行与失败恢复方案；仅追加更高版本 SQL 无法修复尚未执行到该版本的安装路径。
- 必须分别验证空库安装、旧库升级、部分迁移失败后的恢复及备份还原。结构门禁、H2 测试和内存测试不能替代真实 MySQL 验证。
- 持久化保持内存默认、JDBC 可切；新增可选依赖保持重载构造器兼容与单一全参注入。

## 6. 采购、自产和销售的最小业务链路

### 6.1 采购来源

采购订单 → 到货验收 → 待检或合格入库 → 记录批次及采购成本 → 按结算规则形成应付。

支持部分验收、拒收和采购退货；收货事实、应付确认和付款分别记录。采购退货关联原收货批次及成本，不使用商品当前售价冲回。

### 6.2 自产来源

自有生产单 → 领料/退料 → 工序报工与质检 → 完工入库 → 归集在制与成品成本。

必须明确投入原料 SKU 和产出成品 SKU，以及工艺路线与版本。领料、退料、报工、质检和完工是分次发生的业务动作，每个动作的全部明细原子提交，不能把跨天生产流程包在一个事务中。领退料记录在制转移或材料消耗；完工根据已有领退料和报工事实归集成本并登记成品、副产物或报废，禁止再次扣减已经消耗的原料。

多原料到成品的关系由生产单及各动作过账串联；不能放开普通库存转移接口，允许随意跨物料、跨货权转移。

数量不要求不同 SKU 之间简单相等；重量守恒、辅料加入、下脚料、损耗及单位换算按已确认的工艺口径校验并留证据。首轮可采用人工确认用料清单，不先建设完整 MRP。

### 6.3 销售与退货

销售订单确认 → 库存预留 → 拣货/称重 → 分批发货过账 → 按确认规则形成销售应收 → 收款核销。

退货申请 → 关联原发货明细 → 收货待检 → 合格重新可售、返工、冻结或报废 → 按规则处理应收红字、退款与成本冲回。

实物退回、质量放行、金额冲销和退款是独立事实。退回货不能直接恢复可售；历史商品退货不能沿用“仅实物分流、不做财务冲销”的客户加工售后边界。

## 7. 成本与经营核算重点

**现有月度经营结果不等于自有产品毛利。** 必须区分采购付款、生产投入、存货成本、销售成本和期间费用。

| 业务 | 应保留的成本事实 | 需避免的问题 |
|---|---|---|
| 采购 | 原采购金额、适用的附加费用、批次、数量/重量和计价单位 | 付款时直接当作整批销售成本 |
| 自产 | 材料领退、直接人工、外协、确认纳入的制造费用、损耗及分摊依据 | 只有月度费用，没有工单或批次归集对象 |
| 完工 | 在制转成品、暂估成本、成本确认及调整记录 | 未售库存的生产投入全部扣当月销售利润 |
| 销售 | 原出库批次/单件的成本分配及销售成本记录 | 用当前采购价或商品售价计算历史出库成本 |
| 退货与更正 | 原出库成本、退回数量/重量及冲回关联 | 以最新成本冲回，或重复冲回应收和库存 |

同一笔人工、耗材、外协等费用应明确归属与处理状态，不能既进入产品销售成本，又被现有月度汇总重复扣减。加工收入与商品销售收入分别标识，收款不能直接当作收入。

计价方法在试点前确认：高价值、差异明显的单件可评估个别计价；同质批量商品可评估移动加权平均等方法。本文不默认选定方法。暂估、最终确认、跨期调整与关账后更正均保留记录，不静默改写历史结果。

| F3 | 采购验收入库、自有生产领退料/完工及成本流转 | F2；相关业务规则已确认 | 两来源汇入同一 SKU，原料到成品转换可追溯；未售库存与已售成本可区分 |
| F4 | 销售订单、预留/释放、分批发货、退货及最小盘点 | F2、F3 | 并发不超卖；取消可释放；退货待检；差异经审批入账 |
| F5 | 销售应收、核销、红字、成本调整及经营查询 | F4；结算与计价规则已确认 | 实物、金额及成本可相互追溯；加工与销售分别查询；无重复成本 |

**未来明确启动后，可先评审 F0 的剩余缺口与 F1 的档案和字段设计，具体安排以届时确认的实施计划为准。当前不据此启动任何阶段。** F2 实施前必须同时评审库存身份、权限、成本记录和历史兼容，避免只改一个必填字段。成本数据在 F2 开始保留，不能等 F5 展示报表时才补采集。

每个功能增量按 AGENTS 增加有业务价值的测试，执行后端全量、前端全量、生产构建和交付包结构门禁；独立语义化提交，并同步 README、14 和 23。涉及当前接口、上线决定和业务规则时分别更新 16、22、02，避免多个文档维护互相冲突的事实。

## 9. 验收场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 同一 SKU 采购 10 件、自产 10 件，入库时没有销售客户 | 汇总为 20 件，实际重量正确；来源批次和成本分别可查 |
| A02 | 同 SKU 同时存在客户来料和公司自有库存 | 客户库存不进入自有可售量；跨货权转移被拒绝 |
| A03 | 现货 10 件，两张订单并发各预留 6 件 | 最多一笔足额成功；余额与预留一致；双口径商品同时校验重量 |
| A04 | 同一入库或发货请求重复、并发或超时后重试 | 只有一次业务效果并返回原结果；同键不同内容拒绝 |
| A05 | 单据保存、第二条库存明细或成本记录写入失败 | 全部回滚；无孤立台账、半笔生产转换或重复应收；修复后可重试 |
| A06 | 订单部分发货后取消剩余数量 | 只释放未履约预留，已发数量及成本不被撤销 |
| A07 | 商品售出后成本变动，再发生部分退货 | 关联原出库，按原成本规则冲回；待检期间不可再次销售 |
| A08 | 原料 A、辅料 B 生产成品 C，含退料和损耗 | 每个动作全部明细原子提交，全流程可追溯且原料不重复扣减；数量、重量、成本按工艺口径核对 |
| A09 | 本月生产多、销售少，存在未售成品与在制品 | 未售存货成本独立列示；人工、耗材、外协没有重复扣减 |
| A10 | 仓管、销售、财务及客户范围账号访问 | 各自只能读写授权范围；销售无成本权限时接口也不返回成本 |
| A11 | 盘点差异及审批调整 | 冻结盘点基准或明确并发作业口径；仅批准后过账，保留差异和原因 |
| A12 | 旧客户库存迁移与 MySQL 安装/升级/恢复 | 数量重量按原维度一致；历史追溯完整；空库及失败恢复均验证 |

验收必须分别覆盖内存和 JDBC。跨模块故障、并发、权限和迁移在真实 MySQL 上复核，不能仅使用 H2 结果替代。
