## 调研结论

电脑端值得同步整理。手机端的归并涉及找单、单据详情、业务状态和操作入口；电脑端应采用相同的业务组织方式，避免同一事项在不同设备上需要重新理解。

电脑端继续发挥表格、筛选、键盘输入和并排对照的优势。本稿采用“紧凑分组导航 → 按岗位筛选列表 → 右侧同单详情 → 主动展开业务表单”。业务员与管理人员可以持续留在列表里核对；现场人员则从手机同一张单办理操作。

本次检查的是当前工作区源码，不是线上登录实测。主要依据为 `App.vue`、`AppShell.vue`、全局样式和来料、生产、进度、质检、库存、财务、客户等页面的模板及直接调用组件。当前工作区有既存未提交业务改动，本稿不代表它们已经发布或通过验收。

## 现有桌面布局可保留与需调整的部分

| 现有结构 | 调整理由 | 本次设计 |
|---|---|---|
| 按工作台、来料、生产、库存、财务、系统分组的侧栏 | 已有分组可沿用；手机作业与进度又作为独立入口，增加找功能的负担 | 统一订单中心，保留生产和质量的岗位作业视图；低频工具与系统管理集中 |
| `AppShell` 顶部追溯与模块内部查找 | 全局查单与当前列表筛选用途不同，需要清楚区分 | 顶部全局定位原单；列表内按单号、客户、工序、交期筛选 |
| 来料、生产、质检页面顶部的完整提交面板 | 打开列表前先出现录入面板，页面较长 | 列表优先；点新建或本单操作后打开有明确目标的表单 |
| 进度页内的进度表单、列表与改单内容 | 查询和多种提交集中在同一个长页面 | 列表展示进度；本单工序表单更新进度；改单独立做差异核对 |
| 列表加右侧详情 | 适合电脑核对，保留此基础 | 所有入口复用相同单据详情，可收起、展开完整详情、切换概况／流转／附件 |
| 库存分区与发货面板 | 存量分类正确；发货填写不必一直占据页面 | 保留三类库存；选批次查看流水，满足条件时打开该库存的发货确认 |
| 财务八个分区与客户档案中的账单 | 功能完整但入口分散，收款需携带客户和账期 | 账单内登记收款；工资成本、应付、经营分别展开 |
| 标签、附件、设备、配置、运维各自独立 | 跨单管理需要保留，日常作业可以贴近原单 | 详情内打印与留证；全局记录和配置进入工具／系统管理 |

## 手机与电脑的对应方式

| 业务概念 | 手机展示 | 电脑展示 | 共享约束 |
|---|---|---|---|
| 今日工作 | 待办卡片、本岗快捷操作 | 事项列表、临近交期、岗位快捷操作 | 轻任务、正式作业与审批分别办理 |
| 找单与进度 | 订单卡片、状态筛选 | 表格、客户／工序／交期筛选 | 同一有效数据范围，同一原单身份 |
| 扫码与定位 | 底部扫码键、相册与手输兜底 | 顶部查单、扫码枪输入及相关表单的现有扫码能力 | 同码多单必须选定，不自动取第一条 |
| 单据详情 | 独立详情页，底部主操作 | 右侧详情，可展开完整视图 | 同一要求、版本、轮次、流转与附件归属 |
| 收货 | 两段填写 | 分组表单与证据栏并排 | 来源明细、数量单位、要求快照、草稿证据保持一致 |
| 工序作业 | 单内切换进度与正式交工 | 业务表单内切换进度与正式交工 | 五档进度；100% 不自动交工或写库存 |
| 质检 | 逐条判定，异常展开 | 条款与单据／证据并排 | 过程说明、判定、冻结、返工、复检、放行分阶段 |
| 库存与交付 | 分类卡片 → 批次 | 分类表格 → 批次流水侧栏 | 公司料、客户备料、加工库存及不同单位分别处理 |
| 标签与附件 | 单内预览、提交任务、留证 | 单内预览；多选标签预览、所选记录导出 | 每单权限、标签快照、任务状态、原单证据独立保留 |
| 客户与财务 | 客户详情、账单内收款 | 客户列表与详情并排，账单和分摊展开 | 客户 ID、金额权限、账期与价格快照保留 |
| 工具与管理 | 更多中的分组入口 | 业务工具与系统管理 | 按账号真实菜单与有效权限开放 |

桌面“生产作业”“质量作业”是同一订单模型上的岗位视图，可以保存专用筛选与列；不再维护一份不同身份的订单详情。电脑导航不必与手机底栏逐字相同。

## 原有 17 个页面的桌面去向

| 当前页面 | 桌面拟议入口 | 仍可办理的事项 |
|---|---|---|
| 首页 | 工作台 | 待办、指派轻任务、临近交期与快捷操作 |
| 来料 | 订单中心 → 新建收货／母单详情 | 来源、多明细、加工要求、母单确认与拆单 |
| 客户档案 | 客户档案 | 客户、联系资料、别称、在制与授权账单 |
| 标签 | 单内标签；业务工具 → 标签记录 | 预览、目标工位、份数、打印任务、核纸、补打与改派 |
| 生产 | 生产作业 → 本单工序 | 进度、正式交工、交接、损耗及设备产量来源 |
| 进度 | 订单中心／生产作业 | 筛选、进度历史、改单与执行轮次 |
| 质检 | 质量作业 → 本单检验 | 条款、冻结、返工、复检、放行与损耗申请 |
| 库存 | 库存与交付 | 三类库存、批次流水、发货、退货、售后复核与冲正 |
| 财务 | 财务经营 | 客户账单、收款、工资、耗材、资产、折旧、应付与经营 |
| 审批 | 审批中心；工作台待办 | 按场景授权的审批、证据与历史 |
| 登记导入 | 业务工具 → 登记导入 | 模板、预检、警告／阻断复核与显式入账 |
| 附件 | 单内附件；业务工具 → 附件检索 | 原件、派生预览、签名、上传与待关联恢复 |
| 设备 | 系统管理 → 打印与设备 | 设备池、网关、读数与兼容资料 |
| 用户管理 | 系统管理 → 用户与权限 | 账号、顶岗、组织、客户及工序授权 |
| 配置 | 个人账号安全；系统管理 → 存储 | 会话、改密与存储配置分别进入 |
| 运维 | 系统管理 → 存储与运维 | 运行、告警、备份、升级与单据维护 |
| 手机作业 | 手机专用入口；电脑使用相应单内表单 | 保留扫码上下文和桌面／手机共享服务 |

入口归并不构成删除源码、API、迁移或后台依赖的依据。设计稿只对部分低频能力展示示意面板，表中保留事项在正式实施时仍需逐项检查可达性。

## 交互稿覆盖范围

10 个主要视图：工作台、订单中心、生产作业、质量作业、库存与交付、客户档案、财务经营、审批中心、业务工具、系统管理。

可点击体验：订单搜索与组合筛选、表格选择与详情、标签多选预览、导出所选样例、概况／流转／附件、分组收货、草稿保留、新母单打印、进度与交工、质检异常、库存选择及发货复核、客户账单收款、审批与管理入口。顶部可预览 6 个岗位；这只是入口收敛示意，不覆盖全部角色与顶岗组合。

所有客户、单据、金额、统计和媒体均为虚构样例。扫码枪、摄像头、真实上传、打印设备、API 和数据库未接入。大屏中的三类库存、五档进度、独立检验与放行等边界，沿用手机提案中的规则。

## 实施时需辨别的依赖

- **可以优先在前端整理：** 导航分组、列表优先、表单主动展开、原目标传递、详情组件复用、响应式布局、已有客户账单与收款的关联入口。
- **需要核对或补查询契约：** 跨母子单／轮次聚合列表、统一统计、服务端分页筛选、聚合时间线、各场景附件汇总。不能把浏览器里几张样例表拼接当成正式查询方案。
- **多选操作单独评估：** 设计稿提供多张标签预览与所选样例导出；真实批量打印需逐单校验权限、版本、目标及幂等，返回每项结果。没有接口支持前，可先保留单单提交，不增加批量交工、审批、发货或入账。
- **正式权限使用现有会话：** `menuCodes`、`menuTree`、`effectivePermissions`、顶岗和服务端数据范围共同决定入口与动作。不得使用设计稿里的简化角色对象。

## 建议用户确认

1. 是否接受“统一订单中心 + 保留生产／质量岗位视图”，以及列表与右侧详情的布局。
2. 是否接受主动打开收货、交工、质检、发货表单，减少页面默认展开的内容。
3. 是否接受客户内看订单与账单、单内看标签与附件、工具与管理按职责分组。

手机方向已认可；桌面稿确认后，再按交接说明把公共上下文与两种布局逐步接入现有 Vue 项目。

## 本次原型验证

- Chrome 直接打开本地 HTML；10 个主要视图在 1024、1280、1366、1440、1600、1920 像素宽度下，共 60 个组合没有页面横向溢出；表格在空间不足时允许在自己的区域滚动。
- 订单搜索、组合筛选、多选标签预览、详情切换、附件筛选、进度／正式交工、质检失败分支、收货草稿保留及新母单标签、库存选择发货、客户账单收款、审批与管理入口的模拟流程通过。
- 定向核对筛选后旧选中单据清除、重新选单、云璟玉器账单与收款客户一致、未放行批次不显示发货入口；未出现 JavaScript 运行错误。
- 人工查看桌面、笔记本、收货表单与质检表单截图。验证仅覆盖独立设计稿，未运行正式业务测试或构建，没有真实设备、数据库或线上验收。
