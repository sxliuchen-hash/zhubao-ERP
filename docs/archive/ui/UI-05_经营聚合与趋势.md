## 契约

新增 `GET /api/finance/dashboard?yearMonth=YYYY-MM&customerId=可选编号`，沿用 `ApiResponse` 包络。参数校验、错误状态和数字精度与现有 API 一致。

`data` 的一级字段固定为：

| 字段 | 含义 |
|---|---|
| `yearMonth` | 选择的统计月份 |
| `generatedAt` | 服务端本次生成时间 |
| `scope` | 实际公司／客户范围，以及统计口径说明；不能回传未授权客户 |
| `operating` | `revenue`、`wageCost`、`consumableCost`、`depreciationCost`、`outsourceCost`、`result`、`gaps` |
| `trend` | 含选择月份在内的六个月，每月为同范围经营结果与缺项状态 |
| `currentBalances` | UI-06 补齐；本段返回 `null` 并明确尚不可用 |
| `receivableRanking` | UI-06 补齐；本段为 `null`，不能用空数组冒充已查询无余额 |
| `capabilities` | 明确本段支持的部分和各部分不可用原因，不能靠数值 0 表示不支持 |

内部 DTO 可按项目规范命名，类型与字段在 docs/16 中准确记录。字段扩展应兼容，不改掉既有接口字段意义。

## 实施

1. 用服务端授权范围和既有计价／成本规则聚合；不能先计算全公司结果再只过滤客户名单。
2. 公司范围保留公司折旧和未分配成本；客户范围只含可归集成本并显示口径，不把公司成本平摊或按收入比例临时分摊。
3. 六个月共享同一范围与核算语义；当前月标识截至本次查询，不能与完整月直接计算误导性增幅。
4. 保留工资未确认、折旧未生成、未计价等 gaps。真实零值、不可用、缺项与查询失败分开。
5. 金额使用既有 BigDecimal 与精度规则；保持内存／JDBC 可切换，不复制一份固定历史数据。优先只读聚合已有记录，不新增财务账套或历史快照表。
6. 查询不调用生成账单、工资、折旧和核销命令。查询前后记录数与业务状态不变。

有冲销净额、四类成本、工资未确认、折旧缺失、未计价、六个月缺项、非法月份、授权集合及客户范围测试；内存与 JDBC 结果一致。明确验证读取不写账。现有构造器调用和既有经营报表测试兼容。
