## 1. 基线链路（`4447d79`）

| 环节 | 入口 | 现行判断 |
|---|---|---|
| 改名与别称 | 客户档案保存 | 稳定客户编号不变。名称变化时把原名称并入别称，不覆盖已保存单据上的客户名称快照。 |
| 历史名称授权 | 登录会话解析 | 授权客户范围先取授权表，没有授权行时用账号上的客户范围。名称、客户编码或别称只能在唯一对应一个档案时换成客户编号；对上多家或对不上时丢掉该值，不另外授权。纯数字编号保持原值。`客户#编号` 目前对不上名称规则，会被丢掉。 |
| 母子单列表 | 正式工作台、进度 | 工作台空的授权客户范围看不到单据。进度把空范围当成不限制，授权客户范围在歧义名称被丢掉后会看到全部客户。子单另用自己的客户名称参与匹配。 |
| 附件 | 附件读取、手机采集 | 列表和预览走单据归属。采集在客户范围为空时直接通过，授权客户范围因此被放宽。 |
| 打印查询 | 打印任务、母单／子单标签 | 打印任务沿用单据读取。`GET /api/label/mother-orders/{code}` 和 `GET /api/label/work-orders/{code}` 不核对客户范围。 |
| 扫码 | `/api/scan/context` | 同码多种单据、一运单多母单、已拆母单会要求选择，不取第一条。扫码使用账号上的原始客户范围，不使用会话里已经收成编号的范围。 |

改名本身不把授权从旧客户挪到同名新客户：名称授权一旦同时对上旧别称和新客户，整段授权变空。客户编号授权不受这次改名影响。空范围若被某个查询当成“不限制”，歧义授权就会被放宽。

- 扫码查询和过程说明使用会话里的有效客户范围。账号上残留的旧名称不会在改名后匹配到同名新客户。

## 3. 跨材质子单（只调查，未改代码）

多材质可以停在母单上，不能进入一张子单。现有测试 `MultiMaterialIntakeSplitTest` 已覆盖：同一母单两种材质分别入账；一张子单同时分配两种材质被拒绝，且不产生子单和额外库存流水；按材质拆开后，来源行剩余数量可核对。

| 位置 | 现在怎么处理 |
|---|---|
| 收货 | 逐行写入 `biz_receipt_line`，每种材质一条待加工库存。母单头上的材质仍是第一行。同一母单的数量单位必须相同，否则拒绝入账。 |
| 不拆 | 收货明细多于一种材质时，不能整单不拆。 |
| 拆单 | 新收货必须按来源行分配，并核对每行剩余数量和重量。一张子单的来源行出现两种材质就拒绝。子单头只保存第一种来源材质、一个数量单位和第一笔库存流水编号；同材质的多行来源会把货品名称写成「多材质」。 |
| 工序、质检、发货 | 只读子单头上的一个材质、一个数量单位和一组数量、重量。库存转移不允许改变物料。 |
| 财务 | 现行财务代码不按材质分账，账单按单据和工序。它解释不了一张子单里的两种材质。 |

因此继续拒绝跨材质子单。若以后要放开，最小契约要先定：子单头不能再代表全部材质；每种材质保留自己的来源行、剩余量、在制流水，以及工序、质检、发货和账单如何分别引用这些行。在这之前不改拆单、库存和财务。
