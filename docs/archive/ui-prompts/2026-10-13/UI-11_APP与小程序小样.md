# UI-11：APP 与微信小程序可行性小样

**归档说明（2026-10-13）**：本文保留历史执行提示，不作为当前开发指令或验收证明；现行唯一入口见 [项目核心](../../../00_项目核心.md)。
前置：UI-10 已完成，且用户明确启动本段。此前各任务不能提前创建跨端应用工程。

## 目标

验证相同品牌、字段、权限和任务流程能在 APP／微信小程序运行；不是一次交付两端正式产品。

## 执行顺序

1. 先只读核对当前 Web／PWA 能力、共享类型、API、扫码、拍摄和文件上传契约，并形成平台差异表。
2. 查候选框架的当前官方资料，重点验证扫码、短视频上传、登录绑定、包体、相机与文件生命周期。uni-app 是候选，不是已确认选型。
3. 写清候选、依赖、最小工程范围、测试设备和可成功判定的条件。只有确认具体平台方案后才创建隔离的小样，不改现有桌面工程。
4. 小样最多四个真实流程：登录／账号绑定、扫码识别、短视频上传、任务详情与岗位校验。继续使用现有后端权限和业务命令，不带入概念图样例。
5. 平台适配扫码、拍摄、上传、登录、通知与打印，不能直接复制浏览器 DOM 或承诺已有 Vue 页面零改动跨端。

## 完成条件

真机覆盖拒绝授权、弱光扫码、上传中切后台、弱网恢复、登录过期、安全区和重复提交。输出可运行小样、实际结果、平台限制及正式版工作量边界。

缺少签名、平台账号、开发工具或真机时先完成可独立验证部分，明确缺项；不得模拟平台审核通过或宣称已经正式发布。不得自动部署、发布或购买服务。完成后等待用户决定正式移动应用范围。
