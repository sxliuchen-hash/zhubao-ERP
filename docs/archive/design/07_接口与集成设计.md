## 1. 设计原则

- 内部接口优先服务业务闭环，不为未来集成过度设计。
- 扫码、标签、视频、附件、报表这些跨模块能力必须有稳定接口。
- 外部系统一期只做预留，不承诺正式对接。
- 所有修改类接口必须鉴权、校验权限并写操作日志。
- 库存余额不提供直接修改接口，只提供业务动作接口。

---

## 2. 接口风格

最终采用 Java/Vue + RuoYi-Vue 定制路线，内部接口建议 RESTful JSON API。

通用返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 100,
    "pageNo": 1,
    "pageSize": 20,
    "records": []
  }
}
```

ERPNext/Frappe 不作为生产主路线，仅作为模型参考，因此生产接口以本文件定义的 RESTful JSON API 为准。

### 3.2 权限规则

- 所有 API 必须校验登录态。
- 业务查询接口必须校验数据范围。
- 修改、审批、导出、视频替换、标签补打必须写操作日志。

## 4. 扫码内容格式

二维码内容建议使用 JSON 字符串或短格式。为兼容打印尺寸，默认推荐短格式。

### 4.1 短格式

```text
JG|WO|CC-20260706-001-JL-ZD001
```

格式：

```text
系统标识|对象类型|对象编码
```

对象类型：

| 类型 | 说明 |
|---|---|
| MO | 母单 |
| WO | 子工单/返工工单 |
| OUT | 出库单 |
| EXP | 快递单号 |

### 4.2 JSON 格式

```json
{
  "sys": "JG",
  "type": "WO",
  "code": "CC-20260706-001-JL-ZD001",
  "v": 1
}
```

### 4.3 扫码解析接口

```http
POST /api/scan/resolve
```

入参：

```json
{
  "content": "JG|WO|CC-20260706-001-JL-ZD001",
  "scene": "pwa_report"
}
```

出参：

```json
{
  "objectType": "work_order",
  "objectId": 1001,
  "code": "CC-20260706-001-JL-ZD001",
  "nextAction": "report",
  "allowed": true
}
```

## 5. 标签模板接口

### 5.1 获取标签数据

```http
GET /api/labels/{objectType}/{objectId}
```

示例出参：

```json
{
  "templateCode": "WORK_ORDER_LABEL_V1",
  "title": "子工单",
  "fields": {
    "workOrderCode": "CC-20260706-001-JL-ZD001",
    "motherOrderCode": "CC-20260706-001-JL",
    "customerName": "某客户",
    "materialName": "金饰",
    "quantity": "10",
    "weight": "35.200g"
  },
  "qrContent": "JG|WO|CC-20260706-001-JL-ZD001"
}
```

### 5.2 记录补打

```http
POST /api/labels/reprint
```

入参：

```json
{
  "objectType": "work_order",
  "objectId": 1001,
  "reason": "原标签破损"
```

- 补打必须记录操作人、时间、对象、原因。

## 7. 工单、报工与称重接口

### 7.1 拆分子工单

```http
POST /api/mother-orders/{id}/split-work-orders
```

入参：

```json
{
  "processTemplateId": 1,
  "items": [
    {
      "quantity": 5,
      "weight": 17.6,
      "assignedEmployeeId": 101
    },
    {
      "quantity": 5,
      "weight": 17.6,
      "assignedEmployeeId": 102
    }
  ]
}
```

校验：

- 拆分合计不得超过母单可分配余额。

- 生成工序实例时保存单价和损耗率快照。

- `materialId`

## 15. 核心业务工作台接口

当前 M2 先提供评审/联调用确定性样例 API，后续 M3 迁移为真实业务聚合查询。

统一前缀：

```http
/api/business/workspaces
```

### 15.1 查询工作台汇总

```http
GET /api/business/workspaces/summary
```

返回：

- `inboundOrders`
- `activeWorkOrders`
- `pendingQualityCases`
- `inventoryLedgerEntries`
- `mobileTasks`

### 15.2 查询来料工作台

```http
GET /api/business/workspaces/inbound
```

返回：

- `checkpoints`：待扫码、待称重、视频完整率、标签状态。
- `orders`：来料母单队列。
- `risks`：入库异常和下一步动作。

### 15.3 查询生产工作台

```http
GET /api/business/workspaces/production
```

返回：

- `stationLoads`：工位负载和瓶颈。
- `workOrders`：在制工单。
- `handoffs`：称重交接记录。

### 15.4 查询质检工作台

```http
GET /api/business/workspaces/quality
```

返回：

- `metrics`：质检指标。
- `cases`：待处理质检。
- `lossApprovals`：损耗审批。

### 15.5 查询库存追溯工作台

```http
GET /api/business/workspaces/inventory
```

返回：

- `balances`：库存余额。
- `ledgerEntries`：库存台账明细。
- `timeline`：追溯时间线。
- `evidence`：证据完整性。

### 15.6 查询 PWA 作业工作台

```http
GET /api/business/workspaces/mobile
```

返回：

- `tasks`：移动现场任务。
- `capabilities`：PWA 能力边界。
- `offlineDrafts`：离线草稿。

字段契约详见：[16_字段字典与API契约](../../16_字段字典与API契约.md)。

## 16. 外部接口预留

一期只做预留，不纳入主验收。

| 外部系统 | 预留方向 |
|---|---|
| 快递 | 快递单号识别、物流轨迹查询 |
| 短信/企业微信 | 审批、异常、发货通知 |
| 财务软件 | 工资试算、加工费、成本数据导出 |
| 人脸/门禁 | 操作人身份辅助确认 |
| 电子秤 | 串口/USB/蓝牙/TCP 自动读数 |
| 客户门户 | 客户查看订单进度和追溯 |

---

## 17. 接口验收标准

- PWA 扫码后能正确解析母单、子工单、出库单。
- 确认入库接口能生成母单、库存台账、视频任务。
- 拆分工单接口能生成子工单和工序实例。
- 报工接口能计算损耗并触发审批。
- 质检接口能生成返工工单或报废记录。
- 出库接口能冻结库存并在发货后扣减库存。
- 追溯接口能返回完整时间线。
- 报表导出接口能异步生成 Excel 文件。
- 样例接口能返回可复用验收样例。
- 硬件接口能返回设备兼容状态、联动任务和人工兜底信息。
- 工作台接口能返回来料、生产、质检、库存、PWA 的评审数据和字段契约。
