# 手机现场采集方案

> 历史归档：2026-10-10 冻结，仅供追溯编写时方案；当前规则、契约和运行方式以 [文档索引](../../README.md) 中的现行文档为准。

**更新日期**：2026-10-08  
**定位**：前期低成本试运行。工人用自己的手机拍照、录短视频，挂到母单、工单、返工单或出货单上。  
**录像机**：`/api/video-clip-tasks` 保留，作为以后按时间从录像机截取的备选，试运行不采购、不启用、不在作业页引导。

关联：[02 业务流程](../../02_业务流程与规则设计.md)、[07 接口](./07_接口与集成设计.md)。

## 1. 试运行做什么

工人扫标签上的二维码，确认单据后选择场景，用后置摄像头拍一张照片或录一段短视频，上传后在电脑上打开这张单就能看到。

| 场景 | 挂到 | 典型内容 |
|---|---|---|
| 拆包 | 母单 | 开箱、货品外观 |
| 称重 | 母单或工单 | 秤面读数 |
| 缺陷 | 工单或返工单 | 瑕疵特写 |
| 成品 | 出货单或工单 | 装箱前外观 |

同一张单可以有多张照片和多段短视频。进度、工序状态仍不印在标签上，也不靠视频代替报工。

试运行明确不做：

- 不接录像机、不按开始/结束时间截取、不跑 FFmpeg。
- 不上对象存储，文件落在本机 `zhubao.documents.storage.local-root`（默认 `target/zhubao-evidence`）。
- 不做连续监控，不做超过限长的视频。
- 不把手机录像写进视频截取任务。

## 2. 现场步骤

1. 手机打开「手机作业」，已登录。
2. 扫描标签二维码。内容形如 `JG|mother|母单号`、`JG|work_order|工单号`、`JG|outbound|出货单号`、`JG|rework|返工单号`。扫不出来时允许手输编码。
3. 页面显示客户、物料和单号，工人选择场景：拆包、称重、缺陷、成品。
4. 拍照或录像。照片走系统相册/相机，视频由手机自带相机录完再交回页面。
5. 上传。成功后看到缩略图或文件名；失败停在当前页，可原文件重试。
6. 电脑端来料、生产、质检、库存打开同一单号，侧栏列出这些照片和短视频，用现有短期预览链接查看。

弱网只保证「这一次没传上去可以再点一次」。完整的离线队列放到试运行之后，当前离线草稿列表不承担采集。

## 3. 和现有代码的落点

| 现况 | 试运行改法 |
|---|---|
| `MobileOpsWorkspace.vue` 是电脑里的手机示意，按钮没有动作 | 已改成手机收货：识别快递单号、填写要求和期限、生成母单、上传拆包视频 |
| `ScanResolver.vue` 只解析手填文本，且只认 `MO/WO/OUT/EXP` | 已与标签对齐，认 `mother/work_order/outbound/rework`，并保留旧类型。快递面单按运单号识别。实时扫码优先用 `BarcodeDetector`，没有则用内置 ZXing。摄像头打不开时拍一张面单照片再识别 |
| `POST /api/documents/attachments/uploads` 要先有文档包，并把整个文件读进内存 | 已新增 `POST /api/documents/captures`，按单号自动建证据包，文件流式落盘 |
| 附件页上传的是写死的文本文件 | 电脑附件页改为查看；采集入口只在手机作业 |
| 操作工没有 `DOCUMENT_ATTACHMENT_UPLOAD` | 操作工、收货、库管、质检、车间主管可采集自己范围内的单据 |
| 来料单上的「视频失败 / 已关联」来自录像任务状态 | 改为这张单有没有手机视频。有视频记「已关联」，没有记「待补」 |
| `VideoClipTaskService` 只在内存里记截取任务，手工上传只收存储键 | 接口保留，作业页和来料确认不再调用 |

标签服务已经生成 `JG|<scanType>|<编码>`，见 `LabelType`。前端 `scanCode.ts` 仍按旧的 `MO/WO/OUT/EXP` 解析，采集前必须先改齐，否则刚打出来的标签扫不进采集页。

## 4. 接口

采集上传：

```http
POST /api/documents/captures
Content-Type: multipart/form-data
```

| 字段 | 说明 |
|---|---|
| objectType | `mother`、`work_order`、`outbound`、`rework` |
| businessCode | 标签上的编码 |
| scene | `UNPACK`、`WEIGH`、`DEFECT`、`FINISH` |
| file | 照片或短视频 |

服务端：

- 校验登录、角色和客户范围。单号不在范围内则拒绝。
- 照片允许 `image/jpeg`、`image/png`，单张不超过 8MB。
- 视频允许 `video/mp4`、`video/webm`，单个不超过 50MB。页面上提示不超过 30 秒，服务端以大小为准。
- 没有证据包时自动建立，包编码 `DOC-<businessCode>`，业务类型写场景中文名（拆包、称重、缺陷、成品）。
- 用文件流写入现有 `LocalAttachmentObjectStorage`，继续算 SHA-256。同一校验和重复上传时返回已有附件，不存第二份。
- 来源固定为「手机采集」，操作人取当前登录账号。
- 返回附件编码、校验和和现有预览地址。

按单查询：

```http
GET /api/documents/captures?businessCode={编码}
```

返回该单号下的照片和视频元数据，供电脑侧栏使用。内容读取继续走 `GET /api/documents/attachments/{code}/content` 的短期签名。

配置放在 `application.yml` 的 `zhubao.documents.capture`：照片上限、视频上限。默认即上面的 8MB 和 50MB。

`POST /api/documents/attachments/uploads` 保持给电脑端已有文档包使用，手机采集不走它。`/api/video-clip-tasks` 不增加手机文件接收。

## 5. 权限和存储

- 新增权限「手机采集」。授予操作工、收货员、库管员、质检员、车间主管。
- 只允许给扫到的、且在自己客户范围内的单据上传。不能凭这个权限改库存或删别人的附件。
- 试运行文件留在本机目录。备份沿用现有数据库备份之外，试运行结束前要确认这个目录是否纳入现场拷贝。对象存储以后再切换，不改变上传接口。

## 6. 验收

用一部 Android 手机连上试运行环境。地址用 `https://服务器IP`。自签证书提示不受信任时选择继续访问，否则摄像头打不开。上传走网页入口，单次请求不超过 55MB：

1. 扫一张母单标签，拍一张拆包照片并上传，来料页该母单能打开这张图。
2. 再录一段 10 秒左右的短视频并上传，同一母单显示「已关联」，并能播放。
3. 换一个不在客户范围内的单号，上传被拒绝。
4. 故意传一个超过 50MB 的文件，被拒绝且不落盘。
5. 上传中途断网，页面保留文件，恢复后重试成功，且只留下一条附件。
6. 作业页找不到「创建截取任务」或录像机入口。

## 7. 施工顺序

1. 扫码解析与标签格式对齐，并补测试。
2. 采集上传和按单查询，含自动建包、大小限制、校验和去重、操作工权限。
3. 手机作业页改成扫码、选场景、拍照或录像、上传和重试。
4. 来料、生产、质检、库存的当前单据侧栏展示该单照片和视频，来料视频状态改读采集结果。
5. 从作业路径拿掉截取任务引导。录像机接口和硬件页里的历史说明留在备选，不删代码。

第 1、2 步完成就可以用接口试传。第 3、4 步完成才算工人能在手机上试运行。
