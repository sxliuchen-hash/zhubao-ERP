## 1. 管理目标

配置与构型管理用于确保系统从试点到正式上线的配置可追溯、可复现、可审计。

当前 M2.2 已落地只读配置基线：

- 后端 API：`/api/configuration/baseline/*`。
- 前端页面：`配置基线`。
- SQL 草案：[V4__m2_configuration_baseline_contract.sql](../backend/src/main/resources/db/mysql/V4__m2_configuration_baseline_contract.sql)。
- 变更控制 SQL 草案：[V5__m2_configuration_change_control_contract.sql](../backend/src/main/resources/db/mysql/V5__m2_configuration_change_control_contract.sql)。
- 代码基线：[ConfigurationBaselineService.java](../backend/src/main/java/com/zhubao/erp/configuration/app/ConfigurationBaselineService.java)。

注意：当前为评审和 M3 迁移基线，不开放生产编辑。正式可编辑前必须补齐权限、审批、审计日志和历史版本。

覆盖范围：

- 系统参数。
- 编码规则。
- 角色权限。
- 工序模板。
- 损耗率。

## 4. 编码规则

### 4.1 编码原则

- 编码唯一。
- 编码可读。
- 编码不承载敏感信息。
- 编码生成后不可修改。
- 作废单据编码不复用。

### 4.2 建议格式

| 对象 | 格式 | 示例 |
|---|---|---|
| 客户订单 | `ORD-YYYYMMDD-流水号` | `ORD-20260706-001` |
| 母单 | `CC-YYYYMMDD-流水号-客户简称` | `CC-20260706-001-JL` |
| 子工单 | `母单编码-ZD流水号` | `CC-20260706-001-JL-ZD001` |
| 返工工单 | `原工单编码-FG流水号` | `CC-20260706-001-JL-ZD001-FG001` |
| 质检单 | `QC-YYYYMMDD-流水号` | `QC-20260706-001` |
| 损耗单 | `LS-YYYYMMDD-流水号` | `LS-20260706-001` |
| 出库单 | `OUT-YYYYMMDD-流水号` | `OUT-20260706-001` |
| 库存台账 | `STK-YYYYMMDD-流水号` | `STK-20260706-001` |
| 审批单 | `APR-YYYYMMDD-流水号` | `APR-20260706-001` |

## 6. 工序模板配置

### 6.1 工序配置项

| 配置 | 说明 |
|---|---|
| 工序名称 | 如串制、雕刻、打磨、抛光、质检、包装 |
| 工序类别 | 人工/设备/质检/包装，用于决定页面字段和统计口径 |
| 默认工作项目 | 如粗抛、精抛、返工抛光、雕刻 |
| 默认数量单位 | 如件、颗、条、批；影响报工、产能统计和工资试算 |
| 是否设备工序 | 设备工序必须支持机器编号和产能统计 |
| 是否计件 | 是否进入工资试算 |
| 计件单价 | 保存历史，工单创建时快照 |
| 是否记录损耗 | 是否要求录入损耗 |
| 标准损耗率 | 工单创建时快照 |
| 是否必须质检 | 报工后是否进入待质检 |
| 是否必须称重交接 | 关键工序控制 |
| 是否必须交单审核 | 抛光等人工工序提交后是否需要组长/下工序审核 |
| 是否必须操机签字 | 雕刻等设备工序是否要求操机确认 |
| 是否启用表头继承 | Excel/纸质表导入时，姓名、日期、客户、品类等表头上下文是否继承到明细行 |

### 6.2 一期建议工序模板补齐

| 模板 | 适用范围 | 工序顺序 | 关键字段 |
|---|---|---|---|
| 戒托标准加工 | 18K 金戒托 / PT950 吊坠坯 | 雕刻 -> 粗抛 -> 精抛 -> 镶石 -> 终检入库 | 雕刻记录机器编号和品类；抛光记录工作项目、开始/完成时间、交单审核 |
| 银链标准加工 | 银链半成品 | 焊接 -> 打磨 -> 清洗 -> 终检入库 | 焊接/打磨计件，焊接称重，终检入库 |
| 雕刻单工序统计 | 雕刻来料或半成品 | 雕刻 -> 交单审核 | 机器编号、雕刻数量、数量单位、操机签字、设备产能；支持日期/客户/品类继承 |
| 抛光返工模板 | 返工件 | 返工抛光 -> 复检 | 默认不计正式工资，需交单审核和复检；支持姓名/日期表头继承 |

### 6.3 模板变更规则

- 模板变更只影响新建工单。
- 已生成的工序实例不随模板变更自动变化。
- 模板启停必须记录日志。
- 默认数量单位变更只影响新报工和新导入记录，历史工资试算和库存台账不得被重算。

## 7. 损耗率与计件单价

### 7.1 损耗率

配置维度建议：

```text
客户 + 物料 + 工序 + 产品类型
```

一期可简化为：

```text
物料 + 工序
```

变更规则：

- 损耗率变更必须保留历史。
- 工序实例创建时保存损耗率快照。
- 历史工单不因损耗率变更而重算，除非走专门重算流程。

### 7.2 计件单价

配置维度建议：

```text
工序 + 产品类型 + 难度等级
```

一期可简化为：

```text
工序
```

规则：

- 单价变更必须保留历史。
- 工序实例创建时保存单价快照。
- 返工报工默认不计工资。
- 一期工资试算不正式发放。

## 8. 仓库与库存状态

### 8.1 仓库基线

| 仓库 | 说明 |
|---|---|
| 待加工来料仓 | 客户来料确认入库后进入 |
| 在制仓 | 子工单加工中 |
| 半成品仓 | 中间状态，可按业务启用 |
| 成品仓 | 质检通过后待发货 |
| 冻结仓 | 创建出库单后冻结 |
| 返工品仓 | 返工中或待返工 |
| 报废品仓 | 报废物料 |
| 已发货 | 逻辑状态，不一定对应实体仓 |

### 8.2 状态变更规则

- 来料入库：外部 -> 待加工。
- 拆分工单：待加工 -> 在制。
- 完工入库：在制 -> 成品。
- 创建出库：成品 -> 冻结。
- 确认发货：冻结 -> 已发货。
- 返工：成品/在制 -> 返工。
- 报废：对应状态 -> 报废。

## 13. 备份与恢复

### 13.1 备份范围

- 业务数据库。
- 上传附件。
- 视频片段。
- 配置文件。
- 标签模板。
- 报表模板。

### 13.2 备份策略

| 对象 | 建议 |
|---|---|
| 数据库 | 每日全量备份 + binlog 增量，关键阶段增加手动备份 |
| 视频附件 | NAS 快照或文件级增量备份，按保存周期归档 |

| 指标 | 试点目标 | 正式目标 |
|---|---|---|
| RPO | 24 小时 | 15-60 分钟 |

| 恢复演练 | 试点前 1 次 | 每季度 1 次 |
| 备份保留 | 30 天 | 90 天以上 |

### 13.3 恢复演练

试点前至少完成一次恢复演练：

- 从备份恢复数据库。
- 恢复附件和视频访问。
- 验证追溯链路可打开媒体文件。

## 13.4 Docker Compose 运行构型

M3.41 新增 Docker 离线交付基线，运行构型纳入 C4 环境配置管理。M3.44 起，运行包增加 `MANIFEST.sha256` 和 zip `.sha256`，用于构建后上传、客户服务器解压和启动前的完整性校验。M3.45 起，运维中心区分前端展示地址和后端探活地址。

| 配置域 | 文件/变量 | 默认值 | 管理要求 |
|---|---|---|---|
| 镜像版本 | `ZHUBAO_IMAGE_TAG` | `local` | 每次交付必须固定版本号，不使用浮动 tag |
| 后端镜像 | `ZHUBAO_BACKEND_IMAGE` | `zhubao-erp-backend` | 构建机生成，客户侧只加载镜像 tar |
| 前端镜像 | `ZHUBAO_FRONTEND_IMAGE` | `zhubao-erp-frontend` | 只包含 `frontend/dist` 和 Nginx 配置 |
| MySQL 镜像 | `ZHUBAO_MYSQL_IMAGE` | `mysql:8.4` | 版本升级必须先在测试环境验证 |
| 前端端口 | `ZHUBAO_HTTP_PORT` | `80` | 与现场反向代理/防火墙配置同步 |
| 后端端口 | `ZHUBAO_BACKEND_PORT` | `8080` | 默认仅运维直连，前端通过 Nginx 代理 API |
| 前端展示地址 | `ZHUBAO_PUBLIC_URL` / `ZHUBAO_FRONTEND_URL` | `http://localhost/` | 运维中心展示给用户看的访问地址 |
| 前端探活地址 | `ZHUBAO_FRONTEND_PROBE_URL` | `http://frontend/` | 后端容器内部实际 HTTP 探活地址 |
| 前端探活超时 | `ZHUBAO_FRONTEND_PROBE_TIMEOUT_MS` | `800` | 过短会误报，过长会拖慢运维中心响应 |
| 数据库账号 | `ZHUBAO_DB_USERNAME` / `ZHUBAO_DB_PASSWORD` | `zhubao` / `change-me` | 生产必须修改并记录在交付配置单 |
| 数据库 root 密码 | `ZHUBAO_DB_ROOT_PASSWORD` | `change-root-me` | 生产必须修改，禁止使用默认值 |
| 业务仓储 | `ZHUBAO_BUSINESS_REPOSITORY` | `jdbc` | Docker 运行默认使用 JDBC |
| 审批仓储 | `ZHUBAO_APPROVAL_REPOSITORY` | `jdbc` | Docker 运行默认使用 JDBC |
| 文档仓储 | `ZHUBAO_DOCUMENTS_REPOSITORY` | `jdbc` | 元数据默认使用 JDBC，二进制内容走本地对象存储卷 |
| 运行包校验 | `MANIFEST.sha256` / `<zip>.sha256` | 构建时生成 | `.env` 可现场修改不纳入 manifest，其他运行文件启动前校验 |

运行包持久化卷：

- `mysql-data`：MySQL 数据。
- `evidence-data`：附件与证据文件。
- `backend-logs`：后端日志。
- `backup-data`：备份目录和运维中心备份检查目录。

当前 Docker 基线只完成首次初始化和运行包交付；已有数据库升级、自动备份任务、恢复演练和 HTTPS 仍需单独纳入上线构型。

## 14. 变更控制

### 14.1 变更流程

1. 提出变更。
2. 判断变更等级。
3. 评估影响：业务、数据、权限、库存、报表、硬件。
4. 审批。
5. 测试环境验证。
6. 发布到试点或生产。
7. 记录变更结果。

### 14.2 必须审批的变更

- 损耗率。
- 计件单价。
- 库存状态。
- 编码规则。
- 角色权限。
- 视频保存周期。
- 数据库结构。
- 开源组件版本。

## 17. M3.52/M3.63/M3.86/M3.87/M3.88/M3.89/M3.90/M3.91/M3.92/M3.93 权限上下文、登录会话与导航过滤基线

配置基线页新增“当前权限 / 数据范围边界”面板。M3.63 起支持登录会话和 Bearer token，M3.83 起后端返回授权菜单树，M3.86 起前端登录会话按 `menuCodes/menuTree` 过滤侧栏导航，M3.87 起登录账号从 `AuthUserAccountRepository` 读取并使用 PBKDF2 密码哈希校验，M3.88 起同一账号仓储记录失败次数和临时锁定，M3.89 起增加账号启停、管理员解锁和只读账号状态摘要展示，M3.90 起账号创建/重置密码必须通过生产密码策略校验，M3.91 起生产账号按 `password_changed_at` 做 90 天过期检测，管理员重置密码会刷新改密时间，M3.92 起已登录用户可通过 Bearer 会话自助修改密码并刷新改密时间，M3.93 起认证审计事件写入摘要链并提供最近事件完整性校验摘要。评审请求头仍作为自动化测试和无后端登录场景的兜底，避免页面看起来有权限控制但业务和技术边界不清。

| 构型项 | 当前值 | 说明 |
|---|---|---|
| 登录接口 | `POST /api/auth/login` | 从账号仓储读取账号并校验 PBKDF2 密码哈希，返回内存 token 和菜单编码基线 |
| 会话接口 | `GET /api/auth/session`、`POST /api/auth/logout` | 前端保存 token 并在退出时清理本地 token |
| 演示账号接口 | `GET /api/auth/demo-users` | 返回 M3 评审账号，不用于生产 |
| 账号仓储 | `zhubao.auth.users.repository` / `ZHUBAO_AUTH_USERS_REPOSITORY` | 本地默认 `memory`，MySQL profile 默认 `jdbc` 写入 `auth_user_account`；M3.93 已覆盖 `password_changed_at`、失败次数、锁定到期、最近登录、最近失败、启停、管理员解锁、密码策略校验、密码过期检测、登录态自助改密和认证审计摘要链展示 |
| 账号管理接口 | `GET/POST /api/auth/accounts`、`POST /api/auth/accounts/{username}/status`、`POST /api/auth/accounts/{username}/unlock` | 仅 `AUTH_ACCOUNT_MANAGE` 权限可用；要求 Bearer 会话或显式评审角色头，不走匿名默认管理员兜底；创建/重置密码需至少 12 位、包含字母和数字、无首尾空白、不得等于账号名且不得使用常见弱口令，并刷新 `passwordChangedAt`；当前为账号管理/解锁/密码策略/密码过期检测边界，不等于完整 IAM |
| 密码过期边界 | `PasswordExpiryPolicy` | 生产账号 90 天过期；`passwordChangedAt` 为空的生产账号视为过期；评审 seed 账号在该边界中不因 90 天规则过期；登录会话与账号摘要返回改密时间、到期时间和过期状态 |
| 自助改密接口 | `POST /api/auth/password` | 仅接受 `Authorization: Bearer <token>`；不使用请求头角色兜底；校验当前密码、新密码策略和新旧密码不同，成功后刷新 `passwordChangedAt`、清零失败锁定并写 `PASSWORD_CHANGE` 审计 |
| 审计完整性接口 | `GET /api/auth/audit-integrity` | 校验最近认证审计事件的 `previousEventHash/eventHash` 摘要链，返回检查数量、最新事件哈希和断点事件；仅代表摘要链边界，不等于生产不可篡改审计平台 |
| 当前上下文接口 | `GET /api/security/current-context` | 返回操作人、角色、数据范围、敏感动作权限、菜单编码、菜单树和限制说明 |
| 授权导航过滤 | 前端 `App` 读取登录会话 `menuCodes/menuTree` | 登录后侧栏按角色可见模块收敛；未登录或请求头兜底仍展示评审全量导航 |
| Authorization | `Bearer <token>` | M3.63 优先认证来源 |
| 操作人请求头 | `X-Zhubao-Operator` | 当前为评审兜底，后续应仅在测试环境保留 |
| 角色请求头 | `X-Zhubao-Role` | 请求头兜底驱动敏感 POST 守卫和前端展示 |
| 数据范围请求头 | `X-Zhubao-Data-Scope` | 请求头兜底会驱动业务工作台 GET 首版过滤，但完整组织树和客户授权表仍未完成 |
| 默认角色 | `ADMIN` | 仅为兼容评审脚本和自动化测试；生产环境不得使用匿名管理员 |
| 当前限制 | 账号仓储、PBKDF2 密码哈希、失败锁定、启停/解锁、密码策略边界、密码过期检测、登录态自助改密、认证审计摘要链、账号管理审批摘要、内存 token、后端菜单树、按钮权限编码、登录审计、前端授权导航过滤和业务工作台 GET 首版数据范围过滤已接入；默认 seed 仍为评审账号，尚无生产账号前置审批、完整 IAM、SSO/JWT、生产菜单持久化、组织客户授权表和生产不可篡改审计 | 必须在试点上线前继续接入 |

构型要求：

- `current-context` 接口只读，不允许通过该接口修改角色、权限或数据范围。
- 前端必须在配置基线页展示限制说明，避免把评审 seed 账号、请求头权限、M3.86 导航过滤、M3.87 密码哈希边界、M3.88 失败锁定边界、M3.89 启停/解锁边界、M3.90 密码策略边界、M3.91 密码过期检测边界、M3.92 自助改密边界、M3.96 数据范围过滤边界或 M3.97 账号审批摘要边界误认为生产 IAM。
- 后续接入 RuoYi-Vue 或其他权限基座时，应将角色、菜单、按钮、数据范围和审计日志迁移到正式权限模型。
- 所有敏感操作仍必须由后端 `PermissionGuard` 校验，不能只靠前端隐藏按钮。
- 演示 token 只允许作为 M3 试点/评审能力，不进入生产验收基线。
