**文档版本**：V1.8
**更新日期**：2026-07-07  
**来源文件**：

- `入库登记表.xlsx`
- `出货登记表.xlsx`

## 1. 复核结论

这 4 张现场登记表验证了当前项目的大流程方向基本正确：业务不是单纯办公审批系统，而是围绕“收货签收 - 拆包称重 - 工序报工 - 交单审核 - 质检/返工 - 成品出库 - 追溯”的现场闭环。

本轮复核后的判断：

- 工序层面：`抛光` 已作为人工工序存在；`雕刻` 已进入配置基线、前端样例、生产报工接口和独立设备产量落库链路，M3.79/M3.80 已补 `biz_machine_output_record` 及汇总入口。
- 字段层面：入库、出货、抛光日报、雕刻统计的主要字段已补入设计文档、字段字典、前端样例和业务操作命令；其中 `inboundDate`、`workDate`、`operatorSignatureName` 已补入接口命令。
- 实现层面：当前真实业务接口会把现场字段写入库存台账备注作为追溯证据；这能支撑一期评审和闭环验证，但还不是最终结构化业务表。
- 后续重点：不要把 4 张 Excel 原样照搬成 4 张孤立业务表，应吸收字段语义，沉淀到母单、报工、设备产量、出库和库存台账模型中。

本次追加复核结论：

- 2026-07-07 追加核对 4 张参考空白模板后确认：现有一期工序已覆盖 `收货/签收`、`拆包称重`、`雕刻`、`粗抛/精抛/返工抛光`、`终检入库`、`打包出货` 等现场动作；参考表没有提出新的生产工序，但强化了登记来源字段必须结构化的要求。
- 字段层面发现 1 个契约缺口：`入库登记表.xlsx` 的原始 `备注` 列已被后端预检解析为 `remark`，但未列入前后端登记表字段模板；M3.71 已补入 `REG-INBOUND` 字段字典，字段总数由 39 调整为 40。
- `抛光登记表` 的 `姓名`、`日期` 是表头级上下文，不是每一行都重复填写；系统录入或后续 Excel 导入时必须继承到每条工作项目明细。
- `抛光登记表` 一个工作表内包含 6 个重复日报块，每个块有 3 行可填工作项目明细；明细行即使未填写纸质 `序号`，只要存在工作项目、时间、完成情况、交单审核或备注，也应按原始行号进入预检。
- `雕刻登记表` 一个工作表内包含 6 个序号分组，每组 1-8 号机器逐行登记；空白的日期、客户、品类不能直接当作空值，应在本序号组内继承上下文并保留机器行号。
- 四张表的 `序号` 都只能作为纸质行号/日内批次号，不得作为业务主键；若后续做批量导入，必须额外保存 `sourceRegisterType`、`sourceRegisterLineNo`、`sourceRegisterSequence`、`sourceSheetName` 和 `importBatchNo` 作为审计来源。
- `数量` 字段不能只有数值，应明确 `quantityUnit`；入库、雕刻产量和出货数量默认可用 `件`，但宝石、链条、批量包装等场景需要配置为 `颗`、`条`、`批` 等单位。
- 抛光 `姓名`、雕刻 `操机签字`、出货 `经办人` 与系统登录操作人不是同一概念，必须分别保存为作业人/确认人/经办人快照。
- 现场纸质表的来源信息必须进入审计链：现已在入库、报工、出货命令中补入 `sourceRegisterType`、`sourceRegisterLineNo`、`sourceRegisterSequence`，并写入库存台账备注；M3.68 已新增 `sourceSheetName` 和雕刻 `machineLineNo` 预检字段，M3.70 已补齐抛光无序号明细解析和雕刻本组上下文口径，M3.71 已补齐入库 `备注 -> remark` 字段模板契约，M3.74 已将 `importBatchNo`、预检行、标准化字段 JSON 和消息 JSON 落结构化导入批次；M3.78 已新增显式入账命令并继续经库存台账服务落账；M3.79 已将雕刻设备产量落入 `biz_machine_output_record`，真实母单/出库单结构化表仍待推进。
- 出货登记表的 `快递` 是纸质合并栏，现已用 `paperExpressText` 保留原文，同时拆分为 `expressCompany` 和 `logisticsNo` 参与出货校验。
- 入库/出货空白模板行常带 `月 日` 占位符，预检时必须当作空白行跳过，不能误生成阻断业务行。
- 抛光表的 `日期` 在模板中可能是标签，真实日期写在标签右侧；预检需要识别标签后面的日期值。
- M3.73 再次对照 4 张参考表确认没有新增生产工序缺口；实际缺口是模板字段可见性不足：`sourceRegisterType` 和 `sourceRegisterLineNo` 已在命令和预检结果中存在，但未作为 4 类登记模板字段暴露。现已为入库、出货、抛光、雕刻模板各补 2 个审计字段，字段总数由 40 调整为 48。
- M3.74 已开放预检通过后的确认导入批次：保存 `register_import_batch/register_import_row`，保留行级原表行号、纸质序号、标准化字段和校验消息；该动作仍不直接写库存台账或业务单据。
- M3.75 重新读取微信来源的 4 张 Excel：`入库登记表.xlsx` 为 23 行 x 10 列，`出货登记表.xlsx` 为 22 行 x 8 列，`抛光登记表.xlsx` 为 48 行 x 7 列，`雕刻登记表.xlsx` 为 51 行 x 8 列。结论是没有新增工序和新增业务字段；本轮只校准字段命名，把入库表 `寄货人/姓名`、`收货人/姓名` 和雕刻派生字段 `机器编号行号` 写入模板契约与覆盖测试。
- M3.76 已在 `SA 样例库` 增加确认批次复核台，可查看最近确认批次、批次详情、行级标准化字段、警告消息和“待入账映射”状态；这解决了结构化批次确认后的人工复核入口，但业务单据自动入账仍待推进。
- M3.77 已补只读入账映射计划：系统可按已确认批次生成目标命令草稿、已映射字段、缺失字段和警告，帮助判断哪些行可入账、哪些行还缺母单/工单/客户/物料/仓库/称重/物流信息；该计划不生成业务单据，也不写库存台账。
- M3.78 已补显式入账命令：通过 posting plan 的批次行可由 `POST /posting-commands` 转换为既有业务命令并写库存台账；阻断行拒绝，警告行需显式 `allowWarnings`，已入账批次/行进入 `POSTED` 状态防重复。
- M3.79 已补雕刻设备产量独立对象：`REG-ENGRAVING` 显式入账会额外保存 `biz_machine_output_record`，记录机器编号、机器行号、操机签字、产量、批次号和库存台账号。
- M3.81 已补真实母单/出库单基础结构化持久化切片：入库和出库业务动作仍先经 `StockLedgerService` 写台账，成功后保存 `biz_mother_order/biz_mother_order_item` 与 `biz_outbound_order/biz_outbound_order_item` 快照，并提供只读查询接口；M3.82 已补登记表确认批次的行级复核补录入口，可补齐 posting plan 缺失字段并重新判断 READY/BLOCKED，但完整主数据自动匹配、批量复核、状态流转和追溯聚合仍需继续推进。

## 2. 原始表头实测

本节来自 2026-07-07 对 4 个 Excel 文件的直接读取结果。

| 来源表 | 原始标题 | 表头字段 |
|---|---|---|
| `入库登记表.xlsx` | 签收入库登记表 | 序号、入库日期、快递名称、快递单号、寄货人/姓名、收货人/姓名、拆箱签字、货品名称、数量、备注 |
| `出货登记表.xlsx` | 交货情况登记表 | 序号、日期、客户、交货类目、交货数量、快递、经办人、备注 |
| `抛光登记表.xlsx` | 工作项目记录单（日） | 姓名、日期、序号、工作项目、开始时间、完成时间、完成情况、交单审核、备注 |
| `雕刻登记表.xlsx` | 雕刻机统计单（日） | 序号、日期、客户、品类、机器编号、雕刻数量、操机签字、备注 |

### 2.1 原始模板结构复核

| 来源表 | 模板结构 | 预检处理要求 |
|---|---|---|
| `入库登记表.xlsx` | 单表头，20 行空白登记位，日期列预填 `月 日` 占位 | 只含序号和 `月 日` 的行必须视为空白模板行跳过 |
| `出货登记表.xlsx` | 单表头，20 行空白登记位，日期列预填 `月 日` 占位 | 只含序号和 `月 日` 的行必须视为空白模板行跳过 |
| `抛光登记表.xlsx` | 6 个重复的 `工作项目记录单（日）` 块，每块包含 `姓名/日期` 上下文行、表头行和 3 行明细位 | 解析器必须扫描全部日报块；`姓名/日期` 展开到每条明细；纸质 `序号` 可为空但 `sourceRegisterLineNo` 必须保留 |
| `雕刻登记表.xlsx` | 6 个序号分组，每组 8 行机器位；`序号`、`日期`、`操机签字` 为组内合并单元格，`客户/品类` 按组内上下文继承 | 解析器必须按 1-8 号机器行展开；进入新序号组后重置上下文，不能把上一组客户/品类串到下一组 |

### 2.2 本轮补齐字段

| 补齐字段 | 适用登记表 | 系统字段 | 原因 |
|---|---|---|---|
| 登记表类型 | 入库、出货、抛光、雕刻 | `sourceRegisterType` | 用于区分同一业务命令来自哪类现场登记表，支撑审计和问题回查 |
| 原表行号 | 入库、出货、抛光、雕刻 | `sourceRegisterLineNo` | 用于定位 Excel 原始行；抛光无纸质序号、雕刻按机器行展开时尤其关键 |
| 真实表头命名 | 入库、雕刻 | `senderName`、`receiverName`、`machineLineNo` | 入库表原始列是 `寄货人/姓名`、`收货人/姓名`；雕刻表同一 `机器编号` 列既承载设备编号，也承载 1-8 号机器位回表定位 |

现场含义补充：

- `序号` 是纸质表行号或日内批次号，不应作为系统业务主键。
- 纸质表中的 `日期` 常写成月日，系统必须统一成完整业务日期 `yyyy-MM-dd`。
- 纸质表空白行里的 `月 日`、`日期` 只是模板占位或标签，不是有效业务日期。
- `快递` 在出货表中只有一个格子，系统应拆成 `expressCompany` 和 `logisticsNo`，否则无法追溯物流单号。
- `操机签字` 与系统操作人不是同一概念：操作人是录入人，操机签字是设备产量确认人。
- 抛光表是按人、按日、按工作项目的日报，不是简单的工单最终完工数量。

## 3. 覆盖状态矩阵

状态口径：

- `已落接口`：真实业务命令已能接收字段。
- `已落样例`：前端/后端评审样例可展示字段。
- `已落设计`：领域模型和字段字典已有设计。
- `待落库`：还需要独立表或真实业务表持久化，不应只放备注。

| 现场内容 | 当前覆盖状态 | 结论 |
|---|---|---|
| 入库签收 | 已落设计、已落样例、已落接口；母单真实结构化持久化待推进 | 一期可通过 `ConfirmInboundCommand` + 库存台账追溯，后续需落到母单/入库签收表 |
| 出货登记 | 已落设计、已落接口；出库结构化持久化待推进 | `ShipFinishedStockCommand` 已覆盖交货日期、类目、数量、快递、物流单、经办人 |
| 抛光日报 | 已落设计、已落样例、已落接口；日报查询/统计待推进 | `ReportProductionCommand` 已补 `workDate`，能支撑按日统计口径 |
| 雕刻机统计 | 已落设计、已落样例、已落接口；M3.79 已补独立设备产量表和提交/查询接口 | `ReportProductionCommand` 已补 `operatorSignatureName`，`biz_machine_output_record` 可保存机器编号、机器行号、操机签字和台账号 |
| 工序模板 | 配置基线已包含雕刻、粗抛、精抛等 | 现场工序已覆盖，下一步要把模板从只读基线推进到可配置数据 |
| 追溯入口 | 快递单、母单、工单、机器编号、经办人均有设计口径 | 机器编号/经办人追溯需要结构化持久化后才算完整 |
| Excel/纸质登记来源审计 | 命令层、导入模板 API、Excel 上传预览 API、`sourceSheetName`、前端预检操作台、问题 CSV 下载、结构化导入批次、只读 posting plan、显式入账命令和雕刻设备产量落库已补 | 入账已通过业务服务写库存台账；后续需补真实母单/出库单结构化表、机器档案匹配和签名附件 |
| 数量单位 | 领域模型已有 `unit`，真实业务命令已补 `quantityUnit`；结构化持久化和样例展示需继续推进 | `quantity` 不应长期裸存；入库、报工、雕刻产量、出货均应带单位 |

## 5. 工序补齐结论

一期工序模板至少应包含：

| 工序/动作 | 当前状态 | 处理方式 |
|---|---|---|
| 收货/签收 | 已作为入库动作覆盖 | 不计工资，不生成生产工序 |
| 拆包称重 | 已作为来料节点覆盖 | 需要拆箱签字、寄收件人、快递、称重和视频证据 |
| 雕刻 | 已纳入配置基线、报工接口和设备产量独立落库 | 后续重点是机器档案匹配、签名附件和更完整的产能报表 |
| 粗抛/精抛 | 已纳入工序模板 | 必须记录工作项目、日报日期、开始/完成时间和交单审核 |
| 镶石/焊接/打磨/清洗 | 已作为通用工序处理 | 继续按工序报工、称重交接和质检规则处理 |
| 终检入库 | 已覆盖 | 终检通过后转成品库存 |
| 打包出货 | 已落接口 | 需要交货类目、经办人、快递公司、物流单号和出货证据 |

## 6. 建模原则

不建议把 Excel 原表照搬成业务表。Excel 是现场记录习惯，系统模型应该吸收它的证据和责任字段：

- 入库登记字段进入 `biz_mother_order` 或 `biz_inbound_receipt`。
- 抛光登记字段进入 `biz_work_report`，并提供日报查询视图。
- 雕刻统计字段进入 `biz_machine_output_record`，可选关联工单、工序和报工。
- 出货登记字段进入 `biz_outbound_order` / 出库命令 / 库存台账。
- `序号` 只用于显示排序；业务主键必须使用系统编码。
- 现场签字一期保存姓名快照，二期再升级为签名图片或电子签。
- 表头/分组级字段必须在录入/导入时展开到明细行：抛光表的姓名、日期，雕刻表的日期、客户、品类都属于该类字段；雕刻进入新序号组后必须重置上下文。
- 数量必须拆成数值和单位；重量必须拆成数值和单位；前端展示值可以合并，但后端持久化和计算不能只保存字符串。
- 纸质表来源信息不参与业务状态机，但要作为审计字段保存，支撑导入问题回查。

## 8. 验收用例补充

1. 入库登记：录入入库日期、快递名称、快递单号、寄货人、收货人、拆箱签字、货品名称和数量后，系统生成库存台账，追溯链能看到这些字段。
2. 抛光日报：操作工选择抛光工作项目，填写日报日期、开始/完成时间、完成情况，提交后进入交单审核。
3. 雕刻统计：同一客户同一天可按 1-8 号机器录入雕刻数量，保存机器编号、品类、操机签字，并能按机器编号统计产能。
4. 出货登记：选择客户和交货类目，录入交货数量、快递公司、物流单号、经办人后确认出货，库存台账转为已发货。
5. 追溯查询：按快递单号、母单、工单、机器编号或经办人查询时，能关联到入库、工序、设备产量、出货和证据链。
