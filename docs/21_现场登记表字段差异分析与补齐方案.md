# 现场登记表字段差异分析与补齐方案

**文档版本**：V1.2
**更新日期**：2026-07-07  
**来源文件**：

- `入库登记表.xlsx`
- `出货登记表.xlsx`
- `抛光登记表.xlsx`
- `雕刻登记表.xlsx`

---

## 1. 复核结论

这 4 张现场登记表验证了当前项目的大流程方向基本正确：业务不是单纯办公审批系统，而是围绕“收货签收 - 拆包称重 - 工序报工 - 交单审核 - 质检/返工 - 成品出库 - 追溯”的现场闭环。

本轮复核后的判断：

- 工序层面：`抛光` 已作为人工工序存在；`雕刻` 已进入配置基线、前端样例和生产报工接口，但独立的设备产量表/接口仍未落库实现。
- 字段层面：入库、出货、抛光日报、雕刻统计的主要字段已补入设计文档、字段字典、前端样例和业务操作命令；其中 `inboundDate`、`workDate`、`operatorSignatureName` 已补入接口命令。
- 实现层面：当前真实业务接口会把现场字段写入库存台账备注作为追溯证据；这能支撑一期评审和闭环验证，但还不是最终结构化业务表。
- 后续重点：不要把 4 张 Excel 原样照搬成 4 张孤立业务表，应吸收字段语义，沉淀到母单、报工、设备产量、出库和库存台账模型中。

本次追加复核结论：

- `抛光登记表` 的 `姓名`、`日期` 是表头级上下文，不是每一行都重复填写；系统录入或后续 Excel 导入时必须继承到每条工作项目明细。
- `雕刻登记表` 存在同一客户/品类下按 1-8 号机器逐行登记的习惯，空白的日期、客户、品类不能直接当作空值，应继承上一组上下文并保留机器行号。
- 四张表的 `序号` 都只能作为纸质行号/日内批次号，不得作为业务主键；若后续做批量导入，必须额外保存 `sourceRegisterType`、`sourceRegisterLineNo`、`sourceRegisterSequence`、`sourceSheetName` 和 `importBatchNo` 作为审计来源。
- `数量` 字段不能只有数值，应明确 `quantityUnit`；入库、雕刻产量和出货数量默认可用 `件`，但宝石、链条、批量包装等场景需要配置为 `颗`、`条`、`批` 等单位。
- 抛光 `姓名`、雕刻 `操机签字`、出货 `经办人` 与系统登录操作人不是同一概念，必须分别保存为作业人/确认人/经办人快照。
- 现场纸质表的来源信息必须进入审计链：现已在入库、报工、出货命令中补入 `sourceRegisterType`、`sourceRegisterLineNo`、`sourceRegisterSequence`，并写入库存台账备注；M3.66 已新增 Excel 上传预览 API，可解析 4 类登记表并输出阻断/警告行；M3.67 已补前端预检操作台，确认导入和结构化导入批次表仍待推进。
- 出货登记表的 `快递` 是纸质合并栏，现已用 `paperExpressText` 保留原文，同时拆分为 `expressCompany` 和 `logisticsNo` 参与出货校验。

## 2. 原始表头实测

本节来自 2026-07-07 对 4 个 Excel 文件的直接读取结果。

| 来源表 | 原始标题 | 表头字段 |
|---|---|---|
| `入库登记表.xlsx` | 签收入库登记表 | 序号、入库日期、快递名称、快递单号、寄货人姓名、收货人姓名、拆箱签字、货品名称、数量、备注 |
| `出货登记表.xlsx` | 交货情况登记表 | 序号、日期、客户、交货类目、交货数量、快递、经办人、备注 |
| `抛光登记表.xlsx` | 工作项目记录单（日） | 姓名、日期、序号、工作项目、开始时间、完成时间、完成情况、交单审核、备注 |
| `雕刻登记表.xlsx` | 雕刻机统计单（日） | 序号、日期、客户、品类、机器编号、雕刻数量、操机签字、备注 |

现场含义补充：

- `序号` 是纸质表行号或日内批次号，不应作为系统业务主键。
- 纸质表中的 `日期` 常写成月日，系统必须统一成完整业务日期 `yyyy-MM-dd`。
- `快递` 在出货表中只有一个格子，系统应拆成 `expressCompany` 和 `logisticsNo`，否则无法追溯物流单号。
- `操机签字` 与系统操作人不是同一概念：操作人是录入人，操机签字是设备产量确认人。
- 抛光表是按人、按日、按工作项目的日报，不是简单的工单最终完工数量。

## 3. 覆盖状态矩阵

状态口径：

- `已落接口`：真实业务命令已能接收字段。
- `已落样例`：前端/后端评审样例可展示字段。
- `已落设计`：领域模型和字段字典已有设计。
- `待落库`：还需要独立表或真实业务表持久化，不应只放备注。

| 现场内容 | 当前覆盖状态 | 结论 |
|---|---|---|
| 入库签收 | 已落设计、已落样例、已落接口；母单真实结构化持久化待推进 | 一期可通过 `ConfirmInboundCommand` + 库存台账追溯，后续需落到母单/入库签收表 |
| 出货登记 | 已落设计、已落接口；出库结构化持久化待推进 | `ShipFinishedStockCommand` 已覆盖交货日期、类目、数量、快递、物流单、经办人 |
| 抛光日报 | 已落设计、已落样例、已落接口；日报查询/统计待推进 | `ReportProductionCommand` 已补 `workDate`，能支撑按日统计口径 |
| 雕刻机统计 | 已落设计、已落样例、已落接口；独立设备产量表和提交接口待开发 | `ReportProductionCommand` 已补 `operatorSignatureName`，但 `biz_machine_output_record` 仍是设计项 |
| 工序模板 | 配置基线已包含雕刻、粗抛、精抛等 | 现场工序已覆盖，下一步要把模板从只读基线推进到可配置数据 |
| 追溯入口 | 快递单、母单、工单、机器编号、经办人均有设计口径 | 机器编号/经办人追溯需要结构化持久化后才算完整 |
| Excel/纸质登记来源审计 | 命令层、导入模板 API、Excel 上传预览 API 和前端预检操作台已补，结构化导入批次待推进 | 确认导入前仍需 `sourceSheetName/importBatchNo`，避免无法追溯原表行和导入批次 |
| 数量单位 | 领域模型已有 `unit`，真实业务命令已补 `quantityUnit`；结构化持久化和样例展示需继续推进 | `quantity` 不应长期裸存；入库、报工、雕刻产量、出货均应带单位 |

## 5. 工序补齐结论

一期工序模板至少应包含：

| 工序/动作 | 当前状态 | 处理方式 |
|---|---|---|
| 收货/签收 | 已作为入库动作覆盖 | 不计工资，不生成生产工序 |
| 拆包称重 | 已作为来料节点覆盖 | 需要拆箱签字、寄收件人、快递、称重和视频证据 |
| 雕刻 | 已纳入配置基线和报工接口 | 设备产量独立落库仍是 P0/P1 开发项 |
| 粗抛/精抛 | 已纳入工序模板 | 必须记录工作项目、日报日期、开始/完成时间和交单审核 |
| 镶石/焊接/打磨/清洗 | 已作为通用工序处理 | 继续按工序报工、称重交接和质检规则处理 |
| 终检入库 | 已覆盖 | 终检通过后转成品库存 |
| 打包出货 | 已落接口 | 需要交货类目、经办人、快递公司、物流单号和出货证据 |

## 6. 建模原则

不建议把 Excel 原表照搬成业务表。Excel 是现场记录习惯，系统模型应该吸收它的证据和责任字段：

- 入库登记字段进入 `biz_mother_order` 或 `biz_inbound_receipt`。
- 抛光登记字段进入 `biz_work_report`，并提供日报查询视图。
- 雕刻统计字段进入 `biz_machine_output_record`，可选关联工单、工序和报工。
- 出货登记字段进入 `biz_outbound_order` / 出库命令 / 库存台账。
- `序号` 只用于显示排序；业务主键必须使用系统编码。
- 现场签字一期保存姓名快照，二期再升级为签名图片或电子签。
- 表头级字段必须在录入/导入时展开到明细行：抛光表的姓名、日期，雕刻表的日期、客户、品类都属于该类字段。
- 数量必须拆成数值和单位；重量必须拆成数值和单位；前端展示值可以合并，但后端持久化和计算不能只保存字符串。
- 纸质表来源信息不参与业务状态机，但要作为审计字段保存，支撑导入问题回查。

## 8. 验收用例补充

1. 入库登记：录入入库日期、快递名称、快递单号、寄货人、收货人、拆箱签字、货品名称和数量后，系统生成库存台账，追溯链能看到这些字段。
2. 抛光日报：操作工选择抛光工作项目，填写日报日期、开始/完成时间、完成情况，提交后进入交单审核。
3. 雕刻统计：同一客户同一天可按 1-8 号机器录入雕刻数量，保存机器编号、品类、操机签字，并能按机器编号统计产能。
4. 出货登记：选择客户和交货类目，录入交货数量、快递公司、物流单号、经办人后确认出货，库存台账转为已发货。
5. 追溯查询：按快递单号、母单、工单、机器编号或经办人查询时，能关联到入库、工序、设备产量、出货和证据链。
