# 安卓 APP 与集中标签打印开发文档

**状态：2026-10-14 代码已落地一部分，现场验收未完成。** 本文仍是安卓入口、集中打印和改单追溯的设计基准。仓库里已有 `android-app/`、`print-agent/`、备料、工序百分比、改单版本和打印任务；本机已重建指向腾讯云测试地址的 debug APK，网页扫码继续使用应用内实时取景，拍照与录像入口已在本地代码接通。新版网页尚未部署到测试服务器，正式签名 APK、目标手机作业和佳博出纸仍未验收。现行事实以[项目核心](./00_项目核心.md)为准。改单、财务确认和全链追溯的业务规则见[订单变更、换标、计费与全链路追溯设计](./订单变更与全链路追溯设计.md)。

## 1. 目标与范围

一期面向厂内安卓手机，采用内部签名 APK 分发，正常作业始终联网。手机端按现有账号权限覆盖当前 16 个页面的功能，收货、岗位报工、质检和发货保留现场快捷入口；新增可见订单的工序进度汇总与扫码百分比报工、客户备料与库存分口径一览，以及订单中途改单、财务确认、换标和跨母子单追溯。打印时向 ERP 提交任务，由厂内一台保持开机的 Windows 电脑连接佳博标签机并自动出纸。云端 ERP 保存任务、权限和审计记录，厂内电脑主动通过 HTTPS 领取任务，不要求云服务器访问厂内局域网。

整体项目交付包括安卓容器、现有功能的手机布局与权限导航、工序进度汇总及扫码报工、客户备料收货与分批领用、公司自有生产物料的基础出入库及三类库存一览、ERP 系统级改单与工序路线版本、财务逐次确认、标签版本与订单总时间线、相机与文件选择适配、可安装升级的签名 APK、打印任务及状态页面、电脑端打印程序和真实设备验收。桌面端应同样具备新增业务能力，安卓端复用同一服务端事实与权限。完整采购、完整成本会计与实物盘点另行设计；断网业务操作、iOS、应用商店上架、蓝牙手机直打、多个打印工位调度均不在一期范围。现有业务事务、幂等和现场验收阻断仍按[项目核心](./00_项目核心.md)处理；APP 包装不会自动解决这些问题。

| 标签版本与追溯 | 二维码只有 `JG|类型|单号`，旧新标签不能区分；补打先记申请日志再浏览器打印，缺补打历史查询。扫码、附件、工序交付按当前单号分散查询 | 新标签含稳定单据身份和版本／标签实例；旧版新码提示过期，存量旧码提示版本未知；打印任务与改单绑定，母单总时间线聚合各子单和证据 |
| 客户备料 | 正式收货会写入客户所有的 `RAW_WAITING` 余额，库存页可见“待加工”；但收货必须创建母单并填写加工要求、期限，尚无独立的“暂存备料”收货与领用 | 新增不绑定加工计划的客户备料批次、分批领用和专门一览 |

| 扫码与证据 | `ScanInput.vue` 使用网页相机与照片识别；`EvidenceCapture.vue` 使用系统拍摄、选文件和上传 | 真机处理相机权限、文件选择、照片和视频格式、上传与预览 |
| 标签 | 后端 `/api/label/*` 返回标签数据；`labelPrint.ts` 在当前浏览器调用 `window.print()` | 增加服务端任务与厂内打印程序；保留现有预览和必要的人工打印入口 |

| 服务端部署 | 云端 Nginx 通过 HTTPS 提供页面并代理同源 `/api` | 打印程序主动访问 HTTPS；任务持久化并纳入数据库备份 |

## 3. 技术路线与部署

一期采用小型 Android WebView 容器加载固定的 ERP HTTPS 地址。网页与 API 保持同源，业务功能仍由现有 Vue 页面和 Java 服务提供；网页更新随服务器部署生效，只有容器或 Android 权限逻辑变化时才重新发布 APK。容器只允许访问配置的 ERP 域名，其他外链交给系统浏览器，不开放任意网页的原生调用桥。

建议将 Android 工程置于 `android-app/`，厂内电脑程序置于 `print-agent/`，两者分别构建。测试与正式环境的 ERP 地址通过各自发布配置提供；工位凭据、APK 签名密钥和密码不写入源码。服务器部署新版网页时须保持对仍在使用的 APK 容器兼容，确需升级容器时在页面提示最低支持版本。

```text
安卓 APK ──HTTPS──> 云端 ERP ──数据库──> 打印任务
                                      ↑
厂内 Windows 打印程序 ──HTTPS 主动领取与回报──┘
          │
          └──Windows 驱动──> 佳博标签机（USB 或实际具备的网口）
```

若以后选择 Capacitor 标准工程，应把构建后的网页资源打入 APK，并另外处理 API 绝对地址、跨域、附件相对预览链接和网页更新。其配置项 `server.url` 的[官方说明](https://capacitorjs.com/docs/config)将远程地址定位于开发热更新，不作为本方案的生产入口。一期先通过真实安卓手机验证 WebView 路线，再固定最终容器实现。

厂内打印程序与云端保持出站连接，不开放电脑打印端口到公网。打印机若只有 USB，直接连接该电脑即可；若实际型号具备网口，仍可由这台电脑通过局域网驱动打印。佳博[官方 GP-9134T/GP-9135T 规格](https://www.gprinter.net/rzytm/493.html)列出前者标配 USB、串口、并口及选配 Wi-Fi，后者标配网口。用户所述“GT9134T”尚需以机身铭牌、背部接口和自检页核定，不据型号文字推断机器已有网口。

## 4. 安卓端设计

本节的工序百分比、客户备料、公司自有生产物料和改单等业务规则均属于 ERP 系统级改造，后端统一保存并供桌面网页与安卓端使用。以下同时记录手机操作方式与其所依赖的业务能力，不能将这些能力只实现于 APK 或 WebView 本地。

1. **连接与证书：**只加载预设 HTTPS 域名，提供断网、超时和服务不可用提示。当前云端使用自签证书；正式 APK 需让目标手机完整信任证书，优先使用域名与受信任证书，不通过忽略 SSL 错误继续访问。Android [WebView 文档](https://developer.android.com/reference/android/webkit/WebViewClient)要求证书错误时中止连接。
2. **扫码与上传：**在 WebView 中处理网页相机申请和 Android 运行时相机权限；处理 `<input type="file">` 的拍照、相册、文件选择与返回结果。按现有 JPEG、PNG、MP4、WebM 和大小限制，在目标手机测试真实文件类型、上传、签名预览链接与外部窗口。相关回调见 Android [WebChromeClient 文档](https://developer.android.com/reference/android/webkit/WebChromeClient)。
3. **页面行为：**处理系统返回键、键盘遮挡、状态栏与安全区域、重新进入应用、登录失效、附件预览和允许的外部链接。保持后端角色、客户范围及工序权限判定，不在 APK 内另设业务权限。
4. **打印交互：**手机上保留标签预览；用户明确点击“提交到打印工位”后创建任务，显示任务编号和状态。收货保存不自动出纸；重复点击和网络重试使用同一个 `requestId`。状态为“已送入电脑打印队列”时不显示“已出纸”。
5. **安装更新：**确定固定包名、应用名称、图标和 `versionCode`；使用专用发布密钥签名，安全备份密钥和密码。内部提供受控 APK 下载及版本说明，验证同包名、同签名的新版本可覆盖安装。Android [签名规则](https://developer.android.com/studio/publish/app-signing)要求 APK 安装和更新均带数字签名。

### 4.1 全功能导航与工序进度

手机端提供“工作台、现场作业、审批、全部功能”入口；“全部功能”覆盖当前 `App.vue` 的 16 个页面，按服务端菜单、角色、客户和工序权限隐藏或拒绝不可用操作。复杂表格改为可搜索、可筛选、可打开详情的手机列表；保留原业务字段与确认步骤，不因屏幕较小省略权限、证据或复核环节。

“订单加工进度”默认汇总**当前账号有权查看的全部订单**，不只列在制订单；支持客户／订单号、当前工序、进度、期限筛选和分页，显示母单、子单、客户、当前工序、正式业务状态、该工序百分比、最后报工人和时间。拆分母单按子单分组展示；未确认工序权重前，不把多个子单／多道工序的百分比平均成一个貌似精确的母单总百分比。无权查看的订单不能通过列表、计数、搜索或单号直查泄漏。

加工人员从“现场作业→进度报工”或进度详情进入相机扫码。服务端识别母单／子单；母单已拆分时必须选择具体子单，不猜第一条。页面显示单号、客户、当前工序、已有进度与生产要求，操作人选择**未开始（0%）、30%、60%、90%、已完成（100%）**，核对后明确提交。用户已确认这些百分比表示**当前工序进度**，而不是整个订单完成比例。可选填写简短说明，提交成功后刷新列表与该订单的进度历史。

新百分比记录属于“进度报工”，与现有 `ProgressNoteForm` 的文字过程说明及 `ProductionPanel` 的正式工序交付是不同业务事实。选择“已完成”只表示该工序人工报告达到 100%，**不自动交付工序、不自动通过质检、不写库存或工资**；正式交付仍走现有核对和提交链路。界面同时展示“工序进度 100%”与“待正式交付”，避免把两者混为一谈。权限沿用生产报工角色及账号的客户／工序授权，服务端重新校验规范单据身份与当前工序，不信任客户端传入的操作人或客户。

拟在现有业务领域增加独立的工序进度查询和写入接口，返回可见订单列表、工序里程碑和历史；写入包含目标单据、服务端确定的工序、里程碑、说明、稳定 `requestId` 与预期版本。记录追加保存操作人、时间、旧值和新值；同一请求重试只产生一次记录，并发提交必须拒绝陈旧版本。正常报工只允许维持或向前推进；误报回退由有权人员填写原因后更正，保留原历史。接口落地时再同步更新[API 契约](./16_字段字典与API契约.md)，数据库仅追加新迁移，不修改已发布脚本。

### 4.2 客户备料与厂内库存

客户可能一次寄来大量金料、配件或半成品，暂时没有加工要求和完成期限。新增“客户备料收货”独立于加工母单：记录客户及所有权、物料与规格、批次、数量及单位、重量、库位、收货时间、快递和证据；收货后形成客户所有的可用备料余额，不自动生成生产工单。按同一客户、物料、单位和库位汇总可用、已领用与冻结数量，并可展开批次、库龄和收发台账。备料可分多次、按数量及重量领用到不同加工母单；领用与建单须在同一工作单元核对余额并追加台账，失败回滚，同一 `requestId` 不重复扣减。撤销或退回须产生反向台账，不直接改余额。

当前 `StockDimension` 要求母单号，通用库存转移也禁止改变母单维度，不能把独立备料硬塞成一个伪加工母单，或直接放宽所有转移规则。实现时需为备料来源批次与加工目标建立明确关联，并只允许受控的备料领用跨来源转入目标单；保留客户权属和物料追溯，禁止跨客户领用。历史母单 `RAW_WAITING` 仍按现有路径处理，不因新增备料类型自动改账。

库存页和安卓端分别提供三个口径：

| 视图 | 展示内容 | 口径约束 |
|---|---|---|
| 客户备料 | 当前账号有权查看的客户备料批次、物料、可用／已领用／冻结余额、库位与库龄 | 与已经绑定加工单的“待加工”余额分开，领用后不重复计为可用备料 |
| 厂内实物 | 按仓库、物料、权属和状态列出厂内保管的客户料、在制、成品及公司自有物料 | 排除已发货／已出库余额；显示**台账结余**与最后变动时间，不同物料和计量单位不强行合成一个数量 |
| 公司自有 | 公司购入的金料、配件等生产物料及现有财务耗材 | 生产物料新增基础入库、领用、退回台账；耗材暂按现有财务余额单列，核对来源后再决定是否统一，绝不与客户料混算为公司资产 |

库存查询由服务端按角色和客户范围裁剪，统计数、导出和单号直查同样执行权限。公司自有库存仅向获授权的仓库、财务或管理岗位展示；客户范围账号不能借厂内总览看见其他客户备料。页面不把账面余额称为“实盘库存”；若需账实差异、盘盈盘亏和审批调整，应另加盘点流程。公司自有生产物料的入库、领用和退回采用与客户备料相同的幂等、并发与台账要求，但始终使用 `OwnerType.COMPANY`。接口与追加迁移在实施时同步写入[API 契约](./16_字段字典与API契约.md)。

### 4.3 系统改单能力的安卓入口

客户中途改单、工序路线与执行轮次、财务确认、标签版本、母单总时间线是 ERP 整体业务能力，统一由服务端维护，桌面网页与安卓端使用同一套单据、权限和接口。完整规则见[订单变更、换标、计费与全链路追溯设计](./订单变更与全链路追溯设计.md)。本节只规定安卓交互，不另存手机端订单或财务副本。

手机在“订单加工进度”详情提供“改单记录、工序路线、费用、证据、标签”入口；有权人员可扫码定位母单／子单并提交客户变更申请和照片视频，财务在同一系统的待办中逐次确认，组长在生效后核对现场并确认换贴。上述操作在桌面端也应完整可用。费用页只向具备财务权限的账号展示客户单价、工人工费与调整记录；生产人员可见与作业有关的改单结论，但不能因此看到无权金额。

扫码新版旧标签时提示过期并引导查看当前要求；现行无版本的 `JG|类型|单号` 只能提示“版本未知”。关键报工、质检和出库按服务端当前版本校验，旧标签例外放行须有权限及原因。母单已拆分时仍要求选择子单。换新版和同版补打在手机上分别发起，显示打印任务、出纸核实和实物换贴状态，不把提交任务显示成已换贴。

## 5. 服务端打印任务设计

在现有 `label` 领域内保持 `domain / app / infra / web` 分层。任务在服务端根据业务单号和标签模板生成，保存不可变的标签内容快照、业务版本／标签实例、关联改单号、模板与尺寸、份数、提交人、目标工位和 `requestId`；客户端不得上传任意 HTML 或原始打印指令。创建时沿用 `LABEL_PRINT` 权限，并再次验证所打印业务对象的可见范围。代理使用独立的工位凭据，只能领取其绑定工位的任务，不复用管理员账号。

拟新增接口如下；字段与返回码须在实现时同步写入[API 契约](./16_字段字典与API契约.md)。

| 接口 | 用途与关键输入 |
|---|---|
| `POST /api/label/print-jobs` | 创建任务；标签类型、业务单号、当前业务版本、改单号或同版补打原因、模板、工位、`requestId`；同一请求重试返回同一任务 |
| `GET /api/label/print-jobs/{jobId}` | 有权限的提交人或管理人员查询状态、失败原因及时间 |
| `POST /api/label/print-jobs/{jobId}/retry` | 对已送队列、失败或待核实任务显式补打；要求原因，防止无声重复出纸 |
| `POST /api/label/agents/jobs/claim` | 工位代理按授权领取一条任务，服务端原子加租约 |
| `POST /api/label/agents/jobs/{jobId}/report` | 代理带领取令牌上报送入系统打印队列或明确的发送前失败 |
| `POST /api/label/agents/heartbeat` | 上报代理版本、在线时间和工位状态，不携带业务账号密码 |

任务状态拟为 `PENDING`（待领取）、`LEASED`（代理已领取）、`SPOOLED`（已交给 Windows 打印队列）、`FAILED`（确定未送入打印队列）、`UNCERTAIN`（提交或回报中断，是否出纸不明）、`CANCELED`。`SPOOLED` 不等于物理出纸；没有打印机可靠回执前，系统不得自动声称“打印成功”。租约到期但可能已经发送的任务进入 `UNCERTAIN`，由人员核对纸张后再决定补打，避免自动重试产生双份标签。

接口中的普通网络重试复用原 `requestId` 和任务号。人工确认需要重打时，`retry` 创建关联原任务的新打印任务，使用新的 `requestId`，记录原因、操作人和原任务号；不重置原任务历史。改单换新版须从已生效改单另建任务，不调用同版 `retry` 冒充换版。母单和子工单复用现有结构化标签生成；出货、返工现有通用生成链路须核对正式业务单据与模板来源后在同次实现中接入，不能把客户端自填字段当作已核实的业务事实。

任务提交、唯一 `requestId`、领取和状态变更需要事务及并发测试。持久化遵循项目的“本地内存默认、MySQL 下 JDBC 可切换”，数据库变更使用下一个可用的追加迁移版本，不修改 V1—V48。打印任务、补打原因、处理人和状态历史纳入同一数据库备份。既有 `/api/label/reprints` 与补打日志在改造时保持兼容，并将“已申请补打”与实际任务处理结果分开显示。

## 6. 厂内打印程序

电脑端程序开机自启，只连接指定 ERP HTTPS 地址，持有可撤销、可轮换的工位凭据；定时领取任务，在本机把目标打印机固定映射到 Windows 打印队列，并回报任务状态。电脑停机或断网时，任务保留在服务器。程序记录任务号、驱动返回信息和错误日志，不记录完整登录令牌或无关客户数据。

第一步须使用实机确定输出方式：优先验证现有标签版式经 Windows 驱动打印的实际尺寸、二维码可扫性和静默出纸；若驱动无法可靠控制纸张或份数，再评估按佳博 TSPL 指令重绘。当前模板默认 60×40 mm、203 dpi，而佳博官网所列 GP-9134T 为 300 dpi；实际模板、纸张、间隙、方向和驱动设置要以现场出纸校准，不直接把默认 DPI 当作设备事实。

### 7.1 安卓 debug 试装

1. 在未入库的 `android-app/local.properties` 配置本机 SDK 和真实 HTTPS `erp.baseUrl`。当前工作机已设为腾讯云测试地址；其他机器须自行配置，不把登录凭据写入该文件。
2. 使用 JDK 21 在 `android-app/` 执行 `./gradlew.bat :app:testDebugUnitTest` 和 `./gradlew.bat :app:assembleDebug`。产物为 `app/build/outputs/apk/debug/app-debug.apk`；debug 签名只供试装，不可充当正式发布密钥。
3. 当前服务使用自签证书。先从服务器受控取得正在使用的 **`server.crt` 公钥证书**，与服务器端 SHA-256 指纹及 `IP:106.55.226.166` SAN 核对，再在专用测试手机中安装并信任。不要传输 `server.key`，不要通过忽略证书错误继续访问。debug 包允许手机用户证书，正式包仅信任系统证书。
4. 手机连接可访问测试服务器的网络，安装 APK；若用 `adb install -r app/build/outputs/apk/debug/app-debug.apk`，先开启 USB 调试并确认 `adb devices` 能看到设备。依次核验登录、应用内实时扫码、拍照、录像、上传、关联、预览、拒绝授权后的重试与返回页面后的相机释放。当前视频接受 MP4/WebM 且不超过 50MB；系统相机的时长和大小限制只是请求提示，仍以实际文件校验为准。
5. APK 加载服务器上的网页。前端页面修改必须先按测试环境部署流程发布，真机才能看到新增的“录视频留证”入口和扫码恢复提示；只重打 APK 不会更新网页。

## 9. 验收清单

1. 至少两台目标安卓手机安装同一签名 APK，正常登录、退出、更新覆盖安装；后端按原角色和数据范围拒绝越权访问。
2. 实机完成收货、报工、质检和发货的扫码入口检查；拍照、相册、视频上传与签名链接回看能在 APK 中打开。首次拒绝相机权限和重新授权均有明确提示。
3. 用管理员、加工人员和不同客户范围账号核对全部功能菜单及进度列表：有权订单可按客户／单号／工序筛选，无权订单不出现在列表和统计中，扫码直查也被拒绝。拆分母单必须选择子单。
4. 加工人员扫码后可提交 0%、30%、60%、90%、100% 的当前工序进度；历史保留操作人和时间，列表刷新；同一 `requestId` 的重试只记录一次，陈旧版本不能覆盖新进度，普通账号不能无理由回退。报到 100% 后正式工序交付仍保持独立待办。
5. 不填写加工要求和期限也能将客户来料登记为备料；从同一批备料分次领用至不同加工单后，可用余额准确减少，母单和来源批次可互查。并发领用不透支，超时重试不重复扣减；不同客户之间不可领用。
6. 客户备料、厂内实物、公司自有三个视图分别核对台账口径；客户料不进入公司资产统计，财务耗材不与公司生产物料重复计量。受限账号看不到其他客户批次、厂内总量或无权的公司自有库存。
7. 手机提交标签任务后可见编号与状态；同一 `requestId` 的超时重试只产生一条任务；无权限用户不能提交或读取他人任务。
8. 电脑正常领取并打印指定纸张；核对尺寸、方向、数量、文字和二维码。并发提交按任务顺序处理，不串单。
9. 电脑停机、断网、缺纸、服务端重启以及“可能出纸但未回报”均呈现正确状态；不确定任务不自动重复打印，人工补打必须填写原因并留下记录。
10. 发布密钥受控备份，APK 版本号递增；数据库备份包含打印任务、工序进度历史、备料与库存台账，恢复后不会把不确定任务当作未打印任务自动重放。
11. 客户在一张已拆分、部分工序完成的母单中途改要求：申请保留原／新内容和证据；财务逐次确认价格及工费影响后才生效；原工序交付与库存不被覆盖，新执行轮次仍可从母单和原子单互查。同一 `requestId` 重试不重复生效，并发改同一工单有版本冲突提示。
12. 同一客户的雕刻、镶嵌、抛光价目可在一次协议中分别维护；改单详情可见原／新客户收费与工人工费。已入账行原价不变，财务可按确认决定关联原行做红字和差额，重新生成月账不会悄悄重复计费；已确认工资调整另留记录。
13. 改单换新版和丢失补打同版各有独立原因、标签版本、打印任务与换贴记录。新版旧码提示过期，存量 `JG|类型|单号` 仅提示版本未知；扫码旧码仍能找到原母子单，但关键业务不能误按旧需求提交。打印队列状态不冒充物理出纸。
14. 从有权限母单可见所有获授权子单及执行轮次的完整时间线，含经手工序、前后修改、财务确认、标签、照片视频与来源原单；受限账号经列表、计数、附件预览和直接 URL 均看不到无权客户与金额。备份恢复后时间线和证据链接仍可用。

实施前需确认机器铭牌及自检页、标签纸实际规格、固定电脑的 Windows 版本、目标安卓机型与系统版本，以及正式 HTTPS 域名。上述信息影响驱动适配和测试范围，不改变一期的业务架构。
