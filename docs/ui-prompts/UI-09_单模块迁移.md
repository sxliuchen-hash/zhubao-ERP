# UI-09：每次迁移一个剩余模块

前置：UI-03 模板已建立；建议 UI-08 完成后逐模块推进。

用户每次指定一个模块，例如「执行 UI-09，本轮模块为库存」。没有指定时从 docs/27 的顺序选择第一个实际未完成模块，并在开头说明选择。本轮只能完成这个模块，不同时改全部工作台。

## 范围

读取共同基调、UI-03 已实施模板、目标模块页面／API／测试及实际共享组件。允许迁移目标模块和必要共享表现；不改业务命令、核算、权限或其他模块的交互流程。

## 实施

1. 采用统一页头、筛选、列表／详情、表单分区、状态和反馈组件；不再复制另一套布局与颜色。
2. 核心内容按业务优先级组织，长说明可展开，不让主动作埋在页面底部。
3. 电脑保持操作密度，手机改卡片列表与独立详情；已有复杂明细表可提供专用表格视图，但核心处理不依赖横滑。
4. 所有原有真实功能可到达、错误与无权限状态真实。不删掉不好看的功能，也不保留空的演示功能充数。
5. 财务登记表单作为该轮目标时，替换固定采购／领用／资产参数及日期为标准表单，保留已有命令与校验。不能把财务看板又改回文字堆叠。
6. 标签管理作为目标时，应用界面可统一，实际标签继续黑白、毫米纸张和既有编码。其他模块改版不能影响打印。
7. 确认目标模块的旧样式无其他调用后再移除；不扩大为一次性全站 CSS 清理。

## 完成条件

覆盖该模块核心动作、列表选择、筛选、详情返回、无数据、加载失败、无权限和保存中状态。至少留 390／1440px 截图及 320px 溢出检查。全量基线通过后同步文档并单独提交。

在 docs/27 记录 UI-09 已迁移模块与仍未迁移模块。全部迁移完成才进入 UI-10；本轮完成后仍停止，不自动迁移下一个模块。
