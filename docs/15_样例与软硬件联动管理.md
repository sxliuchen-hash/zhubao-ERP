# 来料加工进销存与生产管理系统 样例与软硬件联动管理

**文档版本**：V1.0  
**更新日期**：2026-07-06  
**适用阶段**：M2 起长期维护  
**目标**：统一样例数据、演示脚本、验收证据、硬件兼容状态和失败兜底方案

## 1. 管理目标

项目不能只靠页面截图推进，必须用稳定样例和真实联动边界证明系统设计可落地。

本管理文档约束：

- 样例数据如何维护。
- 样例如何服务演示、测试和验收。
- 摄像头、NVR、标签打印、扫码、电子秤如何分阶段接入。
- 硬件失败时如何不阻塞业务。
- 文档、代码、测试和 Git 如何同步变更。

## 2. 样例库管理

### 2.1 样例类型

| 样例 | 目标 | 必备证据 |
|---|---|---|
| 客户来料主链路 | 验证订单、母单、拆包、工单、报工、质检、出库、追溯 | 母单标签、称重交接、拆包视频、库存台账 |
| 质检返工样例 | 验证返工只走一套工单状态机 | 缺陷照片、返工原因、返工工单、复检记录 |
| 超标损耗审批样例 | 验证损耗归因和工资试算快照 | 投入重量、产出重量、审批记录、试算结果 |
| 视频与标签兜底样例 | 验证硬件失败不阻塞主链路 | NVR 时间段、失败日志、人工上传文件、补打记录 |
| 页面评审样例 | 验证各角色页面是否贴近现场操作 | 队列、状态、异常、责任人、下一步动作 |

- 演示环境初始化数据。

当前 M2 前端样例覆盖：

- 来料：入库检查点、拆包称重、视频状态、标签补打、入库异常处置。
- 生产：工位负载、工单执行、称重交接、损耗阻断、工序模板。
- 质检：待处理质检、质检指标、损耗审批、返工路径。
- 库存：客户所有权余额、库存台账明细、追溯时间线、证据清单。
- PWA：现场任务、扫码解析、能力边界、离线草稿。
- 硬件：设备兼容矩阵、联动任务健康度、失败兜底。

前端加载策略：

- 页面优先调用 `/api/business/workspaces/*`。
- 后端未启动、接口失败或演示离线时，页面保留本地确定性样例兜底。
- DTO 到页面模型的映射集中在 [businessWorkspaceApi.ts](../frontend/src/services/businessWorkspaceApi.ts)。

### 2.3 维护原则

- 同一条样例必须能串起完整业务链路。
- 样例变更必须同步测试。
- 样例必须带负责人和当前状态。
- 样例不能只描述成功路径，必须覆盖异常、返工、损耗和硬件失败。
- 页面新增字段必须优先从集中样例数据读取，避免在组件里分散硬编码。

## 3. 软硬件联动管理

### 3.1 一期硬件边界

| 硬件 | 一期方案 | 失败兜底 |
|---|---|---|
| NVR/摄像头 | 按业务时间段半自动截取 | 截取失败后人工上传 MP4 |
| 标签打印机 | 浏览器打印或 Windows 驱动 | PDF 标签模板人工打印 |
| PC 扫码枪 | USB HID 键盘模式 | 手工录入编码并二次确认 |
| PWA 手机扫码 | BarcodeDetector，ZXing 兜底 | 手工输入工单码 |
| 电子秤 | 人工读数录入 | 拍照留证，二期再做接口采集 |

### 3.2 当前页面位置

### 3.3 联动任务原则

- 所有硬件调用都应产生任务记录。
- 任务记录包含目标设备、业务对象、执行结果、失败原因、下一步动作、责任人。
- 自动失败时必须给出人工兜底入口。
- 人工上传、补打标签、手工录入重量必须进入操作日志。

## 4. 验收要求

M2/M3 起每次验收必须至少覆盖：

1. 一个完整来料主链路样例。
2. 一个质检返工样例。
3. 一个超标损耗样例。
4. 一个视频截取失败人工上传样例。
5. 一个标签补打样例。
6. 一个 PWA 扫码失败手工输入样例。

---

## 5. 当前限制

- 设备状态仍为原型样例，尚未接真实硬件。
- 联动任务未落数据库。
- 视频、标签、电子秤仍未做现场 POC。
- M3 前必须完成硬件 POC 记录和真实 API 设计。
