## 1. 管理目标

项目不能只靠页面截图推进，必须用稳定样例和真实联动边界证明系统设计可落地。

本管理文档约束：

- 样例数据如何维护。
- 样例如何服务演示、测试和验收。
- 摄像头、NVR、标签打印、扫码、电子秤如何分阶段接入。
- 硬件失败时如何不阻塞业务。
- 文档、代码、测试和 Git 如何同步变更。

## 2. 样例库管理

### 2.1 样例类型

| 样例 | 目标 | 必备证据 |
|---|---|---|
| 客户来料主链路 | 验证订单、母单、拆包、工单、报工、质检、出库、追溯 | 母单标签、称重交接、拆包视频、库存台账 |
| 质检返工样例 | 验证返工只走一套工单状态机 | 缺陷照片、返工原因、返工工单、复检记录 |
| 超标损耗审批样例 | 验证损耗归因和工资试算快照 | 投入重量、产出重量、审批记录、试算结果 |
| 视频与标签兜底样例 | 验证硬件失败不阻塞主链路 | NVR 时间段、失败日志、人工上传文件、补打记录 |
| 页面评审样例 | 验证各角色页面是否贴近现场操作 | 队列、状态、异常、责任人、下一步动作 |

### 2.3 维护原则

- 同一条样例必须能串起完整业务链路。
- 样例变更必须同步测试。
- 样例必须带负责人和当前状态。
- 样例不能只描述成功路径，必须覆盖异常、返工、损耗和硬件失败。
- 页面新增字段必须优先从集中样例数据读取，避免在组件里分散硬编码。

## 3. 软硬件联动管理

### 3.1 一期硬件边界

| 硬件 | 一期方案 | 失败兜底 |

| NVR/摄像头 | 按业务时间段半自动截取 | 截取失败后人工上传 MP4 |

### 3.3 联动任务原则

- 所有硬件调用都应产生任务记录。
- 任务记录包含目标设备、业务对象、执行结果、失败原因、下一步动作、责任人。
- 自动失败时必须给出人工兜底入口。
- 人工上传、补打标签、手工录入重量必须进入操作日志。

### 3.4 现场 POC 记录

硬件是否能接入不能只写“支持”或“后续验证”，必须形成可追踪的 POC 记录。当前基线已新增：

- 后端接口：`GET /api/hardware/poc-records`。
- 证据关联接口：`GET /api/hardware/poc-evidence`。
- 前端入口：`软硬件联动 > 现场 POC 记录`。
- 合同表：`hw_poc_record`。
- M3.94 仓储边界：`HardwarePocRecordRepository` 支持 `memory` / `jdbc` 切换，本地默认 `zhubao.hardware.poc.repository=memory`，MySQL profile 默认 `ZHUBAO_HARDWARE_POC_REPOSITORY=jdbc`。
- M3.95 证据关联边界：按附件元数据 `businessType=硬件 POC` 和 `businessCode=POC 编码` 只读聚合证据包、附件编码、缺失数量和下一步动作。
- M3.103 协议样本边界：`GET /api/hardware/protocol-samples` 只读返回现场协议参数、样本载荷、采集方式、证据编码和下一步复测动作。
- M3.104 参数复核边界：`GET /api/hardware/protocol-reviews` 只读返回已确认参数、待复核参数、型号冻结状态、责任人、复核窗口、阻断项和下一步动作。
- M3.105 复测执行结果边界：`GET /api/hardware/protocol-executions` 只读返回复测执行状态、执行人、型号冻结状态、通过/未通过参数、证据状态、结果摘要和下一步动作。
- Seed 数据：`V19__m3_hardware_poc_record_seed.sql` 固化 NVR 视频、标签打印、PWA 弱光扫码和电子秤人工读数 4 条基线 POC 记录。

每条 POC 记录必须包含：

| 字段 | 说明 |
|---|---|
| POC 编码 | 唯一识别一次现场验证 |
| 设备编码 | 关联摄像头、标签打印机、扫码设备或电子秤 |
| 场景 | 业务动作，例如拆包视频、标签打印、弱光扫码、称重交接 |
| 验证窗口 | 现场验证的日期和时间段 |
| 结果 | 通过、有条件通过、阻断 |
| 证据 | 截图、视频、日志、照片或操作记录摘要 |
| 阻断项 | 账号权限、弱光、时间同步、驱动、网络等问题 |
| 责任人 | 当前跟进人 |
| 下一步 | 重试、兜底、二期验证或配置冻结动作 |

### 3.5 M3.30 软硬件作业台基线
