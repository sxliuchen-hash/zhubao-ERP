# A5 客户权限调查

> 2026-10-20。基线提交 `4447d79`。本文件只记录客户改名、旧名称别称、授权歧义，以及母子单、附件、打印查询的同一权限边界。测试服仍是 `cloud-a4-1e783e4-20261019`，运行库 V63。本地 V64 及之后的 A4 增量尚未发布，不能写成已部署。跨材质子单、拆单、库存过账和财务不在本批。

## 1. 当前链路

| 环节 | 入口 | 现行判断 |
|---|---|---|
| 改名与别称 | 客户档案保存 | 稳定客户编号不变。名称变化时把原名称并入别称，不覆盖已保存单据上的客户名称快照。 |
| 历史名称授权 | 登录会话解析 | 授权客户范围先取授权表，没有授权行时用账号上的客户范围。名称、客户编码或别称只能在唯一对应一个档案时换成客户编号；对上多家或对不上时丢掉该值，不另外授权。纯数字编号保持原值。`客户#编号` 目前对不上名称规则，会被丢掉。 |
| 母子单列表 | 正式工作台、进度 | 工作台空的授权客户范围看不到单据。进度把空范围当成不限制，授权客户范围在歧义名称被丢掉后会看到全部客户。子单另用自己的客户名称参与匹配。 |
| 附件 | 附件读取、手机采集 | 列表和预览走单据归属。采集在客户范围为空时直接通过，授权客户范围因此被放宽。 |
| 打印查询 | 打印任务、母单／子单标签 | 打印任务沿用单据读取。`GET /api/label/mother-orders/{code}` 和 `GET /api/label/work-orders/{code}` 不核对客户范围。 |
| 扫码 | `/api/scan/context` | 同码多种单据、一运单多母单、已拆母单会要求选择，不取第一条。扫码使用账号上的原始客户范围，不使用会话里已经收成编号的范围。 |

改名本身不把授权从旧客户挪到同名新客户：名称授权一旦同时对上旧别称和新客户，整段授权变空。客户编号授权不受这次改名影响。空范围若被某个查询当成“不限制”，歧义授权就会被放宽。

## 2. 本批要收口的行为

- 改名只保留原客户编号和旧名称别称，不把权限扩到同名的另一家客户。
- 歧义名称、对不上的别称继续不授权。`客户#编号` 仅在该编号已有档案时收成同一客户编号。
- 授权客户范围为空时，母子单进度、附件采集和打印查询都拒绝，不退回全量。
- 子单客户编号与母单不一致时，进度、扫码候选、附件和打印都不自动按其中一边放行。
- 同一业务号落到多家客户，或同一子单号在库存里对应多家母单时，不挑选第一条。
- 打印母单、子单标签和补打先按单据读取同一客户范围。扫码改用会话里的有效客户范围。

## 3. 明确不处理

- 不开放跨材质子单，不修改拆单分配、库存过账、财务读写。
- 不修改订单维护、库存冲正、数据库迁移，也不把本地 V64 写成测试服已执行。
- 不改安卓壳、云端更新脚本。
- 工作台演示数据和岗位职责过滤保持原样。公司范围账号仍可查看未发生客户冲突的单据。
