**文档版本**：V2.1

**关联文档**：[02_业务流程与规则设计](./02_业务流程与规则设计.md)

## 1. 设计原则

本文的领域对象、字段、枚举和索引包含完整产品的目标方案。除明确说明已落地的切片外，不能据此认定表、字段、状态机或流程已全部实现。实际 MySQL 结构以 [迁移脚本目录](../backend/src/main/resources/db/mysql/) 中已发布的 SQL 为准，当前接口字段见 [API 契约](./16_字段字典与API契约.md)，实施状态见 [开发进度](./14_开发进度跟踪.md)。目标模型与当前切片不一致时先对照代码和迁移，不修改已发布 SQL 来迁就旧设计。

- 业务对象优先于页面字段，避免把系统设计成表单堆砌。
- 库存余额只允许由库存台账汇总或同步更新，不允许直接手工修改。
- 客户所有物料必须和企业自有物料区分。
- 数量、重量、金额、损耗率、单价必须有明确单位和快照。
- 返工不使用两套状态机，作为特殊工单类型建模。
- 称重交接是损耗责任和物料追溯的核心证据。
- 所有关键单据支持操作日志、附件和审批关联。

## 3. 核心领域模型

### 3.1 客户订单 `biz_customer_order`

客户订单是业务来源，不直接代表库存。

关键字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| code | varchar(50) | 订单编号 |
| customer_id | bigint | 客户 |
| status | varchar(30) | 订单状态 |
| expected_delivery_date | date | 预计交期 |
| remark | text | 加工要求和备注 |

状态：`draft`、`confirmed`、`partial_inbound`、`processing`、`partial_shipped`、`completed`、`voided`。

### 3.2 母单 `biz_mother_order`

母单代表一批客户来料，是全链路追溯核心。

关键字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| code | varchar(80) | 母单编码 |
| customer_order_id | bigint | 客户订单 |
| customer_id | bigint | 客户 |
| inbound_date | date | 现场入库日期 |
| inbound_express_company | varchar(80) | 入库快递名称/物流方式 |
| inbound_express_no | varchar(80) | 入库快递单号 |
| sender_name_snapshot | varchar(120) | 寄货人姓名快照 |
| receiver_name_snapshot | varchar(120) | 收货人姓名快照 |
| unpack_signer_name | varchar(120) | 拆箱签字/确认人快照 |
| goods_name_snapshot | varchar(160) | 现场货品名称快照 |
| owner_type | varchar(20) | customer/company |
| owner_customer_id | bigint | 物料所有客户 |
| is_customer_owned | boolean | 是否客户所有 |
| status | varchar(30) | 母单状态 |
| unpack_started_at | datetime | 拆包开始时间 |
| unpack_finished_at | datetime | 拆包结束时间 |
| unpack_video_status | varchar(30) | 视频状态 |
| inbound_remark | text | 入库登记备注 |
| source_register_type | varchar(40) | 原始登记来源，如 inbound_register |
| source_sheet_name | varchar(80) | 原始 Excel/sheet 名称，可空 |
| source_line_no | int | 原始纸质/Excel 行号，可空 |
| source_sequence_no | varchar(40) | 纸质表内序号，可空 |
| import_batch_no | varchar(80) | 批量导入批次，可空 |

规则：

- 客户来料默认 `owner_type = customer`。
- 未确认客户和物料前不得拆分工单。
- 母单作废必须通过审批或权限控制。
- `inbound_express_company` 和 `inbound_express_no` 分开保存，快递单号保持唯一校验。
- `goods_name_snapshot` 是现场登记口径，允许和最终物料档案名称不同，但必须保留映射记录。
- `unpack_signer_name` 一期保存姓名快照，二期可通过附件表关联签名图片。
- `source_*` 字段只用于审计和导入纠错，不参与业务编码、库存余额维度和状态机。

落地状态：

- M3.81 的 `V14__m3_business_document_contract.sql` 已先落 `biz_mother_order` 与 `biz_mother_order_item` 基础切片，保存当前入库业务命令可稳定提供的客户、物料、快递、签收、数量、重量、台账号和登记来源字段。
- `customer_order_id`、`source_sheet_name`、`import_batch_no`、拆包开始/结束时间、视频状态和完整状态流转仍是目标模型字段；导入批次当前仍以 `register_import_batch/register_import_row` 和台账备注追溯。

### 3.7 报工记录 `biz_work_report`

报工是产量、损耗、工资试算的数据来源。

| 字段 | 类型 | 说明 |
|---|---|---|
| work_order_id | bigint | 工单 |
| work_process_id | bigint | 工序实例 |
| employee_id | bigint | 报工员工 |
| completed_quantity | decimal(18,3) | 完成数量 |
| quantity_unit | varchar(20) | 完成数量单位 |
| input_weight | decimal(18,3) | 投入重量 |
| output_weight | decimal(18,3) | 产出重量 |
| weight_unit | varchar(20) | 重量单位 |
| loss_weight | decimal(18,3) | 损耗重量 |
| work_date | date | 工序日记录日期 |
| work_item_name | varchar(120) | 工作项目 |
| started_at | datetime | 本次作业开始时间 |
| finished_at | datetime | 本次作业完成时间 |
| completion_status | varchar(40) | 完成情况 |
| handoff_audit_status | varchar(40) | 交单审核状态 |
| handoff_auditor_employee_id | bigint | 交单审核人 |
| machine_id | bigint | 设备，可空 |
| machine_no_snapshot | varchar(80) | 机器编号快照 |
| is_rework_report | boolean | 是否返工报工 |
| source_register_type | varchar(40) | 原始登记来源，如 polish_daily_register |
| source_line_no | int | 原始日报行号，可空 |
| source_sequence_no | varchar(40) | 纸质表内序号，可空 |
| import_batch_no | varchar(80) | 批量导入批次，可空 |
| reported_at | datetime | 报工时间 |
| remark | text | 报工备注 |

规则：

- 已进入质检或下一工序后，报工更正必须生成更正记录。
- 报工不可物理删除。
- 抛光类工序必须支持 `work_item_name`、`started_at`、`finished_at`、`completion_status` 和 `handoff_audit_status`，用于替代现场纸质日登记。
- 设备类工序可填写 `machine_id` 或 `machine_no_snapshot`，未匹配设备档案时标记为待匹配。
- 抛光日报中的员工和日期属于表头上下文，导入时必须展开到每条 `biz_work_report` 明细。
- `completed_quantity` 必须带 `quantity_unit`，不得只靠前端展示字符串表达单位。

| work_order_code | varchar(80) | 关联工单号，可空 |

规则：

- `雕刻` 必须加入工序模板，可按设备产量统计产能。
- 同一日期、客户、品类、机器编号允许多条记录，但必须保留录入人和录入时间。
- 未绑定工单时只进入产能统计；绑定工单后可参与工序报工和工资试算。
- 雕刻登记表中的日期、客户、品类可由本序号组记录继承；导入器必须在入库前补全，进入新序号组后必须重置上下文，不允许把空白单元格直接持久化为缺失上下文。
- M3.79 已新增 `biz_machine_output_record` 迁移、内存/JDBC 仓储、提交/查询 API；`REG-ENGRAVING` 显式入账后会同步保存设备产量记录。

## 9. 一致性约束

1. 母单未确认前不得拆分子工单。
2. 子工单拆分数量和重量不得超过母单可分配余额。
3. 工序报工必须按顺序执行，跳工序必须有权限和日志。
4. 需要质检的工序未通过质检不得进入下一工序。
5. 返工工单必须关联来源工单和来源质检。
6. 所有库存变化必须生成库存台账。
7. 出库单确认发货前必须冻结足够成品库存。
8. 报工、损耗、库存、视频、审批记录不可物理删除。
9. 单价、损耗率必须使用快照，不得受后续配置变更影响历史单据。
10. 客户所有库存不得和企业自有库存合并计算。

## 11. 当前技术边界与待确认方案

- 库存余额采用同步更新还是异步汇总。
- 金额和重量的小数精度。
- 是否需要软删除字段统一为 `deleted_at`。
- 多组织字段使用 `org_id` 还是 `tenant_id`。
- 视频文件使用本地、NAS、MinIO 还是 S3 兼容对象存储。
- 当前采用 Spring Boot、Vue 3 和 JDBC，领域模块遵循 `domain / app / infra / web`，仓储通过配置在内存默认与 JDBC 间切换。RuoYi-Vue／MyBatis 不属于当前实现约定。新增模型按现有代码、SQL 和 AGENTS.md 落地；未实现的组织、媒体存储或异步汇总方案须另行确认。
