## 6. M3 当前推进记录

### 6.1 已完成

- 启动 M3.1 库存台账持久化切入：新增 `JdbcStockLedgerRepository`，支持将库存台账和余额写入 MySQL 表。
- 默认仓储保持内存模式，配置 `zhubao.inventory.repository=jdbc` 后启用 JDBC 仓储，避免评审环境被数据库依赖阻断。
- 新增 `application-mysql.yml`，通过 `SPRING_PROFILES_ACTIVE=mysql` 和 `ZHUBAO_DB_*` 环境变量接入 MySQL。
- 新增 MySQL 迁移脚本 `V6__m3_inventory_jdbc_repository_contract.sql`，为库存余额表补充 `dimension_key`，解决可空维度字段导致唯一约束不稳定的问题。
- 库存台账号改为日期时间戳 + 序列，降低服务重启后持久化编号冲突风险。
- 新增 H2 驱动的 JDBC 仓储测试，验证台账写入、余额重算、重新读取和跨业务维度转移阻断。
- 启动 M3.2 软硬件现场 POC 记录基线：新增 `HardwarePocRecord`、`GET /api/hardware/poc-records`、前端现场 POC 记录区和 MySQL 合同脚本 `V7__m3_hardware_poc_record_contract.sql`。
- POC 记录覆盖拆包视频、标签打印、PWA 弱光扫码和称重交接，明确结果、证据、阻断项、责任人和下一步动作。
- 启动 M3.3 业务工作台 JDBC 读取基线：新增 `JdbcBusinessWorkspaceRepository`，支持从 `biz_workspace_*` 合同表读取来料、生产、质检、库存追溯和 PWA 工作台数据。
- 新增 `V8__m3_business_workspace_jdbc_repository_contract.sql` 补齐库存追溯时间线表，新增 `V9__m3_business_workspace_review_seed.sql` 提供 MySQL 评审快照 seed 数据。
- `application-mysql.yml` 新增 `ZHUBAO_BUSINESS_REPOSITORY` 和 `ZHUBAO_BUSINESS_SNAPSHOT_CODE`，默认仍为内存仓储，显式设置为 `jdbc` 后读取 MySQL 评审数据。
- 根据页面评审反馈启动 M3.4 UI 整改：将首页主表从 4 条静态焦点记录扩展为来料、生产、质检、库存 15 条跨业务队列，首屏压实为生产运营主控台，并同步 M3.3 实现边界展示。
- 启动 M3.5 真实业务动作基线：新增 `BusinessOperationService`、`POST /api/business/operations/inbound-confirmations` 和前端来料页确认入库调用，确认入库会通过 `StockLedgerService` 写入客户所有原料库存台账。
- 启动 M3.6 生产报工动作基线：新增 `ReportProductionCommand`、`POST /api/business/operations/production-reports` 和前端生产页提交报工调用，报工会在同一工单维度下将 `WIP` 转为 `SEMI_FINISHED` 台账。
- 启动 M3.7 前端评审台信息架构整改：根据页面反馈补强首页真实进度汇报，新增“我目前实际做到了什么”“还不能说完成的部分”“一期业务闭环状态图”和“模块完成度台账”，明确区分真实 API、样例页面、POC 和待开发缺口。
- 启动 M3.8 质检冻结动作基线：新增 `FreezeQualityStockCommand`、`POST /api/business/operations/quality-freezes` 和前端质检页冻结异常库存调用，将同一子工单维度下的 `SEMI_FINISHED` 转为 `FROZEN` 台账。
