# A2 附件访问与预览调查

> 调查日期：2026-10-18。第 1—3 节记录 A2 实施前的源码基线：当时只读检查代码并复用 A0／A1 已记录的测试环境事实。首个 A2 本地增量的状态见第 4 节及[核心进度](./00_项目核心.md)。测试服务器仍运行 A1 发布前的后端，源码结论不等同于该服务器已发布 A1／A2。

## 1. 已核对的消费者链

| 页面／动作 | API | 服务 → 仓储／文件 | 当前表现 |
|---|---|---|---|
| [附件工作台](../frontend/src/features/m1/DocumentManagementWorkspace.vue)进入与查找文档包 | `GET /api/documents/summary`、`/packages`、`/attachments`、`/audit-events` | [DocumentManagementController](../backend/src/main/java/com/zhubao/erp/document/web/DocumentManagementController.java) → [DocumentManagementService](../backend/src/main/java/com/zhubao/erp/document/app/DocumentManagementService.java) → [JdbcDocumentManagementRepository](../backend/src/main/java/com/zhubao/erp/document/infra/JdbcDocumentManagementRepository.java) → `doc_package`、`doc_evidence_attachment`、`doc_audit_event` | 进入页面时四个请求并发；一次读取完整列表，页面本地按关键字和文档包筛选。审计接口仅公司范围管理员／总经理可读，但四个请求共用 `Promise.all`，任何一个失败都会使本次列表装载进入错误分支。普通业务账号实际显示结果未作浏览器实测。 |
| [收货](../frontend/src/features/intake/IntakePanel.vue)、[生产](../frontend/src/features/production/ProductionPanel.vue)、[质检](../frontend/src/features/quality/QualityPanel.vue)、[发货](../frontend/src/features/shipping/ShippingPanel.vue)现场证据 | `GET /api/documents/evidence-links?targetType&targetCode...`；上传后 `POST /evidence-files`、`POST /evidence-links` | [BusinessEvidenceService](../backend/src/main/java/com/zhubao/erp/document/app/BusinessEvidenceService.java) → [JdbcBusinessEvidenceLinkRepository](../backend/src/main/java/com/zhubao/erp/document/infra/JdbcBusinessEvidenceLinkRepository.java)、附件仓储 → `doc_business_evidence_link`、`doc_evidence_attachment`；上传经 [DocumentCaptureService](../backend/src/main/java/com/zhubao/erp/document/app/DocumentCaptureService.java) 到 `evidence-data` | [EvidenceCapture](../frontend/src/features/evidence/EvidenceCapture.vue)按单据显示已关联和待关联，已有失败后显式补关联入口。后端先读全部引用及附件再按单据、阶段、操作筛选；构造每条已关联视图时再次读取全量附件。收货页另有 `/captures`，仅列“手机采集”来源。 |
| 附件页、证据条目点击预览／下载 | `GET /api/documents/attachments/{code}/preview-url`，随后 `GET /attachments/{code}/content?expiresAt&token[&download=true]` | 控制器申请地址时按附件 `businessCode` 校验业务数据范围；服务 HMAC 签发／校验；[LocalAttachmentObjectStorage](../backend/src/main/java/com/zhubao/erp/document/infra/LocalAttachmentObjectStorage.java) → `evidence-data` 原件 | [EvidencePreviewLink](../frontend/src/features/evidence/EvidencePreviewLink.vue)点击时重新取址；图片 `<img>`、视频 `<video>` 直接指向同一原件 URL，下载添加 `download=true`，无缩略或中等清晰度版本。文件读取为 `Files.readAllBytes`，控制器返回完整 `byte[]`。 |

仓储在 JDBC 模式下对上述三张附件表和证据引用表使用无 `WHERE`／`LIMIT` 的全表查询；内存模式同样返回完整列表。当前页面也没有服务端游标、分页参数或阶段／时间／媒体／上传人筛选契约。附件页的文档包列表与所有附件清单是两处展示，同一附件可能出现在两个位置。

## 2. 已证实的差距与影响

| 优先级 | 事实与证据 | 数据／用户影响及实施条件 |
|---|---|---|
| P0：签名用途与响应边界 | [DocumentManagementService](../backend/src/main/java/com/zhubao/erp/document/app/DocumentManagementService.java)的签名载荷只有 `code:expiresAt`，默认有效期 15 分钟；`content` 按签名和“未下线／非待核对”状态放行，不再次读取会话或业务范围。`download` 不在签名中，同一 URL 可切换 `inline`／`attachment`；响应沿用元数据媒体类型，未设置 `X-Content-Type-Options: nosniff`。 | 地址持有者在有效期内可取原件，签名没有绑定清晰度或用途。该行为是当前短期授权设计的可见边界，**未实测跨账号利用或代理响应头**。A2 第一增量先明确短期地址的授权语义、用途和安全内联类型，再设计回归覆盖；避免把已发地址误写成逐请求重新校验业务范围。 |
| P0：整文件传输 | 控制器返回 `ResponseEntity<byte[]>`，本地存储 `Files.readAllBytes`；没有 Range／`206 Partial Content` 处理。图片和视频预览直接使用原件。 | 每次读取在服务端形成整文件字节数组，视频拖动可能重新传原件；浏览器实际请求行为和内存峰值尚未测。先以代表性文件和弱网样例记录传输字节、首图时间、拖动响应，再实现流式／Range，并保护 A1 原件读取与下线语义。 |
| P1：查询规模与重复计算 | 附件页四个全量请求；`summary` 为附件和审计计数再次全量取数；证据板 `links.findAll()` 两次、`documents.attachments()` 至少一次，逐条 `viewOf` 又取全部附件；[DocumentCaptureService](../backend/src/main/java/com/zhubao/erp/document/app/DocumentCaptureService.java)的收货列表也全量取后筛选。 | 数据增长时请求、数据库读取和服务端对象数量随全库规模增加；目前 6 条测试数据不足以证明用户可感的性能瓶颈。先定统一按单据分组的查询契约、排序／稳定分页及范围校验，再对涉及索引的真实查询做计划和数据量核对。 |
| P1：附件工作台权限组合 | `/audit-events` 调用 `assertManager`，其余列表按业务数据范围过滤；前端 `Promise.all` 要求四项均成功。 | 非公司范围管理员／总经理打开附件页可能整页报错，此为代码可推得的结果，需用业务角色定向实测确认。实施时让管理审计单独加载或按权限隐藏，并验证附件本体仍按客户范围显示。 |
| P1：历史与待关联视图 | `EvidenceCapture`能展示同单待关联；`BusinessEvidenceService.query`按单据找所有未在该单类型引用的附件，旧来源不明者标“历史”，仅能回看。`/captures`仅手机采集；附件工作台按 `documentCode` 找关联附件。 | 目前没有跨入口一致的服务端“同一单据全部证据”分页契约。合并前必须保留旧来源不明的只读语义、下线状态、待核对禁止访问、上传成功而关联失败后的补关联条件，并核对同码多单的权限边界。 |
| P2：派生图与视频封面 | 当前代码没有附件派生图、视频封面、方向校正或历史补生成链路；前端本地待上传预览使用 `URL.createObjectURL`，已上传内容使用原件 URL。 | A2 需要新派生对象及可重建索引。以原件为不可替代来源，先新图后历史按需；视频转码应等现场播放数据，不因缺封面就转码全部历史文件。 |

**不是已证实事故：** 目前没有证据表明既有 6 个原件损坏、跨客户已成功读取、页面已经出现内存溢出或视频一定无法拖动。上述条目只描述源码可确认的行为及其可能影响。

## 3. 样本与未实测项

[A0 资产清单](./A0_固定基线与资产清单.md)在 2026-10-18 对测试库实测 `doc_package` 3 行、`doc_evidence_attachment` 6 行、`doc_business_evidence_link` 4 行；附件文件 6 个，共 21,198,741 字节，最大 8,394,963 字节，全部文件 SHA-256 与元数据相符。A1 隔离恢复演练复核同批次 103 张表、6 条附件元数据和 6 个原件，详情见[核心进度](./00_项目核心.md)。这组小样本适合确认兼容与恢复，不足以决定分页阈值、缩略尺寸或视频转码策略。

追加只读核验：测试服务器后端健康接口返回 HTTP 200；当前 6 条附件元数据按媒体类型为 JPEG 4、PNG 1、MP4 1。运行中的 Nginx `/api/` 代理转发到后端，在 `nginx -T` 配置输出中未见 `X-Content-Type-Options`；这不代替对成功附件响应及公网中间层响应头的实际抓取。上述查询只读取运行状态、附件元数据与代理配置，没有读取或改动附件内容。

本轮**未实测**：业务角色打开附件页的 HTTP 结果；不同客户账号对列表、签名地址和原件的越权矩阵；浏览器／安卓壳在现场网络下的首图、下载、视频拖动；成功附件响应头、HAR、内存峰值与 SQL 执行计划。A1 应用后端尚未发布，测试服务器现有 V62／V63 等功能仍来自共享工作树未提交改动；发布策略须先解决版本一致性，不把本调查当成 A2 已上线。

## 4. 首个 A2 本地实施增量

本地代码已完成“原件访问契约与安全响应”首增量：预览／下载分别取址，短期签名含用途和 `original` 清晰度，取址继续校验附件所属单据的数据范围；仅文件头核验通过的 JPEG、PNG、MP4、WebM 可内联，PDF 与不可信类型按附件下载，响应加 `nosniff`。定向测试覆盖用途篡改、期限、取址越权、文件头伪装和前端下载契约。第二个增量改为流式输出原件，视频支持单段 Range／`206`，无效区间返回 `416`；按单据分页、派生图和封面留待后续。旧附件数据没有迁移或清理。

进入下一增量及发布前需固定可发布的 A1 代码版本、取得跨客户测试账号及代表性图片／视频样本、约定手机网络条件与指标口径。**本轮未发布 A1／A2，也没有修改运行数据**。
