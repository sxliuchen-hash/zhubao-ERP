# 收货建单、主数据与工位打印开发方案

**形成日期：2026-10-15；状态：需求分析与开发设计，尚未实施。** 本文依据当前 `App.vue` 的来料、标签、手机作业入口及其服务端调用链整理。现行交付事实以[项目核心](./00_项目核心.md)为准；本文中的新字段、接口和迁移均是拟实施方案，不表示已经上线。

## 1. 目标与业务身份

本次要解决五件相互关联的事：把标签任务准确送到指定工位；让子单标签能直接看出所属母单；让收货选择已有客户和材质并可维护档案；创建订单不强制填写快递公司；客户送货上门、厂内接收等无快递场景也能直接建母单。

**母单号和子单号是现场业务对象的唯一身份。** 母单、子单分别有自己的单号；子单另存不可随意改写的 `motherOrderCode`，形成一母多子的关系。查询、扫码、标签、库存、附件、工序、质检和发货均以真实单号定位，再经服务端核对母子关系。运单号、客户名称、材质名称、手机号、验证码和打印任务号不能代替订单号。系统仍需保留数据库主键、客户／材质编码、请求幂等键、库存流水号和打印任务号等技术标识；“唯一业务身份是订单号”不等于取消这些保证事务和审计所需的标识。

新母单号沿用 `MD-年月日-四位流水`，新子单号沿用 `ZD-年月日-四位流水`；旧单号原样保留。当前两张业务表分别对 `code` 做唯一约束，服务内的同步锁不能单独保证多实例发号。建议在同一业务事务内使用数据库唯一约束保护的订单号登记表／原子序列，登记单号及母单或子单类型；内存实现提供等价的原子保留语义。上线前核查旧号是否跨表重复，不能在有冲突时盲目回填登记表。不要让用户自行用运单号或客户号充当母单号。

## 2. 当前实现与差距

| 事项 | 已有事实 | 与需求的差距 |
|---|---|---|
| 收货入口 | 桌面来料和手机作业复用 `IntakePanel.vue`；只有识别到新运单后才展示建母单表单 | 无快递、上门送货、内部交接不能直接从该入口建单 |
| 收货字段 | 页面手输客户名称、货品名称、数量、重量、要求和期限；快递公司默认“顺丰” | 没有客户和材质的可选档案；快递公司虽后端非必填，页面仍出现且默认值会写成快递事实 |
| 客户身份 | 母单存 `customerId` 与名称快照；手机收货未传客户 ID 时，后端按名称映射已知客户或计算散列 ID | 同名、改名和散列碰撞会影响授权、库存与财务；`sys_customer_authorization` 是用户授权关系，不是客户档案 |
| 材质 | 母单／子单和库存有 `materialCode`；手机表单不选材质，后端缺省为 `MAT-MOBILE` | 占位编码无法表示实际材质；货品名称与材质是不同概念 |
| 运单 | 当前非空运单通过 `courier_identity` 唯一索引绑定一张母单，收货超时按运单找原单 | 不能把运单作为全场景的唯一建单锚点；同一运单含多件、多母单时需要人工选择 |
| 子单标签 | `ChildWorkOrderRecord` 已有 `motherOrderCode`；二维码和首行使用子单号 | 标签字段来源与默认模板没有母单号，纸面无法直接识别母子关系 |
| 集中打印 | 服务端已有打印任务、租约、补打和状态；厂内程序以配置的 `stationId` 领取，用本机 `printerName` 找 Windows 队列 | 创建任务无目标工位字段；仓储领取任意 `PENDING` 任务，先轮询的工位可能拿走别的工位任务；当前只校验一把共享工位令牌 |

上述“差距”是代码核对结果。现有厂内打印程序尚未安装更新，佳博实机出纸、纸张间隙、二维码可扫性仍需现场验证。

## 3. 建单流程：先选来源，再生成订单号

### 3.1 建议的统一入口

收货页和手机收货页提供明确的来源选择：**快递寄来、客户送达、厂内接收／其他**。这些选项只决定需录入的收货来源信息，最终都调用同一母单创建与入库业务服务，生成母单号并进入现有“预览母单标签 → 不拆或拆子单”流程。不要为无快递场景另造一套工单或绕过库存入账。

| 来源 | 必填 | 可选 | 提交后 |
|---|---|---|---|
| 快递寄来 | 客户、货品／材质、数量、重量、加工要求、期限 | 运单号、快递公司、交件人、现场证据 | 生成母单号；有运单则作为来源线索保存，可搜索并核对候选母单 |
| 客户送达 | 同上 | 交件人、交接时间、交接备注、现场证据 | 直接生成母单号；不造虚构运单或“快递”公司 |
| 厂内接收／其他 | 同上 | 来源说明、经手人、交接备注、现场证据 | 直接生成母单号；保留真实来源和操作人 |

快递公司在所有来源下均非必填；仅快递来源显示运单和公司输入，不预填“顺丰”或“快递”。如果现场希望快递来源必须有运单，应单独作为操作规则确认，不能据此禁止无快递建单。无运单时提交超时应保留原 `requestId` 重试，并可用返回的母单号或按客户、时间、操作人筛查；不能生成新请求后盲目再建。提交成功后只显示已保存母单号，单号由服务端生成。

建议将现有 `MobileIntakeCommand` 扩为来源类型、可空运单、客户 ID、材质编码及交接信息；桌面和手机共用同一契约。服务端以 `requestId + 操作人 + 规范化业务内容` 做幂等，母单、来料事实和库存台账同一次提交；不同客户、材质、来源或数量不得复用同一请求号。运单查询改为候选列表或明确的多结果提示，不再静默取第一条。来源字段与原运单字段都保留历史记录，旧单号及旧运单不改写。

### 3.2 运单与订单号的关系

运单是**可空、可重复的外部参考**，订单号是系统生成的业务主键。用户可以按运单检索，结果为零张时继续建单，为一张时可打开核对，多张时必须人工选母单。新建时如运单已有记录，显示客户、收货时间和母单号供核对并提示重复风险；经确认后才允许同运单另建母单。不能仅靠运单自动认定“已有单就不可建”。

落地时需要同步调整 `findMotherOrderByCourierNo` 的单结果契约、扫码上下文、重复校验、超时核对、页面提示和测试，再在**新迁移**中移除 `courier_identity` 的唯一索引或改为普通检索索引。不能直接删索引而继续使用 `findFirst()`。历史数据的运单及其原始证据继续保留。

## 4. 客户档案与材质选项

### 4.1 客户档案

在现有业务域内增加轻量客户档案，不把账号授权表当成客户表。建议字段为稳定 `customerId`、客户编码、显示名称、别名／曾用名、启用状态、联系人与电话（可选）、备注、创建及修改人和时间。编码与名称的规范化去重规则由服务端执行；同名疑似重复需提示核对，不自动合并历史客户。停用客户仍可查看旧订单，但不能用于新单；重命名只改档案展示，订单保留创建时的名称快照。

收货表单提供可搜索、可勾选确认的**单选客户下拉**，展示编码与名称；提交稳定 `customerId`，服务端读取当前有效档案并保存名称快照。无匹配客户时由有权限人员先新增档案，再返回草稿继续收货；不在普通录入框中自由写一个未经登记的客户名称。用户管理里的客户范围也改用稳定客户编码／ID 选择，授权服务端按档案校验，不能因改名扩大或丢失权限。已有按名称或散列 ID 创建的母单、库存、财务和授权需先做只读盘点及映射清单，再按明确规则迁移；未能确认归属的记录保留原值并列出人工核对，不按名字批量猜测。

### 4.2 材质目录

材质与货品名称分开维护。建议目录字段为 `materialCode`、材质名称、常用别名、启用状态、排序、创建及修改人和时间；收货时在可搜索下拉中选择材质，提供“新增自定义材质”入口。自定义内容须经服务端去重后保存为正式可复用选项；普通收货员如无维护权限，可提交待确认材质并由授权人员确认，不能把任意文本写成永久库存编码。停用材质可查旧单，不能新选。

**首版按每张收货物料行选择一种主材质。** 当前母单、子单与库存流水都只有一个 `materialCode`；把多种材质用逗号塞进该字段会破坏库存归集。如现场一张母单确需多材质，应新增收货物料明细行，每行各自材质、数量、重量，并明确拆单与库存扣减的对应关系；该规则需用真实样单确认后设计。`MAT-MOBILE` 仅作为历史占位值保留，新增收货不得再自动写入。

## 5. 子单标签上的母单号

子单的主识别号仍是 `ZD-…`，二维码仍指向子单；标签另显示一行 **“母单：MD-…”**，值只能从已保存的 `ChildWorkOrderRecord.motherOrderCode` 读取，不能由打印者手填。若另需自由备注，单独设计备注字段，不能拿自由文本替代母子单关系。

在标签字段来源中增加 `motherOrderCode`，默认子单模板把该行设为必显；母单模板不显示。40×30 mm 紧凑版需要给子单号、二维码、验证码和母单号保留空间，其他次要字段按版面优先级缩减，母单号不得截断成不可辨认文本。浏览器预览、浏览器打印、服务端打印任务快照及 `print-agent` 绘制必须使用同一字段与版式。模板管理中的自定义子单模板也应始终保留母单号的固定关系区，避免模板误删后现场失去关联信息。

已排队任务的快照保持原样；新任务使用新模板。旧版同版补打沿用原快照，若现场必须补出带母单号的新标签，应作为**新标签版次／换贴**按现有追溯规则处理，不能悄悄覆盖原任务内容。扫码结果继续由服务端返回真实母子关系，纸面展示仅方便人眼核对。

## 6. 指定工位打印

### 6.1 路由规则

创建打印任务时由用户在有权使用的工位列表中选择**目标工位**，可预选管理员配置的常用工位；未选有效工位时不提交。任务创建后保存不可变的 `targetStationId`，任务编号只是执行记录，订单号仍是业务身份。服务端在创建时核对标签业务单、打印权限、客户范围、工位启用状态和模板／纸张能力；服务端冻结标签内容与目标工位，不接受客户端上传任意标签 HTML 或自行指定打印机驱动名。

工位档案至少有工位 ID、名称、启用状态、可打印标签类型、纸张规格、备注。每个厂内打印程序仅持有该工位独立且可撤销轮换的凭据，本机配置 `stationId → Windows 队列名`；云端只选择工位，不直接操作厂内打印机。领取接口按目标工位原子选取最早待打印任务，未分配到该工位的程序绝不能领取。任务已领取后不允许静默改目标；需要转工位时显式取消未出纸任务并新建关联任务，记录原因和操作人。`UNCERTAIN` 必须先人工核纸，不自动换工位重打。

现有 `PrintJob.stationId` 表示**领取后的工位**，创建时为空，不能直接拿它充当目标工位。建议新增 `targetStationId` 并在新迁移中为既有待处理任务建立明确的迁移策略：仅在确认原来唯一工位时批量指定；无法确认的任务标为待人工分配，不让任意工位抢领。现有 `content_snapshot` 为 `VARCHAR(1000)`，新增母单号及版式字段前应评估真实快照长度并扩为可容纳的文本类型，避免任务创建成功却存不下完整标签。领取、回报继续区分 `PENDING`、`LEASED`、`SPOOLED`、`FAILED`、`UNCERTAIN`；`SPOOLED` 只代表送入 Windows 队列，出纸仍需现场核实。

### 6.2 页面与权限

标签页展示目标工位、当前可用状态、任务号、目标工位、队列状态和失败原因；手机和桌面共用接口。工位维护入口放在现有配置／标签管理中，按权限显示；普通打印者只看到可选工位，不看到凭据。工位离线时可排队，但页面要明确提示“待工位上线”；是否允许向离线工位提交由现场流程确定。打印程序启动时检查配置的工位和本机队列，工位与队列绑定不匹配时停止领取并报告错误。

## 7. 拟议数据与接口改动

| 范围 | 拟议改动 | 兼容与约束 |
|---|---|---|
| 客户 | 增加客户档案仓储及列表、创建、修改、停用接口；订单继续存 ID 和名称快照 | 先盘点历史 ID；客户授权和财务引用稳定 ID |
| 材质 | 增加材质目录仓储及列表、创建、停用接口；收货提交材质编码 | 兼容历史 `MAT-MOBILE`，不把货品名称当材质 |
| 收货 | 统一建单请求增加来源类型、可空运单、客户 ID、材质编码和交接信息；运单查询返回候选 | 旧客户端字段在过渡期兼容；无快递不得写伪造运单 |
| 母子单 | 保留母单／子单号与子单外键关系；校验跨表唯一和并发发号 | 历史单号不改写；其他流水仍以单号关联 |
| 标签 | 子单字段来源增加 `motherOrderCode`，默认标签和快照固定显示母单号 | 旧任务快照不重写；换版与补打分开 |
| 工位 | 增加工位档案、独立凭据、任务 `targetStationId`、按工位领取和可用工位查询 | 旧单工位分配需盘点；每个工位只用本机打印队列 |

这些接口形状是设计建议，实施时须同步更新[API 契约](./16_字段字典与API契约.md)。持久化沿用本地默认内存、MySQL 切换 JDBC；迁移按当前最大版本之后追加，禁止修改已发布的 V1—V57。目录、订单、任务、授权和证据都要纳入既有备份与恢复范围。

## 8. 实施顺序与最小验收

1. **主数据与历史盘点：**盘点客户名称／ID、占位材质、运单重复情况和待处理打印任务；确定映射及旧客户端兼容策略。新增客户、材质目录与权限、下拉选择。
2. **统一收货：**先完成来源类型、无运单建单、订单号幂等与库存原子入账；再调整运单多结果查询和唯一索引。桌面、手机共用页面和服务。
3. **子单标签：**从子单事实带出母单号，更新默认模板、40×30 版式、浏览器与打印程序快照。
4. **指定工位：**建立工位档案和独立凭据，任务保存目标工位，按工位原子领取；补齐页面选择、离线提示和人工转工位记录。
5. **现场验收：**在目标电脑和标签机上验证指定工位隔离、纸张尺寸、二维码扫码、断网／卡纸／租约超时与补打核纸。现场结果再写回[项目核心](./00_项目核心.md)。

必要验证覆盖：不同来源均只生成一张母单及一笔库存事实；重复 `requestId` 返回同一单，内容变更拒绝；相同运单多母单必须选择；客户改名不改变历史快照和权限；材质自定义去重；拆单后标签准确显示所属母单；两个工位并发领取不能串工位；离线、租约到期和补打不能自动重复出纸。按改动阶段执行定向测试和现场检查，不把全仓测试与打包作为每一步默认门禁。

## 9. 待用现场样单确认的规则

1. 同一快递包裹中有多件货时，现场是一张母单多条物料，还是多张母单？这决定运单多结果与物料明细的首版范围。
2. 一件货是否可能由多种材质组成并分别计库存？如是，需要物料明细及拆单分配，不能只做多选文本。
3. “厂内接收／其他”具体包括客户上门、业务员带回和内部转交中的哪些情形？交接人、照片和签收是否有强制要求？
4. 现场有哪些打印工位和 Windows 队列，谁能选工位、谁能改默认工位，断线时是否允许先排队？
5. 子单 40×30 mm 标签上，母单号与加工要求、期限的优先级及最小可读字号，以实物样张确认。

未确认项不阻止先实施共同部分，但涉及多材质扣减、运单拆分和实物打印的规则不得凭猜测写成已验收事实。
