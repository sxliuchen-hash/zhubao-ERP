## 1. 当前范围

来料加工生产管理，主线为 **收货 → 母单／拆单 → 标签 → 分批交工 → 质检／返工／放行 → 发货 → 库存、财务与证据追溯**。保留 `App.vue` 原 17 项授权入口及业务依赖，日常入口归并为工作台、订单、生产／质量、库存、客户、财务和审批；低频能力按需打开。桌面、手机共用服务与有效权限。

现行实现不包含完整客户订单、自有产品销售、实物盘点、完整成本会计、小程序或新硬件集成。10-30完整重构计划已纳入客户库存、本厂物料工具、固定资产增强、轻量盘点、独立打样及金工，尚未实施；不据此扩展完整成本会计或供应链。安卓已有 debug 容器，正式签名与当前版本全链验收未完成；网页发布不等于 APK 更新或客户交付。

- Vue 3／TypeScript／Vite，Java 17／Spring Boot 3 模块化单体；领域内保持 `domain/app/infra/web`。不按 `m1`、`sample` 等旧命名判定弃用。
- 10-30将5份独立调研及实施文档完整合入[大版本整体重构方案](./大版本整体重构方案.md)，原文已归档。用户进一步确认固定资产增强、独立打样及金工也必须完成，纳入本次整版范围；打样每次样品交付后确认样费、可明确免收；大模型通常不上传，保留版本／格式／存放引用和轻量确认凭据。[Grok任务册](./重构执行/Grok节点执行任务册.md)已拆为11组105个节点，含依赖、范围、业务门槛、验证和交接；图集19张，拍照计数算法仍后续开发。GR-A01已在分支 `refactor/grok` 建立工作区与保护基准，分出点 `7ba60e3`；三个未提交样式文件仍留在工作区。详见[GR-A01基准](./重构执行/GR-A01-工作区与受保护资产基准.md)。GR-A02 只读清单已用本地合成样本验证，线上快照仍待核。下一节点 GR-A03 待用户指定。动态进度只维护本核心。
- 同日用户明确主要正式使用资产为已录母单、已印工单标签及母单照片，其他模块未深用；[实施策略](./大版本整体重构方案.md#implementation-strategy)改为重点保护这些资产及原收货来源，后续业务统一新模型、分阶段开发、一期完整验收后集中切换。[存量接续](./大版本整体重构方案.md#stock-adoption)保留原号／原码／原照，不重复入库，不默认清空其他真实记录；不长期保留两套完整旧新流程。尚未做服务器数据盘点或迁移。
- 本地默认内存，MySQL 下业务、库存、财务等默认 JDBC；审批、附件元数据等仍有独立开关，Compose 显式覆盖。只开 profile 不代表全部数据持久化；登录会话随账号仓储保存。
- 正式工作台只读真实 `LIVE` 单据，DEMO 快照／仓储／开关已删除；自动客户、附件、固定现场记录与网关样例设备已退出，空库无伪造业务；演示账号初始化已退出，仅保留首次必须改密的管理员；已存账号保留。
- 单据在 `BusinessDocumentRepository`，库存经 `StockLedgerService`，跨仓储用 `BusinessWorkUnit/WorkSession` 同次提交。查询、说明、上传及 100% 进度不写交工、库存或工资。
- 母／子单号是业务身份，运单只是检索线索；多候选人工选择。稳定客户 ID 授权，历史名称仅唯一映射时生效。`CUSTOMER_RANGE` 空名单拒绝；其他岗位仍按本人、班组／部门范围，空组织不扩大权限。
- 桌面、手机使用同一菜单及 `effectivePermissions`，服务端逐请求鉴权；总经理显式清单。10-28 已确认十来人、一个核心管理员，账号升权暂不双人复核，管理员直接保存并审计；预审批新申请及专属放行链已退出（后端 61、前端 30 项通过），账号事务、最后管理员保护和会话撤销保留。业务管理可另勾收货员或库管岗位：收货员办理客户寄存收货、领用和退回，库管再加公司料、退还客户和冻结。收货顶岗本身不含这些库存动作，冲正仍只给管理员。测试服已发布，刘晨已勾选收货员岗位。
- 附件是原件＋数据库元数据／引用，成套备份；MySQL 签名密钥至少 32 字符随机值。生产禁用开发请求头身份。下线不删除原件，管理对账不自动清理文件。
- 迁移 append-only，保留历史表、seed 与原文校验和。代码归档不删表、不清数据。PWA、条件装配、升级、备份及设备依赖不能因没有独立菜单而删除。
