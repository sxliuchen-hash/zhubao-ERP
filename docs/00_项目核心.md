## 1. 当前范围

保留当前前端 16 个页面及其实际调用、权限、持久化、事务、文件存储与部署依赖。当前是来料加工生产管理系统，包含基础经营核算；完整基础档案、客户订单、盘点、自有产品销售、APP／小程序和新增硬件集成不在本轮开发范围。

用户提出的 **ERP 整体业务改造** 包括按权限汇总订单加工进度与当前工序百分比报工、客户备料与公司自有生产物料库存、中途改单、母子单和工序版本、财务逐次确认、换标与跨单证据追溯；桌面端和未来安卓端都使用同一业务服务。改单等全链规则见[订单变更、换标、计费与全链路追溯设计](./订单变更与全链路追溯设计.md)。安卓内部 APK、厂内电脑集中打印、现有 16 个页面的手机覆盖及整体工作量见[安卓 APP 与集中标签打印开发文档](./安卓APP与集中打印开发文档.md)。现有客户来料会形成 `RAW_WAITING` 待加工余额，但必须先建加工母单并填写要求与期限；独立备料收货、分批领用和公司自有生产物料出入库尚未实现。子单已有 `motherOrderCode`，但缺已开工改单版本；标签二维码已有版本与实例标识，实际换贴仍待现场核对；客户协议按月、账单有单价快照，却无订单中途改价差额流程；工序及证据可分单查询，尚无母单聚合时间线。上述仍有待实施部分；当前已有 debug 试装 APK 和服务端打印任务，但无正式签名 APK、工序百分比报工或厂内打印程序；现行范围与现场阻断不因方案编写而视为完成。

## 2. 现行架构与约束

- Vue 3／TypeScript／Vite 前端；Java 17／Spring Boot 3 模块化单体后端；领域内保持 `domain/app/infra/web`。继续复用现有模块，不新增服务、通用框架或客户端。
- 桌面与手机复用 `IntakePanel/ProductionPanel/QualityPanel/ShippingPanel`，扫码目标来自服务端规范身份；多子单或多库存必须人工选择，禁止猜第一条。
- 正式工作台默认 `LIVE`，空库为空。只有显式 `zhubao.business.workspace.demo-enabled=true` 才读取独立 `DEMO` 快照，两者不合并。保留的演示仓储是现行显式演示模式依赖。
- 库存统一经 `StockLedgerService` 写台账；正式业务事实在 `BusinessDocumentRepository`，跨仓储同次提交使用已有 `BusinessWorkUnit/WorkSession`。查询、过程说明和附件上传不隐式发货、报工或写账。
- 本地默认内存；MySQL 下正式单据、库存、财务等默认 JDBC，但评审快照、审批和附件元数据仍受独立开关控制。登录会话跟随账号仓储，MySQL 下写入 `auth_login_session`。Compose 显式覆盖相关 JDBC 开关。只开启 profile 不等于所有数据都持久化。
- 附件使用本地文件＋数据库元数据／引用，两者都要备份。MySQL 预览签名密钥需至少 32 字符随机值。生产禁用开发请求头身份，按真实角色和客户范围授权。
- 数据库历史迁移 V1—V47 保留原文，包括旧表和 seed；V48 仅追加用户管理菜单。代码归档不等于删表、清数据或跳过迁移。`ops` 是受控数据库升级工具，`operations` 是现行运维页，二者均保留。
- `common/security/inventory/work`、PWA、设备接入与备份脚本虽不是独立业务页面，仍是已启用功能的依赖，不能据“无菜单”归档。
