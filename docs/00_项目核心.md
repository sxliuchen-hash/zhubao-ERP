# 项目核心

**更新日期：2026-10-13。唯一现行总览；历史方案不再驱动开发。**

## 1. 当前范围

保留当前前端 15 个页面及其实际调用、权限、持久化、事务、文件存储与部署依赖。当前是来料加工生产管理系统，包含基础经营核算；完整基础档案、客户订单、盘点、自有产品销售、APP／小程序和新增硬件集成不在本轮开发范围。

首条业务线：**收货 → 母单／拆单 → 标签 → 工序交付 → 质检／返工复检／放行 → 发货 → 库存与证据追溯**。已有财务、导入和设备管理按实际岗位使用，不继续扩展外围能力。

## 2. 现行架构与约束

- Vue 3／TypeScript／Vite 前端；Java 17／Spring Boot 3 模块化单体后端；领域内保持 `domain/app/infra/web`。继续复用现有模块，不新增服务、通用框架或客户端。
- 桌面与手机复用 `IntakePanel/ProductionPanel/QualityPanel/ShippingPanel`，扫码目标来自服务端规范身份；多子单或多库存必须人工选择，禁止猜第一条。
- 正式工作台默认 `LIVE`，空库为空。只有显式 `zhubao.business.workspace.demo-enabled=true` 才读取独立 `DEMO` 快照，两者不合并。保留的演示仓储是现行显式演示模式依赖。
- 库存统一经 `StockLedgerService` 写台账；正式业务事实在 `BusinessDocumentRepository`，跨仓储同次提交使用已有 `BusinessWorkUnit/WorkSession`。查询、过程说明和附件上传不隐式发货、报工或写账。
- 本地默认内存；MySQL 下正式单据、库存、财务等默认 JDBC，但评审快照、审批和附件元数据仍受独立开关控制。Compose 显式覆盖相关 JDBC 开关。只开启 profile 不等于所有数据都持久化。
- 附件使用本地文件＋数据库元数据／引用，两者都要备份。MySQL 预览签名密钥需至少 32 字符随机值。生产禁用开发请求头身份，按真实角色和客户范围授权。
- 数据库历史迁移 V1—V47 保留原文，包括旧表和 seed；代码归档不等于删表、清数据或跳过迁移。`ops` 是受控数据库升级工具，`operations` 是现行运维页，二者均保留。
- `common/security/inventory/work`、PWA、设备接入与备份脚本虽不是独立业务页面，仍是已启用功能的依赖，不能据“无菜单”归档。

## 3. 当前事实与尚未关闭的问题

**尚无正式客户交付版本。** 2026-10-13 的 UI 内部记录有后端 446 项、前端 230 项及生产构建通过；这是历史结果，本轮归档不把它计作重新验证或现场验收。

| 优先级 | 未完成项 | 关闭标准 |
|---|---|---|
| P0 | MySQL 8.4 在 V36 的 `year_month` 处已有安装失败记录；部分财务 JDBC SQL 有相同写法风险 | 隔离目标库验证安装及启用 SQL，保持已发布迁移原文，不靠后续版本越过失败 |
| P0 | 新面板与旧报工、质检、发货仍并存；无 `requestId` 的兼容路径缺少同等事务／回放保证 | 查清页面、导入、设备消费者，启用路径统一提交；一次操作的网络重试复用稳定编号 |
| P0 | 拆单逐行写库存／子单，再写母单状态，尚未统一工作单元 | 整体提交；中途失败回滚和必要并发验证。当前为源码风险判断 |
| P0 | 手机 HTTPS、标签打印、实际上传与回看缺少完整现场证据 | 固定环境、真实手机及标签机跑通；接续现有部署改动 |
| P0 | 真实账号、客户／物料、工序及业务规则需限定 | 少量试单资料、实际权限；明确损耗、质检让步、返工与退货边界 |
| P0 | 数据库＋附件的实际恢复尚需闭环 | 备份确有文件、隔离恢复可查，试用数据与正式账边界明确 |

当前配置页不是完整主数据维护中心；工序仍限定雕刻、镶嵌、抛光，收货客户可手填。基础财务不是会计总账或银行代发，未确认损耗／工资规则不得直接用于正式扣款。

网页现状：摄像头／照片扫码、照片与 MP4／WebM 视频上传关联、标签二维码生成及浏览器打印均已有代码链路；证据采集依赖系统文件／拍摄入口，尚无网页内独立开始／停止录像。标签编码为 `JG|类型|单据编号`，需在 ERP 内扫码查询权限范围内的业务信息，普通扫码软件不会直接打开详情。实际手机兼容性、快递一维条码和标签出纸仍待现场验收。

下一步先固定试用环境，处理妨碍测试的目标库安装问题，再从页面跑正常单、拆单、返工复检、部分发货及失败重试；按失败证据和已知风险修复事务／幂等等问题，随后现场验证、恢复及连续试用。**不以全仓治理作为开始测试的前提。** 后续详细治理按[治理与瘦身计划](./治理与瘦身计划.md)逐个动作收口，本轮仅整理计划；不按历史阶段编号继续扩功能，也不把日期计划当验收结果。
