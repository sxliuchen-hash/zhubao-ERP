# 库存管理与母单加工要求模板改造方案

编写日期：2026-10-21。

本文综合此前库存讨论、本轮自有库存页面需求，以及母单加工要求模板需求。本文维护库存与模板的需求和验收规则。2026-10-25 清理过时基线：模板建单、小数单位展示和公司料总览已有实现；寄存、建单、冻结及冲正仍需 JDBC 验收，不能将全文视为尚未实施。实际交付进度与验证结果统一记录在[项目核心](./00_项目核心.md)。

## 1. 改造目标与已确认边界

本次要解决两类日常工作：库管可以清楚地查看和管理库存；收货人员建立母单时可以快速组合加工要求。

| 事项 | 本次口径 |
|---|---|
| 公司自有库存 | 指公司自有生产物料，与客户物料分别记账；不包含自有产品销售。 |
| 客户寄存备料 | 客户物料允许先收货入库，暂不创建加工母单、不进入生产待办；后续可部分领用或直接退还。 |
| 多材质收货 | 一张收货单允许多条物料明细，各行分别记录材质、单位、数量、重量、批次和结余。 |
| 母单加工要求 | 建单时可以勾选加工步骤，也可以选择自行维护的组合模板，再补充本单文字要求。 |
| “车型”的含义 | 用户指车成珠型。本文建议界面使用“车形（车成珠型）”，不涉及汽车车型；模板名称和步骤文案允许维护。 |
| 加工要求与正式工序 | 用户已明确：本轮新增的勾选项只用于母单加工要求描述。选择“开粗、车形”等不会新增岗位报工工序、工序授权或计费项目。 |
| 盒子二维码与库位 | 二期建设。本期只保留仓库、批次及以后关联盒位的扩展空间。 |

下文中的默认规则是本方案建议采用的实施口径；尚未确定的损耗、成本、收费和现场称量规则列在第 12 节，不视为用户已确认。

## 3. 库存分类、编号与数量口径

### 3.1 三个查看范围

| 范围 | 解释 | 主要操作 |
|---|---|---|
| 公司自有物料 | 权属为公司，用于生产的原料和配件 | 入库、领用登记、领用退回、来源与去向查询。 |
| 客户寄存备料 | 权属为指定客户，尚未转入加工任务 | 多明细收货、部分领用到加工单、从加工单退回、直接退还客户。 |
| 加工库存 | 已归属加工母／子单的待加工、在制、半成品、成品、返工和冻结库存 | 查看与追溯；状态由已有收货、生产、质检和发货单据驱动。 |

“厂内实物”是按状态和权属筛选后的汇总视图，不是第四本独立库存账。公司料从库内领到车间，如果实物仍在厂内，不应被算成已经离厂。

### 3.2 编号与来源关系

推荐贯穿关系：**收货单号 → 收货明细行 → 库存批次 → 领用／退回／退还单及明细 → 加工母／子单 → 正式生产、质检与发货记录**。

- 收货单和各类业务操作单号由系统生成；每条收货明细形成可追溯批次。客户自带编号另存为外部参考号，不代替系统批次身份。
- 同一客户、同一物料两次到货，分别保留来源批次；汇总可以合并显示，操作必须落到确定批次。
- 运单号可空、可重复，只作来源线索。入库、领用和附件关联均选择明确单据，不取运单匹配的第一条。
- 一次寄存收货可供多张加工单使用，一张加工单可关联多笔合法来源领用；每笔关系保存来源行及实际数量、重量。
- 库存现有维度不能同时带独立批次和加工母单。来源批次到加工单的追溯应通过领用明细保存，不能直接拼入现有维度或仅写在备注里。

### 3.3 数量、重量和冻结

- 数量明确单位，例如克、颗、件；不同单位分别合计，不出现“100 克＋20 颗＝120 件”。页面取消固定追加“件”。
- 重量采用克，保留当前库存 `DECIMAL(18,3)` 精度约束；数量同样保留允许的小数，拒绝超精度而不是静默截断。接口与页面避免将金额或库存数字做有损转换。
- 独立收货行／批次保存单位，库存查询与操作必须能确定它；同物料不同单位不能落入同一个无单位余额后再按任意单位解释。若允许单位换算，另行明确换算规则和快照，不能自行猜测。
- 待核收货不计可用库存。未称量的重量应显示“待称量”，不填假重量、不把未知重量写成已确认的零。
- 冻结是账面库存中的不可用部分。按数量、重量分别显示账面、冻结和可用，不能冻结时减一次账、计算可用时再减一次。
- 实物退还、领用退回、录入错误冲正和实际生产消耗分别记业务原因，不能都用修改余额处理。

对一个来源批次，未领用账面量按“确认入库－累计领用＋领用退回－直接退还±合法更正”核对；可用量再扣除其中被冻结的部分。数量和重量分别核对。

## 4. 库存页面与日常交互

在现有“库存”菜单内提供页签，首期以“公司自有物料”为主要入口；有权限的用户再切换客户备料、加工库存和出入库记录。沿用现有菜单，不为每个操作增加一级页面。

### 4.1 总览与筛选

- 总览显示有效批次数、按单位分组的数量、已知重量、冻结及待核记录。数字仅代表当前账号可见范围，不能把未知重量或无权限数据当成零。
- 筛选包含权属／客户、物料、批次、仓库、状态及日期。仓库目前按现有合法编码选择；此处不把仓库编码当成盒号。
- 物料使用现有材质档案的稳定编码与显示名称；公司物料名称不适配时完善现有目录，不另造一套同名目录。
- 无库存、筛选无结果、无权限、加载失败分别显示；支持刷新和保留有效筛选。

### 4.2 明细与批次详情

| 列表字段 | 批次详情补充字段 |
|---|---|
| 权属／客户、物料、批次、仓库、数量单位、账面数量／重量、冻结／可用、状态、最近变动 | 来源收货单及行、外部参考号、清点记录、累计领用和退回、直接退还、关联加工单、操作人、时间、凭证与冲正关系。 |

列表点开一批后，只查询和展示该批相关流水；不能用“整页最近一笔流水”冒充此批最近记录。流水至少包含业务类型、单号、来源、去向、变化数量／重量、前后余额和操作人。

入库使用独立表单；领用、退回和退还从选中的批次或原操作明细发起，自动带入不可随意修改的权属、物料、仓库和批次。填写本次量时显示当前可用量，提交仍由服务端重新校验。

成品发货入口放入加工库存的相应动作区；客户成品退货和售后复核继续关联原发货单。客户寄存原料退还使用自己的退还单，名称与入口应区别清楚。

### 4.3 手机页面

手机使用同一服务和权限，采用批次卡片、详情和单步表单，不把六种操作与全部输入框同时铺开。库管可以按物料／批次查找并入库、领用、退回；本期不新增盒码扫码上架。

## 5. 公司自有生产物料流程

### 5.1 入库

选择公司权属及仓库，填写来源说明、日期、交接人和多条物料明细，确认后生成入库单、批次和台账。来源可记录采购到货或其他交接线索；本期不由此自动创建采购应付或付款。

### 5.2 领用与退回

从批次选择数量／重量，记录实际领用人、用途；用于具体加工单时必须关联可访问、可使用的真实母／子单，其他用途必须写明。领用使库内可用量减少，已领用待处理量增加；记录中的操作人取登录会话，领用人作为独立业务字段。

退回从原领用明细选择，累计退回不得超过该笔可退量，恢复原物料、权属和批次。不能只凭同名物料创建一笔无来源退回。公司料与客户料不能通过普通领用互换权属。

**用途关联只是追溯关系。** 当前公司料转在制尚未证明可以与客户料合并形成产品投入。涉及公司配件实际消耗、成品产出和多来源成本时，按第 11 节另做生产联动，不能把领用登记直接视为已完成产品消耗核算。

### 5.3 闭环的交付界限

首期可交付“入库—领用登记—原单退回—余额与去向对账”。尚未确定消耗／报废规则的已领用物料，保留真实未结记录和提示，不能自动全部核销或永久隐藏。

公司物料的最终消耗、报废、供应来源退货及成本确认，在实施对应写入前补齐业务规则。没有这些动作的验收，不能把首期称为公司物料全生命周期核算完成。

## 6. 客户寄存备料与加工衔接

### 6.1 收货时区分业务意图

收货入口提供“现在加工”和“先寄存备料”两种意图：

- 现在加工：沿用现有建母单入口，填写加工要求与期限，遵守现行多材质、单位及拆单限制。
- 先寄存备料：创建独立寄存收货单和多条明细，不要求加工期限、不创建生产任务、不自动产生加工费。

寄存支持“草稿／待核 → 逐行确认 → 入账”。本方案默认整单一次确认：有未核清行时不做部分入账；已经核清的货需要先入库时，可拆成独立收货单。记录申报与实收差异、清点人、时间和证据。待核单与已入账单在查询中明确区分。

### 6.2 从备料建加工单

选择来源批次和领用量，再填写加工要求、期限及加工货品信息。服务端在同一工作单元中创建加工母单、扣减备料、增加加工待加工余额并保存来源分配关系；失败全部回滚，重试回放同一结果。

此路径复用建单校验和编号能力，但不能调用会再次记实物入库的收货路径。已有加工母单补充领料，也须校验同客户、同物料及库存维度兼容性，不能把新增物料偷偷记成原母单首条材质。

本期先覆盖符合现有生产能力的单材质领用。一个寄存单含不同材质或单位时，可分别生成合法加工单；单件产品同时消耗多种原料的关系留到扩展阶段。若需直接创建多材质加工母单，应另按现有逐行收货及拆单分配契约逐项验证，不默认已支持。

### 6.3 两种“退”分别处理

| 操作 | 业务含义 | 必须校验 |
|---|---|---|
| 从加工单退回备料 | 未投入加工、仍可合法退回的物料，恢复原寄存来源 | 原领用关系、可退数量／重量、实际状态；已消耗或成品不能反向伪装成原料。 |
| 备料退还客户 | 未加工的寄存料实际离厂，交还客户 | 指定来源批次和可用量、接收／交接或物流信息；生成独立退还单。 |

现有通用转移命令要求目标维度，不能直接假定可用 `to = null` 执行物理出库；退还须设计明确的出库记账语义及查询排除规则，避免退还量仍被计入厂内实物。

## 7. 母单加工要求勾选与组合模板

### 7.1 模板内容

模板属于全厂共用的加工要求主数据，至少保存稳定编号、名称、有序步骤、启用状态、排序及版本。版本用于防止多人维护时静默覆盖，不承担生产路线版本的含义。

| 示例模板 | 有序步骤 |
|---|---|
| 常规珠型加工 | 开粗 → 车形 → 抛光 |
| 珠型雕刻加工 | 开粗 → 车形 → 雕刻 → 抛光 |

以上为创建时的示例，不是自动新增的正式报工路线。可以使用现有快捷词作为可勾选描述，也可以维护新描述；不能依赖正式工序白名单来校验这些短语。

模板步骤建议保存文字快照，快捷词改名或删除后已有模板仍可解释；模板本身通过显式编辑更新。停用模板后新建单不再提供，已有订单要求保持原文。

### 7.2 建母单时的交互

1. 选择模板或自行勾选步骤；已选步骤显示明确顺序，支持上下移动、取消及添加自定义描述。
2. 模板带入后只修改本次表单；修改共用模板须进入明确的维护动作。
3. 补充尺寸、形状、孔径、雕刻内容、表面效果等本单要求。
4. 页面展示最终写入母单的加工要求，提交前可检查和编辑；所见文本必须与实际保存文本一致。
5. 新建母单成功后显示保存结果。建单失败／超时重试沿用稳定请求编号，模板变化导致最终要求变化时应使用新的请求编号。

切换模板时替换“步骤”部分并保留本单补充说明；不重复追加步骤。用户已直接修改最终文本时，后续切换应先明确提示会覆盖哪些内容，不能悄悄重写。

建议最终要求采用自然语言顺序句，例如“先开粗，再车成珠型，最后抛光”，补充说明另起行。现有质检按换行拆条款，因此不能未经验证就把每道步骤强制拆成一条新的质检任务。具体条款仍由最终确认文本决定。

### 7.3 与现有链路的连接

- 正式字段继续使用 `processingRequirement`；最终文字随母单保存，拆出的子单按现有继承／覆写规则取得该单要求。
- 模板名称、步骤及合成要求设定明确长度限制，并与现有字段容量一致；超长时阻止保存并提示调整，不能截断后继续建单。
- 可附带记录选用的模板编号及版本作来源信息，但查询历史单据不得再用当前模板内容覆盖原要求。
- 现有扫码详情、标签、生产要求展示和质检读取同一份已保存要求。组合文字可能变长，需定向检查标签换行和溢出；不自动改变 40×30 mm 纸张或既有打印快照。
- 后续改变已建单要求，遵守现有改单、快照和财务确认规则，模板管理不能成为绕过业务改单的入口。
- 正式工序、工人授权和工序计费继续按既有业务配置执行。描述中出现“雕刻”，也不自动给该单新增一道正式雕刻工序。
- “从备料建加工单”复用这一选择组件；单纯寄存收货不要求选择加工模板。

## 8. 数据与服务改造建议

### 8.1 复用现有架构

库存仍统一使用 `StockLedgerService` 记账，跨单据、库存、来源关系与请求结果采用 `BusinessWorkUnit/WorkSession`。不新增前端自算库存账，也不另建一套可手工覆盖的余额表。

| 对象／能力 | 改造建议 |
|---|---|
| 独立收货单及明细 | 在现有库存领域补足公司／客户权属、来源、待核／确认状态、单位、实际量和证据关系；复用已有单据能力前核实能否表达无加工母单来源。 |
| 批次信息 | 使用现有批次身份，补来源行与单位；扩展时确保同一余额键不会混入不同单位。保留旧八段库存键的兼容读取。 |
| 领用、退回和退还记录 | 保存正式单号、来源操作／来源行、目标加工单或用途、数量重量及服务端操作人；不只写备注。 |
| 冻结及更正 | 复用既有可适用的冻结／冲正能力；独立备料须有明确的来源和范围，不能假定加工单冲正可直接套用。 |
| 加工要求模板 | 在现有 `business` 主数据的 `domain/app/infra/web` 四层增加命名、有序内容与维护能力，复用档案维护权限。 |
| 库存查询 | 修正小数、权属名称、批次与单位映射；余额和流水的过滤条件、权限和时间口径一致。 |

在新查询中使用明确业务类型和来源关系生成中文动作名称，优先展示业务操作单号。分页流水时，前后余额应来自可靠的期初／累计查询，不能只对本页流水从零累加；数据量较小时可继续复用当前完整授权流水计算，再按真实性能证据优化。

### 8.2 持久化与接口

- 内存与 JDBC 实现提供同样的业务语义。共享模板经服务端保存，不能只放浏览器 `localStorage`，否则电脑与手机不能共用。
- 新增业务写入必须包含 `requestId`，规范化内容须覆盖权属、来源、仓库、批次、单位、目标及数量重量等实际影响字段；相同请求号改内容或换账号应拒绝。
- 模板维护使用稳定编号和版本校验；新增操作须避免网络重试产生同名重复模板，重复停用返回可理解结果。
- API 路径和字段在实现时确定；本方案不把拟新增接口写成已经可调用。现有备料路径仍以 `/api/inventory/prep-stock`、快捷词以 `/api/business/master-data/requirement-shortcuts` 为入口参考。
- 已发布迁移保持原文，新迁移按实施时最大版本递增，同时登记类路径迁移索引与升级探针，不预占固定版本号。
- 仅实施后的现行接口和业务规则更新对应专题；本轮不把方案内容写成现行 API 契约。

## 9. 权限、并发与异常处理

库存查看、入库、领用、退回、实物退还、冻结及冲正应有明确动作权限。建议库管处理日常库存，财务和管理人员按职责查看；实物退还、冻结和冲正的具体授权在对应增量定义并测试。业务管理账号兼岗需按实际职责授权，不因持有客户查看范围就取得全部库存写权限。

新增业务权限不得通过向普通岗位授予通用库存转移权限实现。公司料查看沿用并核对现有角色口径；客户备料始终验证客户数据范围。界面隐藏按钮以外，服务端每次读取和写入均校验权限。

并发领用须锁定／原子校验来源余额，退回须同时保护原操作的累计可退量；更正须保护旧版本。多行提交任何一行失败，单据、库存、来源分配和请求结果全部回滚。HTTP 响应丢失后按原请求回放并返回原单号。

业务已成功、附件上传失败时保留原单和待补证据入口，只补附件。客户越权、冻结库存、余额不足、单位不兼容、来源不可追溯与服务故障均返回明确中文提示。

## 10. 任务拆分与实施顺序

库存与模板可以分别交付；每次选择当前必要的一个增量，按依赖串行合入。以下是可验收任务，不表示必须启动多个智能体。

| 编号 | 任务 | 主要完成标志／依赖 |
|---|---|---|
| I1 | 修正库存显示与查询口径 | 公司／客户权属准确，独立批次可见，小数与单位不丢失，错误和空数据分开；先核对历史单位来源。 |
| I2 | 公司自有物料页面 | 总览、筛选、批次详情和流水；复用现有查询，明确当前领用只表示转入在制。依赖 I1。 |
| I3 | 公司料正式出入库记录 | 入库单、原批次领用／退回、用途和人员追溯、业务权限及幂等；依赖 I1，完善 I2 动作。 |
| I4 | 客户寄存多明细收货 | 独立单据、待核到确认、多单位来源隔离、事务与持久化。依赖 I1。 |
| I5 | 客户备料管理与直接退还 | 来源批次详情、原领用退回、部分实物退还及凭证。依赖 I4。 |
| I6 | 从备料建加工单 | 来源分配、单材质建单与库存转移原子提交，不重复入库；复用已完成的加工要求组件。依赖 I4。 |
| I7 | 冻结、更正与历史对账 | 按实际规则补充独立库存冻结／冲正，历史缺来源记录可查且不能虚构回退。依赖相关库存单据。 |
| T1 | 加工要求模板主数据 | 新增、编辑、排序、停用、权限、版本及内存／JDBC 持久化；与库存任务无前置依赖。 |
| T2 | 建母单勾选与模板应用 | 模板、步骤勾选与排序、补充要求、最终文字预览、稳定重试；桌面／手机共用。依赖 T1。 |
| T3 | 模板下游与定向验收 | 母单、子单、扫码、标签和质检保持已保存原文，模板编辑不改历史。依赖 T2。 |

建议先完成 I1、I2，让自有库存先可看清；T1—T3 作为边界明确的独立增量尽早交付；随后补 I3—I7 的写入闭环。I1／I2 的页面完成不能代替 I3 的业务单据验收。

此前讨论过的 25—41 人日库存估算、额外 18—30 人日多材质生产估算，覆盖范围比“页面＋文字模板”更大，不作为本轮工期承诺。实际排期按上述任务及第 12 节现场规则细化；多材质生产另行估算。

## 11. 后续扩展范围

1. **盒位与二维码**：仓库、区域、货架、盒子档案，扫码查盒、放入、取出、移盒和负责人授权；要求“批次总量＝各盒量＋未上架量”。不能把现有仓库字段直接改成盒号。
2. **多种原料投入一件产品**：多来源领料、客户／公司权属隔离、成品独立身份、工序和质检、成本与收费及成品发货关系。未完成前，不宣称金料＋裸石＋公司配件的全过程核算已接通。
3. **公司料消耗、报废及成本结算**：依据现场规则形成业务单据和复核，库存耗用不能自动等同客户应收或工人工费。
4. **正式工序可配置**：只有以后明确提出将开粗、车形等作为正式报工工序时，才扩展工序目录、岗位授权、执行顺序和财务项目；本轮文字模板不触发该项。
5. **完整盘点与自有产品销售**：另立需求，不并入本轮页面改造。现有库存整理先以有来源的核对和受控更正处理。

## 12. 分阶段需要落定的现场规则

下列问题不阻塞库存只读页面和加工要求模板，但必须在对应库存写入上线前形成明确口径。

| 规则 | 方案默认与处理边界 |
|---|---|
| 哪些物料按颗／件，哪些必须称重 | 批次必须有明确数量单位；重量未知先待核，不填假值。允许零重量正式入库的物料范围需按现场确认，再统一各层校验。 |
| 公司领用何时算实际消耗 | 领用先登记用途和去向；未明确消耗及复核时机前，不自动核销已领用量。 |
| 多种原料是否经常做成一件产品 | 未取得明确事实前，本期按现有单材质生产能力接单；多投入成品关联另立增量。 |
| 原寄存料退还所需凭证 | 需要接收或交接信息；是否强制照片、签收或物流，按实际交付方式定义。 |
| 冻结与冲正由谁办理 | 普通余额不可编辑；在相关动作实施前按现有角色和兼岗确定权限，不自行设置审批金额或重量门槛。 |
| 开粗、车形等描述的现场名称 | 默认提供“开粗、车形、雕刻、抛光”示例，允许有档案维护权限的人员调整描述和模板。 |

## 13. 验收场景与最小充分验证

| 场景 | 应达到的结果 |
|---|---|
| 公司料单批入库 10.500 克，领用 4.250 克，原单退回 1.125 克 | 库内未领用量为 7.375 克，已领用未退回为 3.125 克，来源、人员和用途可追；不被截成整数。 |
| 客户甲寄存 100 克金料和 20 颗裸石 | 两条独立来源及单位，展示不合并成 120 件；不创建生产待办或加工费。 |
| 从 100 克寄存金料中领用 30 克并建加工单 | 备料剩 70 克，加工待加工 30 克，合计没有增加；新母单关联原批次领用，不再收一次货。 |
| 退还剩余备料中的 10 克 | 来源批次再减少 10 克，生成正式退还单，厂内实物排除已退还部分；不伪造成品发货。 |
| 同请求连续点击／响应丢失重试 | 一笔库存变动、同一个业务单号；内容变化或换账号不能回放别人的结果。 |
| 两人同时领同一批剩余库存 | 合计不透支数量或重量，失败请求无残留单据和来源分配。 |
| 多行确认时中间一行失败 | 所有行、库存、单据和请求结果均回滚。 |
| 客户范围账号访问其他客户，或普通账号访问公司料 | 服务端拒绝，页面不显示越权余额和流水；不能通过改批次／单号绕过。 |
| 普通库管执行获授权库存动作 | 专门业务接口允许对应动作，通用任意库存转移仍受原权限保护。 |
| 冻结批次、退回超原领用量、历史来源缺失 | 阻止非法写入，显示可理解原因；不补造历史入库或领用。 |
| 选“常规珠型加工”，再改为“珠型雕刻加工” | 步骤按模板顺序变化，补充说明保留，不重复追加，预览与保存文本一致。 |
| 保存模板后建单，再编辑／停用该模板 | 新单使用新内容或不再提供，已建母单、已拆子单与已生成标签快照保持原要求。 |
| 仅选择开粗、车形等描述 | 产生母单文字，不新增正式岗位、工序交付、工资或计费记录。 |
| 手机 320／375 像素宽度查看与建单 | 列表、表单和模板勾选不横向溢出，按钮与提示可读。 |

按实际增量执行定向验证：查询与金额精度验证对应 DTO／服务和页面；库存写入覆盖正常、失败、并发、幂等和越权；模板覆盖持久化、多人版本冲突、文字生成及历史快照；迁移验证仓储与升级发现。JDBC 验证需注明使用 H2 兼容模式还是真实 MySQL，不能混称。

不把前后端全量测试、生产构建和打包设为每次增量前置条件。涉及标签文字布局时做定向预览；实机出纸等结果单独记录。发布时按实际迁移完成备份和升级验证，文档完成不等于发布完成。
