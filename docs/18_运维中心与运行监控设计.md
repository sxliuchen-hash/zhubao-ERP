# 运维中心与运行监控设计

**文档版本**：V1.0  
**更新日期**：2026-07-07  
**适用阶段**：M3.49 运维中心 PWA 探活与运行控制台视觉层

---

## 1. 目标

运维中心用于在评审和试点阶段集中查看：

- 后端 API、前端 PWA、数据库、附件存储、软硬件联动的运行状态。
- JVM 内存、线程数、CPU 核心、后端运行时长等服务器指标。
- 报错汇总、最近日志、责任人和下一步动作。
- 数据库备份状态、最近成功时间、下次应完成时间、备份目录和恢复演练口径。
- 运维接入清单，明确哪些已真实探测，哪些仍是评审样例。

本阶段不在页面执行备份命令，不暴露完整日志文件下载，不开放原始 Actuator 端点给普通业务页面。

---

## 2. 参考依据

- [Spring Boot Actuator Endpoints](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html)：用于健康检查、指标、loggers/logfile 等运维端点设计参考。
- [Micrometer Concepts](https://docs.micrometer.io/micrometer/reference/concepts.html)：用于统一指标模型和 MeterRegistry 思路参考。
- [MySQL mysqldump](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html)：用于数据库逻辑备份口径参考。

本项目当前实现为业务聚合 API：`GET /api/operations/center`，不是直接把所有 Actuator 端点暴露给前端。

## 3. 当前实现

### 3.1 后端

新增模块：

- `OperationsCenterSnapshot`
- `OperationsCenterService`
- `OperationsCenterController`

接口：

```http
GET /api/operations/center
```

返回内容：

- `summary`：总体状态、服务数量、降级服务、错误数、备份状态、运行时长。
- `services`：后端、前端、数据库、备份、附件存储、硬件 POC 状态。
- M3.48 起，`services` 增加 `PWA_ASSETS`，用于检查 `manifest.webmanifest` 和 `sw.js` 是否可通过前端探活地址访问。
- `runtimeMetrics`：JVM 内存、线程数、CPU 核心、后端运行时间。
- `errorSummaries`：报错汇总、责任人、下一步动作。M3.47 起，配置日志文件后优先从 WARN/ERROR 日志聚合生成；未配置时保留评审样例。
- `recentLogs`：近期日志。M3.47 起，配置 `log-file` 后读取日志文件尾部记录，按内容识别视频截取、数据库备份、登录权限、数据库连接、附件对象存储等来源；未配置日志文件时返回明确标注的评审样例。
- `backupStatuses`：数据库备份状态。未配置备份目录时返回待配置状态。
- M3.43 起，配置 `backup-root` 后会对最新 `.sql/.dump/.backup/.gz` 文件计算文件大小和 SHA-256 checksum；备份文件超过 `backup-rpo-hours` 时状态降级为 `超过 RPO`。
- M3.45 起，前端服务状态不再只展示配置 URL，可配置 `frontend-probe-url` 由后端发起 HTTP/HTTPS 探活；本地评审默认不探活，Docker 运行默认探测容器内 `http://frontend/`。
- M3.47 起，配置 `log-file` 后，运维中心会读取日志文件、展示近期日志，并将 WARN/ERROR 聚合到 `errorSummaries`；读取失败或路径错误会生成日志来源异常。
- M3.48 起，基于同一个 `frontend-probe-url` 检查 `manifest.webmanifest` 和 `sw.js`，用于区分前端站点可访问但 PWA 静态资源缺失的情况。
- `checklist`：运维接入清单。

### 3.2 前端

新增：

- `operationsCenterData.ts`
- `operationsCenterApi.ts`
- `OperationsCenterWorkspace.vue`

导航新增：

- `OC 运维中心`

页面覆盖：

- 运维中心总览。
- 前后端/数据库运行情况。
- 服务器运行指标。
- 报错汇总。
- 近期日志。
- 数据库备份情况。
- 运维接入清单。

M3.49 起，前端视觉层统一到现场控制台风格，运维中心首屏保留服务、报错、备份、运行时间四类核心指标，并通过深色焦点面板突出当前异常服务和下一动作；该调整不新增后端接口。

## 4. 配置项

```yaml
zhubao:
  operations:
    frontend-url: ${ZHUBAO_FRONTEND_URL:http://localhost:5173/}
    frontend-probe-url: ${ZHUBAO_FRONTEND_PROBE_URL:}
    frontend-probe-timeout-ms: ${ZHUBAO_FRONTEND_PROBE_TIMEOUT_MS:800}
    backup-root: ${ZHUBAO_BACKUP_ROOT:}
    log-file: ${ZHUBAO_LOG_FILE:}
    backup-rpo-hours: ${ZHUBAO_BACKUP_RPO_HOURS:24}
```

说明：

| 配置 | 默认 | 说明 |
|---|---|---|
| `frontend-url` | `http://localhost:5173/` | 运维中心展示给用户的前端访问地址 |
| `frontend-probe-url` | 空 | 后端实际探测的 HTTP/HTTPS 地址；Docker 默认 `http://frontend/` |
| `frontend-probe-timeout-ms` | `800` | 前端探活连接和请求超时时间，最小按 200ms 处理 |
| `backup-root` | 空 | 数据库备份目录，只读扫描 `.sql/.dump/.backup/.gz` |
| `log-file` | 空 | 只读日志文件路径；配置后读取尾部日志并聚合 WARN/ERROR |
| `backup-rpo-hours` | `24` | 备份 RPO 提醒窗口 |

前端地址分工：

- `frontend-url` 面向用户和运维人员，例如 `http://localhost/` 或现场局域网域名。
- `frontend-probe-url` 面向后端运行环境，例如 Docker Compose 网络内的 `http://frontend/`。
- 本地开发默认 `frontend-probe-url` 为空，运维中心显示 `NOT_CONFIGURED`，避免后端单元测试或未启动前端时被误判为生产宕机。
- PWA 静态资源探活复用 `frontend-probe-url`，检查路径为 `manifest.webmanifest` 和 `sw.js`；当前只证明静态资源存在和内容结构基本有效，不等同于完整离线缓存验收。

备份证据字段：

| 字段 | 说明 |
|---|---|
| `fileSize` | 最新备份文件大小，例如 `10 B`、`3.25 MiB`；未接入目录时显示 `未计算` |
| `checksum` | 最新备份文件 SHA-256，例如 `sha256:<hex>`；用于部署交付和恢复演练时核对备份文件 |

5. 增加告警阈值和通知渠道，例如短信、企业微信或邮件。
6. 将运维中心纳入试点上线验收用例。
