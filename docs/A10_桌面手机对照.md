> 2026-10-20。从提交 `64acd7c` 只读对照，分支 `codex/a10-client-parity`。范围是[架构升级总方案](./架构升级总方案.md)的 A10，以及[项目核心](./00_项目核心.md)技术债表中「桌面和手机对上述权限、冲正、打印边界还没有逐项对照」。没有改页面、后端和数据库迁移。没有真机，本文不是手机验收。工作区里未提交的安卓壳和云端脚本不纳入对照。

## 对照方法

桌面和手机是同一套网页。宽度不超过 900px、账号属于现场岗位、并且能看到手机作业菜单时，登录后从工作台进入[现场作业](../frontend/src/features/m1/MobileOpsWorkspace.vue)。「全部功能」打开的来料、生产、质检、库存、标签、运维，与桌面菜单是同一组件。

现场作业的收货、报工、质检、发货分别挂 [IntakePanel](../frontend/src/features/intake/IntakePanel.vue)、[ProductionPanel](../frontend/src/features/production/ProductionPanel.vue)、[QualityPanel](../frontend/src/features/quality/QualityPanel.vue)、[ShippingPanel](../frontend/src/features/shipping/ShippingPanel.vue)。桌面来料、生产、质检、库存页挂的也是这四个面板。手机给前三个加上 `field`，发货面板没有这个参数。

四项都核对过：是否调用同一服务、必填是否一致、失败后是否复用请求编号、同码多单是否必须人工选择。下面只写分叉。没有点名的提交，这四项一致。

## 差异

### 岗位报工：现场作业多一道本地核对

桌面生产页不传 `field`。点提交就调用 `submitProcessStation`，请求是单号、工序名和 `requestId`，接口为 `POST /api/business/operations/process-stations`。

现场作业传入 `field`。`deliver` 在该工序尚未完成本地核对时直接返回，不发请求。勾选加工要求只留在页面，不进入请求体。没有单独列出的要求时，看过当前单即可进入确认。桌面没有这道拦截。

除此以外两端相同：失败后同一单号和工序沿用原 `requestId`；母单已拆时扫码停住，提示选择子单，不取第一条。

### 现场作业没有来料确认、拆单、损耗、退货和数量冲正

这些动作不在现场作业里。手机从「全部功能」打开对应页面时，与桌面是同一个组件，不是另一套服务。

| 动作 | 页面 | 提交 |
|---|---|---|
| 确认入库 | 来料页 | `confirmInbound`。失败沿用 `inboundRequestId` |
| 不拆 / 拆单 | 来料页 | `MotherSplitPanel`。失败沿用原请求编号 |
| 损耗申请 | 质检页 | `approveLoss`。请求里没有 `requestId` |
| 退货、售后 | 库存页 | 与发货确认分开 |
| 未拆单母单数量、重量冲正 | 运维页，且仅管理员 | `OrderMaintenanceService.reverseReceiptEntry` |

冲正在服务端判断：母单尚未拆单、交付、发货或形成财务记录，且只有一条收货流水时，先冲正原流水，再按新数量和重量追加收货流水。客户、材质、货品仍拒绝直接覆盖。页面不按桌面或手机分叉。查找出多条时每条单独保存，不自动改第一条。失败后按内容指纹复用 `requestId`。

发货确认本身没有分叉。库存页和现场作业都用 `ShippingPanel` 调用 `shipFinishedStock`。出库单号、物流单号、数量、重量必填；多笔余额时必须点选完整维度，不默认第一笔。失败后按指纹复用 `requestId`。

收货建单也没有分叉。两端都调用 `submitMobileIntake`，接口为 `POST /api/business/operations/mobile-intakes`。客户、加工要求、期限、材质、货品、数量和重量的校验不看 `field`。失败后内容不变就沿用原 `requestId`。同一运单对应多张母单时必须点选，或明确选择运单再建一张。

质检提交没有分叉。两端都调用 `submitQualityCheck`，接口为 `POST /api/business/operations/quality-checks`。每一条都要有结果，不合格和让步必须写原因；`field` 只是逐条翻页，不减少提交字段。开返工、返工报工、复检和放行同样复用各自的 `requestId`。已拆母单必须选择子单。

### 手机订单详情少展示客户名称

授权没有分叉。扫码使用会话里已经收成编号的客户范围。收货、报工、质检、发货写入使用同一次会话范围。列表查询优先用登录会话，页面不另传一套客户范围。

[手机订单详情](../frontend/src/features/m1/MobileOrderDetail.vue)只给收货岗画出客户和重量。操作工、质检员打开详情时这两项不出现。扫码响应里仍有客户名称，进入报工或质检面板后仍显示。这不改变能办理哪些客户的单据。

## 打印失败提示

没有按端分文案。标签页是同一个 [LabelWorkspace](../frontend/src/features/m1/LabelWorkspace.vue)。`FAILED` 显示「发送前失败」，`UNCERTAIN` 显示「不确定是否出纸」，具体原因用任务上的 `failureReason`。提交到打印工位失败时，页面显示接口返回的消息；内容没变就复用 `requestId`。浏览器预览打印走 `openLabelPrint`。隐藏框架打不开时函数直接返回，桌面和手机都没有失败提示。没有标签机，这些文案不能当成已经出纸。

同码多单：收货、报工、质检、发货在需要选择时必须点选，未选择前不能提交。标签页若服务端已经带上母单号，会先打开该母单标签，并允许再选子单。这条例外两端相同。
