---

## 1. 当前状态

截至 M3.114，本项目仍处于一期开发推进和内部验证阶段，尚未形成第一个可交付给客户的正式版本。

当前已有的运行包、页面和接口可用于内部评审、现场规则确认、脱敏样例验证和试点前准备；不得把评审 seed 账号、账号表与密码哈希边界、登录失败锁定/启停/解锁/密码策略/密码过期检测/登录态自助改密/认证审计摘要链边界、业务工作台 GET 首版数据范围过滤、账号管理审批摘要、请求头身份兜底开关、账号客户范围及其可视化、账号前置审批申请单、申请单号显式校验、生产配置强制申请单号开关、申请单审批任务交接和审批通过态校验、硬件 POC 记录仓储可切换、硬件 POC 证据只读关联、内存菜单树、样例数据或局部业务闭环描述为生产已上线。

## 2. 版本记录规则

形成首个客户交付版本时，必须新增一条版本记录，并至少包含：

| 字段 | 说明 |
|---|---|
| 版本号 | 建议格式 `v0.1.0-customer-preview`、`v1.0.0-pilot` 或客户约定版本号 |
| 交付日期 | 实际交付给客户或试点环境的日期 |
| 交付形态 | Docker 离线包、云服务器部署、本地服务器部署或演示环境 |
| 包含范围 | 已交付模块、接口、页面、脚本和文档 |
| 验证证据 | 后端测试、前端测试、构建、运行包验收、浏览器验证、备份恢复演练 |
| 已知限制 | 尚未完成或不允许客户按生产使用的边界 |
| 升级说明 | 从上一版本升级的数据库、配置、运行包和回滚说明 |
| 客户可见变更 | 用非技术语言说明客户能看到的功能变化 |
| 后续计划 | 下一版要解决的事项 |

---

## 3. 首个客户版本准入条件

首个客户交付版本至少应满足：

- `docs/22_真实数据与上线待确认清单.md` 的 P0 项已有明确结论或试点边界。
- 核心业务闭环使用脱敏真实样例跑通，并保留测试或验收证据。
- 权限侧不再依赖演示明文密码；至少明确生产账号、角色、菜单和数据范围方案。
- 运行包通过无源码交付验收，客户部署不依赖开发目录、`.git`、前端源码或测试代码。
- 备份与非破坏性恢复演练至少完成一次，并保存 checksum 与 JSON 记录。
- 客户可见限制写入版本记录，避免把试点能力误认为完整生产交付。
