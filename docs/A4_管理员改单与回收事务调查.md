# A4 管理员改单与回收事务调查

> 2026-10-19 首个 A4 增量。仅核对源码并对测试服务器 V63 运行库执行只读聚合 SQL；没有修改业务数据。A4 全部动作范围和验收条件见[架构升级总方案](./架构升级总方案.md)。

## 1. 页面到写入的链路

| 动作 | 页面／API → 服务 → 仓储 | 当前边界 |
|---|---|---|
| 母单、子单改正 | [运维页改单面板](../frontend/src/features/m1/OrderMaintenancePanel.vue) → [前端 API](../frontend/src/services/orderMaintenanceApi.ts) → [控制器](../backend/src/main/java/com/zhubao/erp/business/web/OrderMaintenanceController.java) → [OrderMaintenanceService](../backend/src/main/java/com/zhubao/erp/business/app/OrderMaintenanceService.java) → 单据仓储 | 要求管理员和原因，但请求没有 request ID、版本或预期值。服务先覆盖主单字段，再写 `biz_order_adjustment` 文本记录。JDBC 仓储两步各自新开自动提交连接，第二步失败时前一步不会回滚。 |
| 回收母单／子单 | 同一页面、API、服务 → 单据仓储、旧打印仓储、目标打印仓储 | 母单回收依次标记母单、子单和相关打印任务；恢复按批次依次清标记。各仓储新开连接并各自提交，某一步失败会留下部分回收或恢复状态。库存流水、余额、财务记录和附件没有同步冲正。 |
| 打印任务改正 | 同一页面、API、服务 → 旧打印仓储或目标打印仓储、单据调整仓储 | 打印份数、工位或队列覆盖写入后再记文本调整；两次写入无共享事务。已领取目标任务也允许改目标，出纸及队列侧状态需要单独确认。 |

V62 迁移仅追加回收标记与 `biz_order_adjustment`；不提供业务版本或幂等约束。`BusinessWorkUnit` 能处理采用 `WorkSession` 的命令，但此服务目前不使用它；给服务外层增加普通事务注解也无法自动接管仓储内新开的 JDBC 连接。现有[单元测试](../backend/src/test/java/com/zhubao/erp/business/app/OrderMaintenanceServiceTest.java)覆盖管理员权限、成功改正及回收恢复，未覆盖审计写入失败、跨仓储中途失败、重复或并发提交。

## 2. 测试服务器只读样本

运行[可复跑聚合 SQL](../scripts/a4-maintenance-readonly-audit.sql)，`START TRANSACTION READ ONLY`；只输出计数，不输出客户或单据内容。

| 项目 | 结果 | 解释 |
|---|---:|---|
| 母单／子单／旧打印任务／目标打印任务 | 3／2／1／0 | 现有回收链只有少量单据，目标打印任务无样本。 |
| 调整记录／四类回收标记 | 0／均为 0 | 测试库尚无真实改单或回收动作，无法从当前数据证明成功或失败路径。 |
| 已回收母单下可见子单、已回收业务单下可见打印任务、母／子单调整孤儿 | 均为 0 | 仅代表当前样本不存在这些不一致；没有失败注入或并发验证。 |

## 3. 已证实风险与下一步

| 发现 | 证据级别及数据影响 | 建议顺序／进入实现条件 |
|---|---|---|
| 改单覆盖字段与审计记录非原子 | 源码已证实：JDBC 两次独立提交；若第二次失败，业务值已变而无调整记录。当前测试库未观察到实例。 | **P0 首个修复增量。**先让母／子单改正及调整记录共用同一 JDBC 连接，失败注入验证回滚；补请求编号、内容冲突和并发策略时避免重复覆盖。 |
| 已入账数量、重量、材质、客户可直接覆盖 | 源码已证实覆盖，不修改引用的库存流水、余额、财务和来源分配；造成何种差额取决于具体单据，当前测试库无改单样本。 | **P0 设计与保护。**按是否已入账区分允许的描述改正和需差额／冲正的事实调整；明确历史兼容及页面提示，再放行金额或库存字段的实作。 |
| 整单回收跨三仓储非原子 | 源码已证实逐步独立提交；失败后可能只隐藏部分单据或打印任务。当前测试库无回收样本。 | **P0 后续独立增量。**设计共享会话、批次幂等及可恢复补偿，注入各阶段失败，核对库存／财务仍留存时的用户可见性。 |
| 外部打印设备状态 | 当前只核代码与数据库，未实测设备队列及纸张。 | **待现场决定。**以实际打印批次核对领取、排队、出纸和改派；数据库状态不能代替纸张验收。 |

本调查不改变既有改单行为。下一小增量先解决“业务单据覆盖与调整记录”在 JDBC 下的原子性；回收链和入账冲正另列独立增量，避免一次跨越多个业务边界。
