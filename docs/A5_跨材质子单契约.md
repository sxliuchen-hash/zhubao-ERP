# A5 跨材质子单契约

> 2026-10-20。基线提交 `64acd7c`。本文只记录契约结论。不改业务代码，不改 `docs/00_项目核心.md`，不改数据库迁移。

## 1. 结论

继续拒绝一张子单混用多种材质。多种材质停在母单的收货行上，按材质拆成多张子单。同一母单的数量单位必须相同。

在制余额按「子单 + 材质」分开。应收、工资和改单差额按「子单 + 工序」各记一行，单价也只按工序。没有一行能同时说明某种材质的库存和这笔金额。写不出这种行，就不放开，也不先改代码。

## 2. 现行行为

| 位置 | 规则 |
|---|---|
| 母单 | 每种材质一条收货行，各自一笔待加工库存。母单头上的材质是第一行。各行数量单位必须相同，母单数量和重量等于各行合计。 |
| 不拆 | 收货明细多于一种材质时，不能整单不拆。 |
| 子单 | 一张子单的来源行只能有一种材质。两种材质同时分配时拒绝，不产生子单，也不产生这次拆单的库存流水。 |
| 同材质多行 | 可以进同一张子单。每条来源各有一笔转入在制的流水，库存维度相同，余额合在一起。子单头保存这一种材质、合计数量和重量、母单的数量单位，以及第一笔流水号。来源多于一行时，货品名称写成「多材质」，材质编码仍是这一种。 |
| 下游 | 工序、质检、发货、应收和工资都读子单头上的一种材质、一组数量和重量。库存转移不能改变物料。工序交付的数量和重量必须等于子单头整单。 |

`MultiMaterialIntakeSplitTest` 已覆盖：同一母单两种材质分别入账；一张子单同时分配两种材质被拒绝，且不产生子单和额外库存流水；按材质拆开后，来源行剩余数量可核对。

## 3. 现有的行

| 名称 | 身份 |
|---|---|
| 收货行 | 母单行号。一种材质、一个数量单位、数量、重量、一笔待加工流水。 |
| 分配行 | 子单号 + 收货行号。抄下该行材质、本次数量和重量、转入在制的流水号。 |
| 子单头 | 子单号。一个材质编码、一个数量单位、合计数量、合计重量、工序列表、第一笔在制流水号。 |
| 在制余额 | 权属、客户、母单、子单、材质、仓库、状态。同一子单的两种材质是两笔余额。 |
| 工序交接 | 子单号 + 工序名，只记一次，上面一个流水号。 |
| 质检 | 质检单号 `QC-` 加子单号，上面一个流水号。冻结按该材质的半成品余额整笔转出。 |
| 发货 | 发货单号。命令里一个材质、一组数量和重量，对应一笔成品转已发的流水。 |
| 应收 | 来源键 `PROCESS\|子单号\|工序`。按次数量为 1，按克取子单头重量，按件取子单头数量。客户协议里同一道工序只有一条单价。行上没有材质、收货行号或流水号。 |
| 工资 | 来源键 `PAY\|子单号\|工序`。数量来源与应收相同。损耗扣款按子单号和工序名。 |
| 改单差额 | 增额 `CHANGE\|改单号\|工单\|工序`，数量为 1。减额红字 `CHANGE-RED\|改单号`。工资调整 `PAY-ADJ\|改单号`。这些键没有材质或收货行号。 |

## 4. 放开时各自要引用的行

| 事项 | 要分别解释每种材质，必须引用 | 现行记录实际引用 | 能否闭合 |
|---|---|---|---|
| 子单头 | 只标识子单号、母单、客户、要求、期限和工序列表 | 第一种来源材质、合计数量和重量、第一笔流水 | 合计数量不属于单独一种材质的在制余额 |
| 来源行 | 分配行引用收货行号，材质以该收货行为准 | 拆单已经这样写，并拒绝两种材质 | 能对上收货行 |
| 剩余量 | 该收货行的数量和重量减去已分配 | 已经按收货行号 | 能对上收货行，不进入账单 |
| 在制流水 | 该分配行自己的流水，余额按该行材质 | 分配行有流水号；子单头只留第一笔；后续工序不读分配行流水 | 两种材质是两笔余额 |
| 工序 | 每一次库存转移引用其中一笔在制余额 | 子单号 + 工序；物料和整单数量都来自子单头 | 第二笔在制没有交接 |
| 质检 | 冻结、返工、放行引用其中一笔材质余额 | 子单头上的一种材质，以及该维度上的全部半成品余额 | 结果落不到另一种材质 |
| 发货 | 一次出库引用其中一笔材质余额 | 命令中的一个材质和一组数量 | 指向不了另一条来源 |
| 账单 | 每一笔金额引用决定该数量的分配行，并引用该材质的单价 | 子单号 + 工序；数量来自子单头；单价只按工序 | 见第 5 节 |

来源行、剩余量和在制流水可以按收货行分开。工序、质检和发货要跟这三行对齐，就得各自点名一笔材质余额。账单点不了这行。

## 5. 账单解释不了

客户协议里，同一道工序只能有一条单价，单价不按材质。月度应收见到已有的 `PROCESS|子单号|工序` 就不再记。工资来源键同样只到子单和工序。改单加收、红字和工资调整按改单号或「工单 + 工序」记一笔金额。

下面三种算法都会把金额和在制流水拆开，本文都不采用：

1. 账单继续用子单头。头上的件数或克数是几种材质的合计。工序只能按头上的一种材质转移这个合计，第一种材质的余额对不上，其余材质没有被这笔金额解释。
2. 每种材质各记一笔，仍用现在的工序单价。协议没有规定第二种材质是否适用这一单价。按次计价时，一张子单记 1 次，还是每种材质各记 1 次，金额不同。现行来源键也放不进第二笔。
3. 账单仍按子单和工序记一笔，库存按分配行分成多笔。退货、冻结、损耗扣款和改单差额都说明不了扣的是哪一种材质。

第 4 节的账单一行因此空着。继续拒绝跨材质子单。

## 6. 明确不处理

- 不新增或修改数据库迁移，不改子单头字段的含义。
- 不改 `docs/00_项目核心.md`。
- 一张母单里的多种材质，仍按材质拆成多张子单。每张子单一种材质，下游继续认该子单头。
