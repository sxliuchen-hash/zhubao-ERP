## 2. 操作方式

1. 在当前项目中选用你要使用的开发模型，不需要给它重讲全部历史。
2. 先发送下方启动提示词。第一次只执行 UI-01。
3. 检查本段结果、截图、测试和提交；合格后再发送下一段，不一次让模型执行整个列表。
4. 不必把所有提示词和设计文档全文粘贴进对话。让模型读共同基调、当前任务及指定代码即可。

```text
请在 F:\APPkaifa\zhubao-ERP 中执行 UI-01。
先读取 AGENTS.md、docs/ui-prompts/00_固定基调.md、docs/ui-prompts/UI-01_主题基础.md，按这三份要求直接完成本段开发。
开始前检查 git status，保护已有未提交改动。当前任务之外的提示词不用通读。
不要重新规划风格，不要新增组件库，不要实现财务接口，不要自动继续 UI-02。
完成开发、验证、文档同步和本段独立提交后，按固定基调规定的格式报告结果并停止。
```

以后把任务编号和文件路径换成当前段，例如：

```text
继续执行 UI-02。读取 AGENTS.md、docs/ui-prompts/00_固定基调.md、docs/ui-prompts/UI-02_外壳与导航.md。
先检查 UI-01 的实际提交和完成条件，满足后直接完成 UI-02；不要自动推进其他任务。
```

## 4. 第一版的明确裁剪

- 财务只做已有账务能支撑的经营分析。收入、成本和趋势按选择月份；未收、应付和客户排行显示「截至当前」，返回实际 `asOf`，不伪称历史月末余额。
- 第一版不新增账龄、预算、净利润、完整现金流、银行账户余额、历史余额回放和成本分摊模型。后续需要时另排任务。
- 第一版移动导航使用已有能力：「工作台、现场作业、审批、更多」，按授权裁剪。「更多」打开当前用户有权访问的业务入口；不造空消息中心或假任务入口。
- 第一版不新增 vue-router、第三方 UI 组件库或跨端应用工程。保留现有 `activeTab`、菜单编码和业务命令；后续深链接与平台适配另做。
- 开发截图需要真实接口或明确标注的测试环境数据；正式运行页面不能保留概念图样例。

这些是将整体规划落成第一版任务的范围约束，不取消后续多端路线。

## 5. 模型偏离时的纠正提示词

```text
当前结果偏离了已经确定的基调。请只修正当前任务，不扩展范围：
1. 重新读取 docs/ui-prompts/00_固定基调.md 和当前任务文件。
2. 对照本段完成条件，列出最多 5 项实际偏差并直接修正。
3. 不新增依赖，不重写业务服务，不塞入演示数据，不把未实现入口做成可点击空按钮。
4. 重点检查手机无横向溢出、金额与状态层级、权限范围及真实失败状态。
5. 验证修正涉及的行为；按 AGENTS.md 完成本段检查与提交。给出修正后的截图和证据，不继续下一任务。
```

## 6. 验收或交接提示词

```text
请只验收刚完成的 UI 任务，不开始下一段。
对照任务文件逐项核对，检查实际差异、测试结果和电脑／手机截图；特别核对真实数据、服务端授权、缺项与失败状态。
输出「已满足／未满足／未验证」三类结论，每个问题给出文件位置和复现步骤。不能用测试总数代替具体任务验收。
如有本段引入的缺陷，直接修复并验证；基线未通过不得提交或宣称完成，不修与本段无关的现有问题。
最后更新当前任务状态，记录本段提交号、验证证据和下一任务编号，停止。
```
