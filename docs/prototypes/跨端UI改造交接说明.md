## 建议的实施增量与验收点

| 增量 | 主要范围 | 本增量应验证的事实 |
|---|---|---|
| A：跨端上下文与手机导航 | `App.vue`、`AppShell.vue`、`MobileOpsWorkspace`、扫码目标桥接；按需抽取共享状态 | 现有菜单权限过滤、底栏扫码、单号与对象类型正确、桌面入口未回归 |
| B：统一列表与详情 | 首页、进度、来料／生产／质检列表的相关查询消费方，统一单据详情组件 | 筛选范围一致、母子单／轮次清楚、同码选择、迟到响应不串单、返回保留筛选 |
| C：现场业务表单 | `IntakePanel`、`ProductionPanel`、`ProcessProgressPanel`、`QualityPanel`、`ShippingPanel` | 现有提交契约、要求确认、失败恢复、幂等、证据关联及各自业务边界 |
| D：标签、附件、客户与财务关联入口 | 标签、证据、客户、库存和财务的相关直接调用链 | 保持正确对象；不会因换位置重新开单、改账、重新打印或泄露金额 |
| E：桌面布局（确认后） | 同一共享上下文上的表格、筛选、侧栏、表单；工具与系统管理 | 1024／1366／1440 等宽度、列表表单分离、岗位视图、原有 17 项能力入口可达 |

各增量可按真实依赖拆小。跨端上下文和查询契约未稳定前，不并行改同一文件；先提交已验证的小节点，再继续下一步。

## 用户验收应关注什么

- 不需要猜该进“现场作业、生产还是进度”，从同一张单能找到本岗下一步。
- 手机扫码后不反复手输单号；电脑筛选后能保持当前列表与正确单据。
- 进度到 100% 后仍能清楚区分正式交工、质检与放行。
- 保存收货后打印的是刚生成的母单，不是先前浏览的其他单据。
- 客户账单登记的是当前客户与账期；库存发货对应选中的可发维度。
- 切换角色、客户、列表或单据后不泄露旧数据，提交目标不串单。
- 合并入口后，原来必需的退货、复检、补打、核纸、导入、备份等能力仍能找到。
