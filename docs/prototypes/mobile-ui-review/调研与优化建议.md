# 手机端 UI 调研与优化建议

日期：2026-10-23。状态：**供用户确认的界面提案，尚未实施产品改造。**

2026-10-23 用户反馈“我觉得很好”，已认可手机稿整体方向；本轮继续补充桌面稿与 [Grok 实施交接说明](../跨端UI改造交接说明.md)，尚未改造正式业务页面。

效果稿：[打开可交互 HTML](./index.html)。浏览器直接打开即可使用，不依赖后端或外部资源。手机打开显示完整手机界面；电脑打开显示页面导航、手机预览和调整说明。

## 调研依据与边界

按当前工作区 `frontend/src/App.vue` 的 17 个导航页面，检查其页面模板、直接复用组件和手机布局规则。重点追踪 `AppShell`、`MobileOpsWorkspace`、`MobileOrderDetail`、`ScanInput`、`IntakePanel`、`ProductionPanel`、`ProcessProgressPanel`、`QualityPanel`、`ShippingPanel` 及库存、客户、财务、标签页面。

本次是静态源码调研与独立原型的浏览器验证，没有登录线上业务系统，没有操作真实客户单据。工作区包含多项已有未提交改动，调研以本地当前代码为准，不把本地能力推定为线上已发布能力。下文的“繁琐”是对入口与信息结构的判断，没有真实用户耗时或点击埋点，不能据此宣称已经提升了某个比例。

## 当前主要问题

1. **同一业务存在多个入口。** 手机按授权常驻“工作台／现场作业／审批／全部功能”，工作区还在增加独立底部扫码键，而全部功能又能打开来料、生产、进度、质检、库存。现场页复用这些页面里的提交面板，用户需要先判断该进哪个模块。
2. **同一张单的上下文分散。** 手机详情可以带单号进入报工或质检，但目标面板仍保留自己的扫码、查找、要求与证据区。带入目标不等于强制再次扫码，不过视觉上仍反复出现完整定位表单。
3. **列表与大表单同时出现。** 来料、生产、质检在业务池之前先放提交面板；进度页同时出现进度表单、查询列表和改单内容；库存的加工库存／流水区域中还挂着发货面板。手机需要经过较长页面才能到列表或当前事项。
4. **日常操作和配置挤在一起。** 标签页并列现场贴纸、通用生成、按母单生成，管理员还看到队列和模板维护。设备、运维、附件页保留了较多桌面控制台结构。
5. **关联资料需要跨模块寻找。** 客户档案已经有账单和进度，但收款在财务、标签在标签页、附件又有独立管理页。可以通过共享详情减少跳转，而不是重复制作业务规则。
6. **已有响应式调整主要解决适配。** 当前确有手机卡片、折叠筛选、列表与详情切换，以及 900px 下的岗位入口过滤；仍有多种表格保持至少 640px 宽。下一轮重点应是信息结构和操作顺序，而不仅是继续缩小按钮。

## 拟议手机导航

常驻入口：**待办、订单、扫码、库存、更多**。库存只在账号有相应菜单和读取权限时显示。其余入口也继续按真实菜单与权限过滤。

- **待办：** 汇集本岗业务作业、轻任务和待审批事项，保留明确类型；不设置跨类型通用“完成”操作。
- **订单：** 合并手机端的找单、在制进度与作业池入口；默认筛选按岗位和账号范围确定。
- **扫码：** 公用定位入口；订单、母单、运单及执行轮次识别后打开正确对象，同码多单先选择。
- **库存：** 分加工库存、客户备料、公司料，批次内查看流水并办理允许的操作。
- **更多：** 客户、基础资料、财务、审批、标签记录、附件检索、登记导入、管理与个人设置。

这是展示层的归并，不减少既有功能。桌面导航与现有 API 不因本稿改变。岗位首页的内容排序可以变化，常驻导航的概念保持一致。

## 17 个页面的逐项建议

| 当前页面 | 当前手机负担 | 拟议归属与展示 | 保留的业务能力 |
|---|---|---|---|
| 首页 | 快捷业务、统计、轻任务和业务池同页，内容较长 | 改为待办首页；保留少量概览与本岗常用操作，业务列表进入订单 | 轻任务指派、完成、作废与业务作业分别处理 |
| 来料 | 收货面板、母单池、详情、证据同页 | 列表归订单；收货用两段表单；保存成功后直达打印、拆单 | 客户、来源、多明细、要求模板、原料行与证据关联 |
| 客户档案 | 客户、材质、要求模板共用分区；详情较多 | 客户列表 → 客户详情 → 资料／在制／账单；材质与模板归基础资料 | 稳定客户 ID、别称、客户授权、模板版本 |
| 标签 | 多种生成入口与打印、队列、模板配置堆叠 | 单内预览打印为主；更多保留跨单记录；工位队列归系统管理 | 原标签版本、任务快照、工位、份数、核纸、补打与改派 |
| 生产 | 报工面板、工单池、交接和设备产量同页 | 作业池归订单；单内工序作业用“更新进度／正式交工”切换 | 要求核对、交工、称重、损耗与设备产量来源 |
| 进度 | 查询、扫码、百分比、改单与时间线同一面板 | 列表进度归订单；更新进度在工序作业；改单独立展开 | 现有百分比档位、回退原因、轮次、改单财务确认与生效 |
| 质检 | 质检面板、待检池、损耗申请与证据同页 | 待检筛选归订单；单内逐条判定；不合格后才展开异常处理 | 冻结、返工、复检、放行、过程说明与损耗申请 |
| 库存 | 三类库存、总流水与发货操作混排 | 保留三类库存，批次详情带流水；发货从可发库存办理 | 库存归属、完整维度、单位、退货、售后复核及冲正 |
| 财务 | 八个分区、全局筛选和较多录入项 | 默认客户账单；账单内登记收款；工资成本、应付、经营按组进入 | 分摊、单价快照、工资试算／确认、耗材、资产、折旧与付款 |
| 审批 | 常驻底栏与首页事项分离，专门控制台偏重 | 首页待办可直达；更多保留审批列表；详情聚焦原因、差异与决策 | 会话身份、场景授权、自批分离、范围及一次决策 |
| 登记导入 | 模板说明、规则、映射和批次复核较长 | 更多 → 业务工具；上传预检 → 复核 → 显式入账，详情按需展开 | 模板、映射、警告与阻断、重放及入账记录 |
| 附件 | 独立上传台、文档包、缺口与管理信息混排 | 单内附件为日常入口；更多保留跨单检索和管理 | 原单归属、正式操作关联、待关联恢复、签名预览与原件下载 |
| 设备 | 设备池、POC／拓扑及网关读数信息较多 | 更多 → 打印与设备；设备列表 → 状态／读数／配置 | 已启用的读数接入、设备兼容与管理能力 |
| 用户管理 | 手机账号编辑的角色、范围、客户与工序较长 | 更多 → 用户与权限；列表和编辑分开，高级授权按需展开 | 账号、角色、顶岗、班组／部门、客户与工序授权 |
| 配置 | 个人会话和存储内容管理职责混合 | 个人安全与系统存储分开进入 | 改密、退出、会话、存储读取和管理 |
| 运维 | 单据维护、运行、备份、存储与告警共页 | 更多 → 存储与运维，按事项列表进入 | 备份、升级计划、运行告警、单据回收与恢复 |
| 手机作业 | 与首页和各业务页重复，单据内再次展开定位组件 | 融入扫码、统一详情及单内动作；保留无贴纸直接收货 | 本岗权限、同码选单、规范目标及共用提交服务 |

## 原型中可体验的内容

- 待办、订单、统一详情、收货、工序作业、逐条质检、发货、库存、客户、财务、审批、更多，共 12 个主要视图。
- 管理员、收货员、操作工、质检员、库管员、财务 6 种预览身份。身份切换仅说明“按岗位收敛”的方向，**不是对当前十种角色和顶岗组合的完整权限建模**。
- 订单搜索与状态筛选、扫码样例、同运单多单选择、详情三个页签、附件分场景筛选、收货两段填写、标签预览与打印回执。
- 进度五档选择、正式交工核对、质检缺陷与后续独立放行／返工入口、手选发货库存和发货二次确认。
- 库存分类与批次流水、客户详情与账单、收款登记、审批意见，以及低频管理的示意面板。

原型中所有客户、金额、单据、文件与统计都是虚构样例。媒体、摄像头、Excel 上传、打印机、权限服务及管理接口没有接入。它用于确认布局与流程，不作为业务验收或完整功能实现。

## 合并显示时必须保留的边界

1. 订单列表、扫码结果与详情只聚合当前账号有权查看的对象；不能在前端合并后泄露客户、金额或附件。
2. 同码多母单、多子单、多库存必须人工选择。母单、子单、执行轮次、标签版本保持清楚；不可把运单作为证据归属单号。
3. 进度仍使用现有 0%、30%、60%、90%、100% 档位；100% 不自动交工、写库存或创建质检。
4. 质检过程说明、正式判定、冻结、返工、复检、放行仍是各自的业务操作；不能用一个完成按钮代替。
5. 客户备料、客户加工料、公司料及不同单位不混合统计。公司料领用只按现行规则转入在制，不自动成本核销。
6. 收货草稿文件、正式操作证据、历史文件各自保留状态和原归属；离开页面不能丢掉待关联文件。
7. 打印任务提交不等于实际出纸；核纸、补打、改派与原快照、请求回放机制保留。
8. 工资试算、正式工资、账单收款分摊、改单金额确认、改单生效和审批授权不因位置靠近而合成一次隐式提交。

## 建议实施顺序（确认后开展）

1. **先改手机信息结构：** 导航、待办首页、订单列表与统一详情；保留原服务和权限契约。
2. **再收拢现场表单：** 收货两段填写，工序进度／正式交工，逐条质检与发货，处理好返回、草稿及错误恢复。
3. **再归拢关联资料：** 单内标签与附件、客户内账单、库存批次流水，逐项验证原业务入口可达。
4. **最后整理低频管理：** 财务其他分区、导入、设备、权限、存储与运维，按实际岗位验证手机可用性。

统一详情的跨单时间线、聚合待办数量、合并列表筛选等是拟议展示，其中部分需要补查询接口或对齐 DTO；不能当作纯样式修改直接上线。正式落地前应列清接口与权限影响，对库存、金额、质检、幂等和事务只执行受影响链路的必要验证。

## 用户需要确认的方向

- 是否接受“待办／订单／扫码／库存／更多”的手机主结构，以及把“现场作业”和“进度”融入订单流程。
- 是否接受标签、附件、改单、拆单从单据详情办理，保留全局检索与管理入口。
- 是否接受当前较紧凑的卡片、两段收货表单和底部主操作，以及浅色绿灰的视觉方向。

确认后才修改正式页面。未确认前不部署、不接入真实提交，不把本提案记为功能已完成。
