## 当前技术

| 层面 | 当前实现 |
|---|---|
| 后端 | Java 17、Spring Boot 3、模块化单体 |
| 前端 | Vue 3、TypeScript、Vite，电脑工作台与手机岗位页 |
| 数据 | MySQL、内存/JDBC 可切仓储；测试使用 H2 等替身 |
| Excel | Apache POI；预检、确认、补录后显式入账 |
| 扫码与标签 | BarcodeDetector 优先、内置 ZXing 兜底；本地二维码、浏览器黑白打印 |
| 认证 | PBKDF2、Bearer 会话、角色菜单、客户授权和工序绑定 |
| 证据 | 本地对象存储、校验和、短期签名；手机采集为现场主路径 |
| 交付 | MySQL + 后端 + Nginx 前端的 Docker Compose 离线包 |

RuoYi、ERPNext、Odoo 为历史选型或模型参考，未成为当前运行基座。独立 Worker、Redis、厂商 NVR/FFmpeg、NAS/S3/COS 附件存储、外部身份系统和流程引擎须按需求验证，不因早期方案出现名称就视为已交付。

## 模块边界

| 模块 | 职责 |
|---|---|
| business | 母单、子工单、工序、质检、出库退货命令、在制进度 |
| inventory | 台账、余额和状态转移；其他领域通过库存服务写账 |
| finance | 客户协议、加工费、收付、工资、耗材、折旧、外协、应付与经营查询 |
| security / approval | 认证、角色菜单、客户及岗位范围、账号生命周期、轻量审批与审计 |
| document / media | 证据包、采集上传、预览和下线；视频截取任务为备选 |
| register / machine | 导入预检与入账、机器档案、产量及绑定；产量不自动等于库存报工 |
| label / scan | 标签、模板、补打、扫码；标签印固定信息，进度扫码查 |
| gateway / hardware | 真实设备和读数；POC、兼容池与实施说明区分来源 |
| operations | 服务、设备、存储、备份恢复的只读状态 |
| configuration / sample | 评审基线与样例说明，不代表真实配置编辑或生产事实 |

客户订单、完整基础档案、盘点审核和多组织等仍按 PRD 管理，不能因当前无独立模块而取消。

## 数据流与一致性

1. 收货确认保存母单，调用库存服务形成客户所有待加工库存；运单用于识别已有母单。
2. 人工选择不拆或拆子单，校验剩余数量重量，继承要求与期限，按所选工序交付。
3. 报工校验账号工序和前道状态；中间工序留在在制，末道完成转半成品。
4. 质检取登录人员逐条判定；不合格走冻结、返工、复检，库存仍由统一服务处理。
5. 出库、退货、售后和损耗审批通过业务命令写台账，页面不能直接改余额。
6. 手机证据按单号入包，不创建 NVR 截取任务；查询不得隐式生成账单、工资或折旧。

返工沿用特殊工单与原单关联，不另造库存状态机。单价、损耗率和质检配置保留历史快照；更正、作废、异常记录前后值与审计。

查询应基于单据和台账。目前工作台评审 seed/快照与正式单据仍并存，部分查询合并两者；接口返回不等于全部为正式交易事实。本次文档整理不改变该逻辑。

## 运行配置与持久化

| 方式 | 当前行为 |
|---|---|
| 本地默认 | 内存仓储，重启不保证保留业务数据 |
| mysql profile | 库存、正式单据、财务、导入、机器、标签模板、网关、菜单、授权、账号审计等用 JDBC；工作台、审批、附件元数据仍受各自开关控制，默认可能为 memory |
| Docker 包 | Compose 在 mysql profile 上显式将工作台、审批、附件等切到 JDBC；以运行包 .env 和 Compose 为准 |

连接使用 ZHUBAO_DB_URL、ZHUBAO_DB_USERNAME、ZHUBAO_DB_PASSWORD。开关与默认值以 backend/src/main/resources/application.yml、application-mysql.yml 为准。ZHUBAO_BUSINESS_SNAPSHOT_CODE 选择评审快照，不是正式账期。

zhubao.documents.repository 控制附件元数据仓储，zhubao.documents.storage.* 控制文件内容存储；数据库备份不包含附件。HTTPS、上传限制、备份恢复和升级见 [部署手册](./19_Docker一键部署与离线交付.md)。

本地请求头兜底用于评审测试，MySQL 默认关闭。MySQL 默认强制账号前置审批，页面须形成申请、批准、执行闭环，不能以关闭开关掩盖流程缺口。

## 安全与查询

- 敏感写入、审批、补打、附件替换和下线校验操作权限并记录审计。
- 菜单隐藏不能替代服务端授权；客户、本人和岗位范围须服务端执行。
- 财务客户读取与公司工资、折旧、耗材、应付读取分别授权；聚合与明细共用范围。
- 预览校验签名与时效，不暴露存储路径；当前会话和摘要链不等于完整 IAM、分布式会话或不可篡改保全。
